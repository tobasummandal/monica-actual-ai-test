# Standardize Logging with Laravel Log Facade in DAV and Job Components: Components Use Dedicated

## Status
Accepted

## Context
DAV (Distributed Authoring and Versioning) and Job components require consistent, traceable logging across the application. Different operational contexts (DAV file operations, background jobs, API requests) benefit from separate log streams to enable targeted monitoring, debugging, and retention policies.

## Decision
Components within DAV and Job subsystems MUST use the Laravel Log Facade for all logging operations. Components MAY use dedicated log channels for DAV operations to enable separate log routing and retention policies.

## Rationale
- **Consistency**: Centralizing on Laravel's Log Facade ensures uniform logging patterns across all components
- **Flexibility**: Dedicated channels allow DAV operations to be routed separately (e.g., to different files, external services, or retention schedules)
- **Observability**: Separate channels improve debugging and monitoring by isolating operational concerns
- **Maintainability**: Using framework-native logging reduces custom implementations and technical debt

## Consequences

### Positive
- Unified logging interface across DAV and Job components
- Ability to configure channel-specific handlers, formatters, and retention policies
- Improved log filtering and analysis for DAV-specific operations
- Easier integration with centralized logging systems

### Negative
- Additional configuration overhead for dedicated channels
- Potential log duplication if not carefully configured
- Team must maintain consistency in channel naming conventions

## Implementation Guidelines

1. Use `Log::channel('dav')` for DAV-specific operations
2. Use `Log::channel('jobs')` for background job logging
3. Define channels in `config/logging.php` with appropriate handlers
4. Document channel purposes and retention policies
5. Use contextual logging with tags and context arrays for better traceability
