# Standardize Unit and Feature Test Organization in CI/CD Pipeline: Pipelines Execute Both

## Status
Accepted

## Context
Test execution in CI/CD pipelines has been inconsistent, with some pipelines running only unit tests or only feature tests. This fragmentation leads to incomplete validation of code changes and delayed detection of integration issues.

## Decision
We standardize CI/CD pipelines to execute both unit and feature test suites on every commit, ensuring comprehensive validation before code reaches production.

## Policies

1. CI/CD pipelines MUST execute both unit and feature test suites on every commit

## Consequences

**Positive:**
- Comprehensive test coverage on every commit
- Early detection of integration issues
- Consistent quality gates across all repositories
- Reduced defects reaching production

**Negative:**
- Increased pipeline execution time
- Higher infrastructure resource consumption
- Potential for flaky feature tests to block deployments

## Implementation Notes
- Configure pipeline stages to run unit tests first (faster feedback)
- Run feature tests in parallel when possible
- Establish timeout thresholds and retry policies for flaky tests
- Monitor pipeline duration and optimize test suites as needed
