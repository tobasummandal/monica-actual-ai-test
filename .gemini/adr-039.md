# Adopt Laravel Fortify for Authentication Action Standardization: Domain Specific User

## Status
Proposed

## Context
Our application requires standardized authentication action handling across multiple domains. Laravel Fortify provides a robust foundation for authentication flows, but we need to ensure domain-specific user management operations maintain clear boundaries and responsibility separation.

## Decision
We adopt Laravel Fortify as the authentication framework while implementing domain-specific user management services as dedicated service classes within their respective domain boundaries.

## Rationale
- Laravel Fortify provides battle-tested authentication pipelines and action standardization
- Domain-specific services maintain separation of concerns and business logic isolation
- Dedicated service classes enable testability and reusability across authentication flows
- Clear domain boundaries prevent cross-cutting concerns in user management

## Policies

1. Domain-specific user management services (CreateAccount, AcceptInvitation, CancelAccount) MUST be implemented as dedicated service classes within their respective domain boundaries

## Consequences

### Positive
- Standardized authentication action handling via Fortify
- Clear ownership of user management operations within domains
- Improved testability of domain-specific logic
- Reduced coupling between authentication framework and business domains

### Negative
- Additional service layer abstraction to maintain
- Potential duplication if not carefully designed
- Team must understand both Fortify patterns and domain service patterns

## Implementation Notes
- Service classes should implement consistent interfaces
- Fortify actions should delegate to domain services rather than containing business logic
- Document the mapping between Fortify actions and domain services
