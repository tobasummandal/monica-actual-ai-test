# Adopt PHPUnit for Unit Testing in Domain-Driven Architecture: Unit Tests Focus

## Status
Accepted

## Context
In a Domain-Driven Design (DDD) architecture, unit tests serve as a critical validation layer for domain logic, value objects, and aggregates. PHPUnit is the de facto standard testing framework for PHP applications and provides robust tooling for isolated component testing.

## Decision
We adopt PHPUnit as the primary framework for unit testing in our domain-driven architecture, with a strict focus on testing individual components in isolation.

## Policies

1. Unit tests MUST focus on testing individual components in isolation without external dependencies

## Rationale
- PHPUnit provides comprehensive assertion methods and mocking capabilities essential for DDD testing patterns
- Isolation ensures tests remain fast, deterministic, and focused on domain logic validation
- Mocking external dependencies (repositories, services, APIs) prevents test brittleness and coupling
- Unit tests serve as executable specifications of domain behavior

## Consequences
- Improved code quality through rigorous domain logic validation
- Faster test execution cycles enabling rapid feedback
- Reduced maintenance burden by decoupling tests from infrastructure changes
- Requires discipline in dependency injection and test doubles (mocks/stubs) usage
- Integration testing must be handled separately with appropriate tools

## Implementation Guidelines
- Use PHPUnit's built-in mocking via `PHPUnit\Framework\MockObject\MockObject`
- Leverage value object and aggregate testing patterns from DDD
- Maintain test-to-code ratio of 1:1 minimum for domain classes
- Organize tests mirroring domain structure (tests/Domain/...)
