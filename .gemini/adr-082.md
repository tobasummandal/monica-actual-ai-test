# Adopt Domain-Driven DAV/CardDAV Integration Pattern for External Contact Synchronization: Import Export Operations

## Status
Proposed

## Context
External contact synchronization requires robust handling of import and export operations across DAV/CardDAV protocols. Current implementations risk violating single responsibility principle by combining multiple concerns within monolithic resource handlers, leading to maintenance complexity and reduced testability.

## Decision
Adopt a domain-driven design pattern that separates import and export operations into distinct, focused resource classes. This approach aligns with established architectural principles and enables independent evolution of synchronization concerns.

## Policies

1. Import and export operations SHOULD be separated into distinct resource classes (ImportResource, ImportVCardResource) following single responsibility principle

## Rationale
- **Separation of Concerns**: Distinct classes isolate import logic from export logic, reducing cognitive load and maintenance burden
- **Testability**: Focused resource classes enable targeted unit testing without cross-cutting concerns
- **Extensibility**: Independent resource classes allow protocol-specific implementations (vCard, iCalendar) without affecting sibling operations
- **Domain Alignment**: Reflects domain language where import and export represent fundamentally different operations

## Consequences

### Positive
- Improved code clarity and maintainability
- Reduced coupling between import/export concerns
- Easier to implement protocol-specific variations
- Simplified testing and debugging workflows

### Negative
- Increased number of resource classes to manage
- Potential code duplication in shared validation logic
- Requires clear naming conventions to avoid confusion

## Implementation Notes
- ImportResource handles inbound contact data transformation
- ImportVCardResource specializes in vCard format parsing
- Shared validation logic should be extracted to utility services
- Both classes should implement common interface for consistency
