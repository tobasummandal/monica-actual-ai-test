# Adopt Laravel Fortify for Authentication Action Standardization: Authentication Actions Password

## Status
Accepted

## Context
Authentication workflows in Laravel applications often scatter password-related logic across multiple locations: controllers, requests, services, and events. This fragmentation makes it difficult to maintain consistent behavior, audit security changes, and test authentication flows comprehensively.

Laravel Fortify provides a standardized action-based architecture for authentication concerns, including password reset, password update, and user creation. Adopting Fortify actions centralizes this logic and provides a clear, testable interface.

## Decision
We adopt Laravel Fortify for authentication action standardization. All authentication actions—specifically password reset, password update, and user creation—will be implemented as Laravel Fortify action classes.

## Policies

1. All authentication actions (password reset, password update, user creation) MUST be implemented as Laravel Fortify action classes in the app/Actions/Fortify namespace

## Consequences

### Positive
- **Centralized Logic**: All password and authentication actions live in a single, predictable location
- **Consistency**: Fortify enforces a standard interface for all authentication actions
- **Testability**: Action classes are easy to unit test in isolation
- **Auditability**: Changes to authentication logic are tracked in a single namespace
- **Reusability**: Actions can be invoked from controllers, commands, or other services
- **Security**: Fortify includes built-in rate limiting and security best practices

### Negative
- **Learning Curve**: Team members must understand Fortify's action pattern
- **Dependency**: Introduces a framework dependency; migration away requires refactoring
- **Overhead**: Simple password updates may feel over-engineered with the action pattern

## Implementation Notes
- Action classes inherit from `Illuminate\Contracts\Auth\Authenticatable` or implement custom interfaces
- Each action is a single, invokable class with a `__invoke()` method
- Actions are registered in `config/fortify.php` or bound in a service provider
- Use Fortify's built-in events (`PasswordReset`, `PasswordUpdated`) for side effects
- Validation logic should be defined in the action or delegated to form request classes
