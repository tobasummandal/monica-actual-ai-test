# Adopt Domain-Driven Resource Modeling for Data Access Layer: Data Models Follow

## Status
Accepted

## Context
The data access layer requires a clear, maintainable structure that aligns data models with their domain responsibilities. Without consistent naming and organization conventions, models become difficult to locate, understand, and extend as the system grows.

## Decision
Adopt domain-driven resource modeling where data models follow a naming convention that explicitly reflects their domain purpose and responsibility.

## Policies

1. Data models MUST follow a consistent naming convention that reflects their domain purpose (e.g., File.php for file entities, VCardResource.php for vCard protocol resources)

## Consequences

**Positive:**
- Models are self-documenting through their names
- Domain boundaries become explicit and discoverable
- Reduces cognitive load when navigating the codebase
- Facilitates onboarding of new team members
- Enables predictable file organization

**Negative:**
- Requires discipline to maintain naming consistency
- May result in longer class names in some cases
- Refactoring domain responsibilities requires renaming
