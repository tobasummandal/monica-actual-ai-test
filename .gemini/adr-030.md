# Adopt Mock-Based Unit Testing for External Service Dependencies in CI/CD Pipeline: Test Doubles Created

## Status
Accepted

## Context
External service dependencies (APIs, databases, payment gateways, etc.) introduce non-determinism, latency, and brittleness into unit tests. Direct calls to external services during CI/CD pipeline execution cause flaky tests, slow feedback loops, and environmental coupling. Test doubles enable isolated, fast, and reliable unit testing.

## Decision
We adopt mock-based unit testing using test doubles for all external service dependencies in our CI/CD pipeline. Test doubles are created using the testing framework's built-in mocking capabilities for consistency and maintainability.

## Policies

1. Test doubles SHOULD be created using the testing framework's built-in mocking capabilities (e.g., PHPUnit mocks, Mockery) for consistency

## Rationale
- **Isolation**: Mocks decouple unit tests from external systems, enabling true unit testing
- **Speed**: Mock responses are instantaneous, reducing test execution time
- **Reliability**: Eliminates flakiness caused by external service unavailability or latency
- **Consistency**: Using framework-native mocking ensures uniform patterns across the codebase
- **CI/CD Efficiency**: Faster feedback loops accelerate development cycles

## Consequences
- Developers must maintain mock definitions alongside production code
- Mock behavior must be kept synchronized with actual service contracts
- Integration tests remain necessary to validate real service interactions
- Initial setup requires learning framework-specific mocking patterns
