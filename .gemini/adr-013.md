# Standardize Unit and Feature Test Organization in CI/CD Pipeline: Unit Tests Placed

## Status
Accepted

## Context
Unit and feature tests need consistent organization within the CI/CD pipeline to improve maintainability, clarity, and execution efficiency. Without standardized placement, tests become scattered, making it difficult to locate, maintain, and execute specific test suites.

## Decision
Unit tests MUST be placed in the `tests/Unit` directory and organized by domain boundaries. Feature tests MUST be placed in the `tests/Feature` directory with corresponding feature organization.

## Policies

1. All unit tests MUST be placed in the tests/Unit directory and organized by domain boundaries

## Rationale
- **Clarity**: Clear separation between unit and feature tests improves discoverability
- **Maintainability**: Domain-based organization aligns with business logic structure
- **CI/CD Efficiency**: Standardized paths enable targeted test execution and parallel runs
- **Scalability**: Consistent structure supports team growth and onboarding

## Consequences
- Developers must follow the directory structure convention
- CI/CD pipelines can reliably locate and execute test suites
- Test execution can be optimized by domain or test type
- Migration of existing tests may be required

## Implementation
- Directory structure: `tests/Unit/{DomainName}/{TestFile}.php`
- Directory structure: `tests/Feature/{FeatureName}/{TestFile}.php`
- Update CI/CD configuration to reference standardized paths
- Document structure in project README and contribution guidelines
