# Adopt Inertia.js with SSR for Frontend-Backend Integration: Javascript Entry Points

## Status
Proposed

## Context
Inertia.js enables seamless frontend-backend integration by allowing server-side rendering (SSR) of Vue/React components while maintaining a unified JavaScript codebase. Entry points (app.js for client-side hydration and ssr.js for server-side rendering) must be organized consistently within Laravel's asset structure to ensure maintainability and follow framework conventions.

## Decision
Adopt Inertia.js with SSR support, organizing JavaScript entry points according to Laravel's standard asset directory structure.

## Policies

1. JavaScript entry points (app.js, ssr.js) MUST be located in resources/js/ directory following Laravel's standard asset organization

## Consequences

### Positive
- Aligns with Laravel conventions, reducing cognitive load for Laravel developers
- Centralizes frontend assets in a predictable location
- Simplifies build configuration and asset pipeline integration
- Enables consistent SSR and client-side rendering workflows

### Negative
- Requires developers to understand both Inertia.js and Laravel asset organization
- Build tooling must be configured to handle both entry points

## Alternatives Considered
- Placing entry points in a separate frontend/ directory (rejected: breaks Laravel conventions)
- Mixing entry points across multiple directories (rejected: reduces maintainability)
