# Adopt Eloquent ORM Models as Standard Data Access Layer: Each Model Correspond

## Status
Accepted

## Context
Our application requires a consistent and standardized approach to data access across all layers. We need to establish clear conventions for mapping domain entities to database tables and ensure maintainability as the codebase grows.

## Decision
We adopt Eloquent ORM Models as the standard data access layer for our Laravel application. Each Model will correspond to a single database table, establishing a one-to-one mapping between domain entities and their persistent storage.

## Policies

1. Each model MUST correspond to a single database table with the table name following Laravel's naming conventions (plural, snake_case)

## Consequences

### Positive
- Clear, predictable mapping between models and database tables
- Reduced cognitive load when navigating the codebase
- Easier onboarding for new team members
- Simplified database schema documentation
- Consistent use of Eloquent conventions across the project

### Negative
- May require refactoring of existing models that violate this convention
- Limits flexibility for complex domain models that might span multiple tables
- Requires discipline to maintain as the application evolves

## Implementation Notes
- Model names should be singular and PascalCase (e.g., `User`, `BlogPost`)
- Corresponding table names should be plural and snake_case (e.g., `users`, `blog_posts`)
- Use explicit table name declaration only when deviating from conventions is unavoidable
- Document any exceptions to this rule in the model's class docblock
