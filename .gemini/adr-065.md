# Adopt Laravel Fortify for Authentication with Centralized Input Validation: Authentication Logic Not

## Status
Accepted

## Context
Our application requires a robust, maintainable authentication system that prevents logic duplication and ensures consistent input validation across all authentication flows. Multiple authentication entry points (web, API, admin panels) create risk of divergent implementations and security gaps.

## Decision
Adopt Laravel Fortify as the centralized authentication framework, enforcing all authentication logic through Fortify Actions and a single validation layer.

## Rationale
- **Single Source of Truth**: Fortify Actions serve as the exclusive authentication logic implementation point
- **Consistency**: Centralized validation prevents logic drift across different authentication flows
- **Maintainability**: Changes to authentication behavior require updates in one location only
- **Security**: Reduces attack surface by eliminating duplicate or alternative authentication paths
- **Framework Integration**: Fortify is Laravel's official authentication scaffolding solution

## Policies

1. Authentication logic MUST NOT be duplicated outside of Fortify Actions

## Consequences

### Positive
- Guaranteed consistency across all authentication flows
- Simplified security audits and compliance reviews
- Reduced maintenance burden for authentication features
- Clear architectural boundaries for auth concerns

### Negative
- Learning curve for team unfamiliar with Fortify
- Potential performance overhead if not optimized
- Constraints on custom authentication flows outside Fortify's design

## Implementation Notes
- All login, registration, password reset, and 2FA logic must use Fortify Actions
- Custom authentication requirements must extend Fortify, not bypass it
- Input validation must be centralized in Fortify's validation layer
- Regular audits to ensure no authentication logic exists outside Fortify
