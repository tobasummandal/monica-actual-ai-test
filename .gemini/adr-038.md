# Adopt Laravel Fortify for Authentication Action Standardization: Password Validation Hashing

## Status
Accepted

## Context
Authentication workflows across the application require standardized password validation and hashing mechanisms to ensure consistent security posture, reduce vulnerabilities from custom implementations, and maintain compliance with industry best practices across all deployment environments.

## Decision
Adopt Laravel Fortify as the standardized framework for authentication action handling, specifically leveraging its built-in password validation and hashing capabilities through Laravel's Hash facade and validation rules.

## Consequences

### Positive
- Centralized password security handling eliminates custom implementations
- Hash facade provides algorithm flexibility (bcrypt, argon2, etc.) without code changes
- Validation rules enforce consistent password requirements across all endpoints
- Framework updates automatically improve security posture
- Reduced attack surface from standardized, battle-tested implementations

### Negative
- Dependency on Laravel Fortify package adds framework coupling
- Team must maintain familiarity with Fortify conventions
- Custom authentication flows may require adaptation

## Policies

1. Password validation and hashing operations MUST use Laravel's Hash facade and validation rules to ensure consistent security standards across all deployment targets

## Implementation Notes
- Use `Hash::make()` for password hashing in all user creation/update flows
- Apply `password` validation rule for new password inputs
- Configure hashing algorithm in `config/hashing.php`
- Audit existing custom password handling for migration to Fortify
