# Adopt Mock-Based Unit Testing for External Service Dependencies in CI/CD Pipeline: Teams Use Contract

## Status
Proposed

## Context
External service dependencies introduce flakiness, latency, and cost into CI/CD pipelines. Unit tests that call real services are slow, unreliable, and difficult to reproduce. Mock-based testing allows teams to validate application logic in isolation while maintaining confidence in integration points.

## Decision
We adopt mock-based unit testing as the standard approach for external service dependencies in our CI/CD pipeline. Teams will use contract testing or recorded fixtures to validate mock behavior against real service responses, ensuring mocks remain synchronized with actual service contracts.

## Rationale
- **Pipeline Speed**: Mocks eliminate network latency and service availability as test blockers
- **Reliability**: Tests become deterministic and reproducible across environments
- **Cost**: Reduces API calls, database operations, and third-party service charges during testing
- **Contract Validation**: Contract testing and fixtures ensure mocks accurately represent real service behavior
- **Parallel Execution**: Mock-based tests can run safely in parallel without resource contention

## Policies

1. Teams MAY use contract testing or recorded fixtures to validate mock behavior against real service responses

## Consequences
- Mock maintenance overhead when external service contracts change
- Requires discipline to keep mocks synchronized with real services
- Contract tests or fixture updates needed when integrations evolve
- Improved CI/CD pipeline performance and reliability
- Better developer experience with faster feedback loops
