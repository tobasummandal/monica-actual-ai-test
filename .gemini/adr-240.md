# Adopt Domain-Driven Test Organization with Mirrored Directory Structure: Web Concerns Separated

## Status
Proposed

## Context
Test organization significantly impacts maintainability, discoverability, and the ability to apply domain-specific testing strategies. As applications grow, mixing API concerns (controllers, endpoints, request/response handling) with web concerns (view helpers, UI utilities, client-side logic) creates friction when applying specialized testing approaches.

## Decision
Adopt a domain-driven test organization that mirrors the production directory structure, with explicit separation between API and Web concerns. This enables independent testing strategies tailored to each domain's unique requirements.

## Policies

1. API and Web concerns SHOULD be separated into distinct test directories (Api/Controllers vs Web/ViewHelpers) to enable independent testing strategies

## Rationale
- **Domain Alignment**: Test structure reflects business domains, improving cognitive load and navigation
- **Strategy Independence**: API tests can emphasize contract validation and integration; Web tests can focus on rendering and interaction
- **Scalability**: Clear boundaries prevent test directories from becoming monolithic as the codebase grows
- **Tooling Flexibility**: Separate concerns allow different test runners, fixtures, and utilities optimized per domain

## Consequences
- **Positive**: Faster test discovery, clearer ownership, easier to apply domain-specific best practices
- **Positive**: Reduced coupling between test suites enables parallel execution and independent CI/CD pipelines
- **Negative**: Requires discipline to maintain mirroring between production and test structures
- **Negative**: Initial refactoring effort if migrating from flat or mixed test layouts

## Implementation Notes
- Establish clear naming conventions (e.g., `tests/Api/Controllers/`, `tests/Web/ViewHelpers/`)
- Document which testing tools and patterns apply to each domain
- Use linting or CI checks to enforce structure consistency
