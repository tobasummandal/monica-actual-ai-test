# Adopt Domain-Driven DAV/CardDAV Integration Pattern for External Contact Synchronization: Non Compliant Dav

## Status
Accepted

## Context
External contact synchronization via DAV/CardDAV protocols requires robust handling of server implementations that do not fully comply with RFC standards. Non-compliant DAV servers present integration challenges that demand explicit, domain-driven exception handling to maintain system reliability and provide clear diagnostic information.

## Decision
Adopt a domain-driven DAV/CardDAV integration pattern that explicitly handles non-compliant DAV server behaviors through dedicated exception types and clear error messaging.

## Policies

1. Non-compliant DAV server behaviors MUST be handled through explicit exception types (e.g., DavServerNotCompliantException) with clear error messaging

## Rationale
- Explicit exception types enable precise error handling and recovery strategies
- Clear error messaging improves debugging and operational visibility
- Domain-driven approach aligns with business logic for contact synchronization
- Centralized non-compliance handling prevents scattered workarounds throughout the codebase

## Consequences

### Positive
- Improved system resilience when integrating with non-standard DAV implementations
- Enhanced observability through structured exception handling
- Clearer separation of concerns between DAV protocol handling and business logic
- Easier maintenance and future protocol version support

### Negative
- Additional exception types increase codebase complexity
- Requires comprehensive testing against various non-compliant server implementations
- May require periodic updates as new non-compliant behaviors are discovered

## Implementation Notes
- Define DavServerNotCompliantException with detailed context about the specific non-compliance
- Implement validation layer to detect non-compliant behaviors early
- Document known non-compliant server types and their workarounds
- Provide clear logging and monitoring for non-compliance incidents
