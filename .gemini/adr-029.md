# Adopt Mock-Based Unit Testing for External Service Dependencies in CI/CD Pipeline: Mock Expectations Verify

## Status
Proposed

## Context
Unit tests in the CI/CD pipeline frequently interact with external service dependencies such as APIs, databases, and message queues. Testing against real external services introduces flakiness, latency, and cost. Mock-based testing provides a controlled alternative, but requires discipline in verifying that mocks are used correctly.

## Decision
We adopt mock-based unit testing for external service dependencies in our CI/CD pipeline. Mock objects MUST be configured with explicit expectations that verify both the parameters passed to external service methods and the order in which those methods are invoked.

## Policies

1. Mock expectations SHOULD verify that external service methods are called with correct parameters and in the expected order

## Rationale
- Verifying mock expectations ensures tests catch integration bugs early, even when using mocks
- Parameter verification prevents silent failures where code calls the right method with wrong arguments
- Order verification catches logic errors in call sequencing
- Explicit expectations make test intent clear and maintainable

## Consequences
- Tests become more robust and catch real integration issues
- Test setup requires more careful specification of mock behavior
- Mock expectations must be updated when external service contracts change
- Developers must understand mock frameworks and expectation syntax

## Implementation
- Use mock frameworks (e.g., Mockito, Jest mocks, unittest.mock) that support expectation verification
- Document expected call sequences in test comments
- Review mock expectations during code review
- Fail tests when mock expectations are not met
