# Adopt Laravel Fortify for Authentication with Centralized Input Validation: Custom Fortify Actions

## Status
Proposed

## Context
Laravel Fortify provides a headless authentication backend with built-in actions for common authentication flows. To maintain consistency with Fortify's architecture and enable centralized input validation across authentication operations, we need to establish patterns for creating custom Fortify actions.

## Decision
We adopt Laravel Fortify for authentication and implement custom Fortify actions that extend or implement Fortify's action contracts. This approach ensures our authentication logic remains compatible with Fortify's ecosystem while allowing customization for application-specific requirements.

## Policies

1. Custom Fortify Actions SHOULD extend or implement Fortify's action contracts to maintain consistency with the framework

## Consequences

### Positive
- Custom actions remain compatible with Fortify's built-in features and middleware
- Centralized validation logic can be applied consistently across authentication flows
- Clear contracts make authentication logic predictable and testable
- Framework updates are less likely to break custom implementations

### Negative
- Developers must understand Fortify's action contracts and patterns
- Custom actions are tightly coupled to Fortify's architecture
- Changes to Fortify's contracts may require updates to custom implementations

## Implementation Notes
- Custom actions should be registered in `config/fortify.php`
- Input validation should be centralized in form request classes or dedicated validators
- Actions should remain focused on a single responsibility
- Test coverage should verify action behavior and validation integration
