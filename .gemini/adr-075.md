# Adopt CardDAV/WebDAV Protocol for External Contact Synchronization: Non Compliant Dav

## Status
Accepted

## Context
External contact synchronization requires integration with various CardDAV and WebDAV servers. Many servers in production environments do not fully comply with RFC standards, leading to integration failures and poor user experience.

## Decision
We adopt CardDAV/WebDAV protocol for external contact synchronization with explicit handling for non-compliant DAV servers through dedicated exception handling and diagnostic mechanisms.

## Policies

1. Non-compliant DAV servers MUST be handled with specific exceptions (DavServerNotCompliantException) to provide clear error diagnostics

## Rationale
- Provides clear separation between protocol compliance issues and genuine errors
- Enables targeted debugging and server-specific workarounds
- Improves user experience through informative error messages
- Allows graceful degradation when servers don't meet standards

## Consequences

### Positive
- Clear diagnostic information for troubleshooting non-compliant servers
- Ability to implement server-specific compatibility layers
- Better error reporting and logging

### Negative
- Increased complexity in error handling logic
- Need to maintain compatibility mappings for known non-compliant servers
- Potential performance overhead from compliance checking

## Implementation Notes
- DavServerNotCompliantException should include server identification and specific compliance violations
- Maintain a registry of known non-compliant servers and their workarounds
- Log all non-compliance issues for monitoring and analysis
