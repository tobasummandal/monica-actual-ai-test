# Adopt Mock-Based Unit Testing for External Service Dependencies in CI/CD Pipeline: Integration Tests That

## Status
Proposed

## Context
External service dependencies (APIs, databases, message queues) introduce flakiness, latency, and cost into unit test suites. Tests that depend on real external services are difficult to run locally, slow down CI/CD pipelines, and create brittle test environments. Unit tests should be fast, deterministic, and isolated.

## Decision
We adopt mock-based unit testing for all external service dependencies. Integration tests that verify real external service interactions are separated from unit tests and run in dedicated CI/CD stages.

## Rationale
- **Speed**: Mocked unit tests run in milliseconds; real service calls add seconds or minutes
- **Reliability**: Mocks eliminate network flakiness and external service outages
- **Cost**: Reduces API calls, database operations, and infrastructure usage during testing
- **Isolation**: Unit tests remain independent and runnable offline
- **Separation of Concerns**: Integration tests validate end-to-end flows; unit tests validate logic

## Policies

1. Integration tests that verify real external service interactions SHOULD be separated from unit tests and run in dedicated CI/CD stages

## Consequences
- Unit test suites become faster and more reliable
- Developers can run tests locally without external service access
- Integration tests require separate infrastructure and longer execution time
- Mock maintenance is required when external service contracts change
- Teams must establish clear boundaries between unit and integration test scopes
