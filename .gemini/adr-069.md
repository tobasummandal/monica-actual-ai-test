# Adopt Laravel Fortify for Authentication with Centralized Input Validation: Fortify Actions Registered

## Status
Accepted

## Context
Laravel Fortify provides a headless authentication backend that decouples authentication logic from the frontend. To leverage Fortify's full capabilities for centralized input validation and authentication workflows, Fortify Actions must be properly registered and configured within the application's service provider.

## Decision
We will register and configure Fortify Actions in the FortifyServiceProvider to enable centralized input validation and standardized authentication handling across the application.

## Policies

1. Fortify Actions MUST be registered and configured in FortifyServiceProvider

## Consequences

### Positive
- Centralized authentication action registration ensures consistency across the application
- Custom validation logic is encapsulated within dedicated Action classes
- Service provider configuration provides a single source of truth for authentication workflows
- Easier to test and maintain authentication logic
- Supports dependency injection within registered actions

### Negative
- Requires understanding of Fortify's action registration pattern
- Additional boilerplate in FortifyServiceProvider
- Team must follow established conventions for action registration

## Implementation Notes
- Register actions in `boot()` method of FortifyServiceProvider
- Use `Fortify::authenticateUsing()`, `Fortify::createUsersUsing()`, etc. as appropriate
- Ensure all custom actions implement required Fortify contracts
- Document registered actions and their validation rules
