<rule_activation id="1331ceea-2c42-41c2-90d9-0afa4bccf470" title="Adopt Internationalization (i18n) Language Files for Multi-Language Support: Locale Specific Formatting" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. The codebase adopts a systematic internationalization (i18n) strategy using locale-specific language files to support multi-language applications with proper separation of translations from business logic.
</rule_activation>

### Rules

- **R-I18N-001** MAY: Locale-specific formatting rules (dates, numbers, currency) MAY be defined in dedicated format.php files per locale.

### Verify

```bash
# Count language files in lang/ directory
find lang/ -type f -name '*.php' | wc -l | grep -E '[0-9]+'

# Verify no hardcoded user-facing strings outside language files
grep -r "echo\|print" app/ | grep -v "trans(\|__('\|@lang" || echo 'No hardcoded strings found'

# Check translation completeness (Laravel)
php artisan lang:check --missing || composer run check-translations
```

**Accept when:**
- Language directory structure exists with at least one locale containing all required translation categories (auth, validation, passwords, actions, pagination, http-statuses, format)
- No hardcoded user-facing strings are found in application code outside of language files
- Translation loading mechanism is implemented and functional with fallback to default locale for missing keys
- All user-facing text strings in web interfaces, APIs, and command-line tools are externalized to language files
- Error messages, validation feedback, and system notifications are managed through the i18n system
- HTTP status messages and standard framework responses use translation keys
- Authentication and authorization messages are localized
- Pagination controls and navigation elements reference translation files

<enforcement>
Claude Code MUST verify i18n compliance through automated CI pipeline checks for missing translation keys across supported locales. Code review MUST block merges if translation keys are missing from language files. Static analysis tools MUST scan for hardcoded strings in application code. Violations trigger CI pipeline failures and code review blocks. Periodic translation completeness audits MUST compare key counts across locales. Exception requests require technical lead approval with documented remediation timelines.
</enforcement>
