<rule_activation id="f276407f-5e0e-4f16-8764-17e1729b5f10" title="Organize Test Files by Domain and Feature Modules: Test File Names" applies_to="tests/Unit/Domains/**/*Test.php">
These rules are ALWAYS ACTIVE for all test files under tests/Unit/Domains/ that follow domain-driven design organization.
</rule_activation>

### Rules

- **R-TEST-001** MUST: Test file names MUST append 'Test' suffix to the corresponding production class name (e.g., RemoveModuleFromTemplatePage.php → RemoveModuleFromTemplatePageTest.php)
- **R-TEST-002** MUST: Test files MUST be organized under tests/Unit/Domains/ with subdirectories mirroring the production code structure (app/Domains/ or src/Domains/)
- **R-TEST-003** MUST: Test file paths MUST mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- **R-TEST-004** SHOULD: Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) SHOULD be represented as subdirectories within their respective domains
- **R-TEST-005** SHOULD: Test namespace declarations SHOULD follow the pattern Tests\Unit\Domains\{DomainName}\{ModuleName}

### Verify

```bash
# Verify test files exist under tests/Unit/Domains/ with Test suffix
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify namespace conventions are followed
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are represented as subdirectories
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'

# Verify test file naming consistency
find tests/Unit/Domains -type f -name '*.php' ! -name '*Test.php' -print
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- Test namespace declarations follow Tests\Unit\Domains\{DomainName}\{ModuleName} pattern
