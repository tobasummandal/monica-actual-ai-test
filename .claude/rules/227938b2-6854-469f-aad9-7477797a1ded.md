<rule_activation id="227938b2-6854-469f-aad9-7477797a1ded" title="Organize Test Files by Domain and Feature Modules: Test Organization Facilitate" applies_to="tests/Unit/Domains/**/*">
These rules are ALWAYS ACTIVE for all test files under tests/Unit/Domains/ to ensure consistent domain-driven test organization that mirrors production code structure and facilitates parallel test execution.
</rule_activation>

### Rules

- **R-TEST-001** SHOULD: Test organization SHOULD facilitate parallel test execution by allowing independent domain or module test runs.
- **R-TEST-002** MUST: Test files under tests/Unit/Domains/ MUST mirror the production code structure from app/Domains/ or src/Domains/.
- **R-TEST-003** MUST: Test file names MUST append 'Test' suffix to production class names (e.g., UserManager.php → UserManagerTest.php).
- **R-TEST-004** MUST: Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) MUST be represented as subdirectories within their respective domains.
- **R-TEST-005** SHOULD: Test file paths SHOULD replace src/ or app/ prefix with tests/Unit/Domains/ prefix while maintaining identical subdirectory structure.
- **R-TEST-006** SHOULD: Namespace declarations in test files SHOULD follow pattern Tests\Unit\Domains\{DomainName}\{ModuleName}\.
- **R-TEST-007** MAY: Shared test utilities or base test classes MAY serve multiple domains (EXC-001).
- **R-TEST-008** MAY: Legacy test files MAY be exempted during migration period into domain structure (EXC-002).

### Verify

```bash
# Verify test files exist under tests/Unit/Domains/ with correct structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify namespace conventions are followed
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are represented as subdirectories
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- Namespace declarations match the directory structure pattern Tests\Unit\Domains\{DomainName}\{ModuleName}

Claude Code MUST verify test file organization against these rules during code review and generation. Violations MUST be flagged in CI pipeline checks, code review comments, and pre-commit hooks. Exceptions require documented justification with EXC-ID reference and tech lead approval.
</enforcement>
