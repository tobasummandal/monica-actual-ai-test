<rule_activation id="80de625b-007b-4a74-895a-cc5e40a2a73d" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Pipelines Run Unit" applies_to="{tests/**/*.php,.github/workflows/**,.gitlab-ci.yml,phpunit.xml}">
These rules apply to PHP test files in tests/Unit and tests/Feature directories, CI/CD pipeline configuration files, PHPUnit configuration, and test execution scripts.
</rule_activation>

### Rules

- MAY: CI/CD pipelines MAY run unit and feature tests in parallel to optimize build time.

### Verify

```bash
grep -r "class.*Test extends" tests/Unit/ | wc -l
grep -r "class.*Test extends" tests/Feature/ | wc -l
php artisan test --testsuite=unit --stop-on-failure
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both unit and feature test directories exist and contain test files following the *Test.php naming convention
- PHPUnit configuration defines separate test suites for unit and feature tests
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings

<enforcement>
Claude Code MUST NOT skip or defer verification. Violations are detected by automated CI/CD pipeline checks that fail builds if tests are not properly organized or placed in incorrect directories.
</enforcement>
