<rule_activation id="b88f3d24-3a6e-4cda-b188-d1038b7fddf1" title="Adopt Domain-Driven Service Layer Architecture for Business Operations: Controllers Placed Web" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching the domain-driven service layer architecture pattern in web applications.
</rule_activation>

### Rules

- **R-DDD-001** SHOULD: Controllers SHOULD be placed in Web/Controllers subdirectories within their respective domain feature folders
- **R-DDD-002** SHOULD: Business logic for account management operations SHOULD be encapsulated in dedicated service classes within domain boundaries
- **R-DDD-003** SHOULD: Service classes SHOULD be named after the business operation they perform (e.g., CreateAccount, AcceptInvitation)
- **R-DDD-004** SHOULD: Controllers SHOULD remain thin, limiting them to request validation, service invocation, and response formatting
- **R-DDD-005** SHOULD: Dependency injection SHOULD be used to provide services to controllers, avoiding direct instantiation
- **R-DDD-006** MUST: Business logic MUST NOT be implemented directly in controller methods
- **R-DDD-007** SHOULD: Service classes SHOULD be placed in Services/ subdirectories within each feature area
- **R-DDD-008** SHOULD: Domain folders SHOULD be created under app/Domains/ with subfolders for each feature area

### Verify

```bash
# Count service classes in domain structure
find app/Domains -type f -name '*.php' -path '*/Services/*' | wc -l

# Verify service namespace conventions
grep -r 'namespace.*Domains.*Services' app/Domains --include='*.php' | wc -l

# Count controllers in domain web structure
find app/Domains -type f -name '*Controller.php' -path '*/Web/Controllers/*' | wc -l
```

**Accept when:**
- Service classes exist in app/Domains/{Domain}/{Feature}/Services/ directories
- Controllers exist in app/Domains/{Domain}/{Feature}/Web/Controllers/ directories
- At least 3 domain service classes follow the established pattern
- Controllers do not contain business logic exceeding complexity thresholds
- Service classes are properly namespaced with Domains\{Domain}\{Feature}\Services pattern

<enforcement>
Claude Code MUST verify directory structure and namespace compliance before accepting code changes. CI pipeline checks for proper file organization MUST pass. Pull requests containing controllers with business logic or misplaced service classes MUST be blocked.
</enforcement>
