<rule_activation id="6b0fe053-7ede-4625-82e3-a79dd3a91ea5" title="Adopt Domain-Driven Service Layer Pattern for Journal Management: Service Classes Follow" applies_to="app/Domains/Vault/ManageJournals/**/*.php">
These rules are ALWAYS ACTIVE for all service layer implementations within the Vault domain's ManageJournals subdomain.
</rule_activation>

### Rules

- **R-DDD-001** MUST: Service classes MUST follow single-responsibility principle with one primary operation per class (e.g., CreatePostMetric, DestroySliceOfLife, UpdateJournalMetric)
- **R-DDD-002** MUST: Service class names MUST follow verb-noun convention to clearly communicate intent
- **R-DDD-003** MUST: Controllers MUST remain thin and delegate business logic to services rather than implementing it directly
- **R-DDD-004** MUST: Services MUST accept primitive types or DTOs as parameters rather than HTTP request objects to maintain independence from web layer
- **R-DDD-005** SHOULD: Use dependency injection for service dependencies to improve testability and enable mocking
- **R-DDD-006** SHOULD: Group related services in subdirectories if a domain grows large (e.g., ManageJournals/Services/Posts, ManageJournals/Services/Metrics)
- **R-DDD-007** SHOULD: Ensure services encapsulate meaningful business logic, validation, or orchestration beyond simple delegation

### Verify

```bash
# Count service classes in domain
find app/Domains/Vault/ManageJournals/Services -type f -name '*.php' | wc -l

# Count controllers in domain
grep -r 'class.*Controller' app/Domains/Vault/ManageJournals/Web/Controllers | wc -l

# Verify service namespace structure
grep -r 'namespace.*Services' app/Domains/Vault/ManageJournals/Services | head -5

# Check for business logic in controllers (should return minimal results)
grep -r 'DB::transaction\|Model::create\|->save()' app/Domains/Vault/ManageJournals/Web/Controllers | wc -l
```

**Accept when:**
- Service classes exist in dedicated Services directories within domain boundaries
- Controllers delegate to services rather than implementing business logic directly
- Service class names follow verb-noun convention and implement single-responsibility operations
- Services accept DTOs or primitive types as parameters, not HTTP request objects
- Related services are grouped in logical subdirectories
