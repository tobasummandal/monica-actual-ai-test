<rule_activation id="0bec545f-dc19-4467-8277-12b6d25a4323" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Pipelines Execute Both" applies_to="**/*">
These rules are ALWAYS ACTIVE for test files in `tests/Unit/**/*.php` and `tests/Feature/**/*.php`, CI/CD pipeline configurations (`.github/workflows/*`, `.gitlab-ci.yml`), PHPUnit configuration (`phpunit.xml`), and test execution scripts.
</rule_activation>

### Rules

- **R-CICD-001** MUST: CI/CD pipelines MUST execute both unit and feature test suites on every commit.
- **R-TEST-001** MUST: Test files MUST be organized in `tests/Unit/` and `tests/Feature/` directories according to their test type.
- **R-TEST-002** MUST: Test files MUST follow the `*Test.php` naming convention.
- **R-PHPUNIT-001** MUST: PHPUnit configuration MUST define separate test suites for 'unit' and 'feature' with appropriate directory mappings.
- **R-CICD-002** SHOULD: CI/CD pipelines SHOULD execute unit tests first (for fast feedback) followed by feature tests.

### Scope

**In scope:**
- All PHP test files in `tests/Unit/` and `tests/Feature/` directories
- CI/CD pipeline configuration files (e.g., `.github/workflows/*`, `.gitlab-ci.yml`, `phpunit.xml`)
- Test execution scripts and automation tools
- PHPUnit configuration and test suite definitions

**Out of scope:**
- Manual testing procedures and QA processes
- End-to-end browser testing frameworks (e.g., Selenium, Cypress)
- Performance and load testing suites
- Third-party package tests within vendor directories

**Exceptions:**
- EX-001: Legacy tests that predate this standard and require significant refactoring
- EX-002: Experimental or spike tests that are explicitly marked as temporary

### Verify

```bash
# Verify unit test directory exists and contains tests
grep -r "class.*Test extends" tests/Unit/ | wc -l

# Verify feature test directory exists and contains tests
grep -r "class.*Test extends" tests/Feature/ | wc -l

# Execute unit test suite
php artisan test --testsuite=unit --stop-on-failure

# Execute feature test suite
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both unit and feature test directories exist and contain test files following the `*Test.php` naming convention
- PHPUnit configuration defines separate test suites for unit and feature tests
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings

<enforcement>
Claude Code MUST NOT skip or defer verification. CI/CD pipeline checks MUST fail builds if tests are not properly organized. Code review checklist MUST verify test placement and categorization. Pull requests MUST be blocked until test organization issues are resolved.
</enforcement>
