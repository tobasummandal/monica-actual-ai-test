<rule_activation id="b1a52f3a-89dd-445d-9af0-3822c053089f" title="Adopt Eloquent ORM Models as Standard Data Access Layer: Model Specific Business" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all database-backed entities in the application. All data access operations MUST use Eloquent ORM models as the primary abstraction layer.

**In scope:**
- All persistent domain entities stored in relational database tables
- CRUD operations for File, Account, ContactInformationType, GiftOccasion, CallReasonType, PostTemplateSection, QuickFact, and similar entities
- Relationship definitions between domain entities
- Data validation rules at the model layer
- Entity-specific business logic and computed properties

**Out of scope:**
- Complex analytical queries requiring raw SQL for performance optimization
- Data transfer objects (DTOs) used for API responses or inter-service communication
- Read-only views or materialized views without corresponding base tables
- Temporary or session-based data not persisted to the database
- Third-party API integrations where data is not stored locally

**Exceptions:**
- EXC-001: Performance-critical queries require raw SQL optimization that cannot be achieved through Eloquent query builder
- EXC-002: Legacy database schemas with complex naming conventions incompatible with Eloquent conventions
- Approved exceptions must be tagged with 'raw query approved' comment
</rule_activation>

### Rules

- **R-ELQ-001** MUST: All data access operations for database-backed entities MUST use Eloquent ORM models as the primary abstraction layer. Models MUST be placed in the app/Models namespace and extend Illuminate\Database\Eloquent\Model.

- **R-ELQ-002** MUST: All models MUST define either $fillable or $guarded properties immediately after model creation to prevent mass assignment vulnerabilities.

- **R-ELQ-003** SHOULD: Model-specific business logic and computed attributes SHOULD be encapsulated within the model class using accessors, mutators, and custom methods rather than scattered across controllers or services.

- **R-ELQ-004** SHOULD: Relationship methods SHOULD be documented with PHPDoc annotations specifying return types for better IDE support and static analysis.

- **R-ELQ-005** SHOULD: Models SHOULD leverage Laravel's attribute casting ($casts property) to automatically convert database values to appropriate PHP types (dates, JSON, booleans).

- **R-ELQ-006** SHOULD: Cross-cutting concerns like logging and auditing SHOULD use model events (creating, created, updating, updated) rather than duplicating logic in controllers.

- **R-ELQ-007** SHOULD: Use 'php artisan make:model' command to generate new models following Laravel conventions automatically.

- **R-ELQ-008** MAY: Model factories MAY be used for testing to generate realistic test data without manual array construction.

### Verify

```bash
# Count model files extending Model class
grep -r 'extends Model' app/Models/ | wc -l

# Find model files with incorrect namespace
find app/Models -type f -name '*.php' | xargs grep -L 'namespace App\\Models'

# Show all models with their database tables
php artisan model:show --all | grep -E '(Table|Database)'

# Detect direct DB facade calls (excluding approved exceptions)
grep -r 'DB::select\|DB::insert\|DB::update\|DB::delete' app/Http/Controllers/ app/Services/ | grep -v 'raw query approved'
```

**Accept when:**
- All model files exist in app/Models namespace and extend Illuminate\Database\Eloquent\Model
- No direct DB facade calls for CRUD operations found in controllers or services (excluding approved exceptions)
- Model count matches database table count for domain entities (excluding pivot tables and migrations table)
- All models define either $fillable or $guarded properties for mass assignment protection

<enforcement>
Claude Code MUST verify compliance before considering data access tasks complete. Verification commands MUST be executed to detect:
- Direct DB facade usage in controllers/services without exception documentation
- Models missing mass assignment protection ($fillable/$guarded)
- New database tables without corresponding model classes
- N+1 query problems through Laravel Debugbar or Telescope monitoring

Violations MUST be remediated before code review approval. Exception requests require Tech Lead review with performance benchmarks or technical justification documented in code comments.
</enforcement>
