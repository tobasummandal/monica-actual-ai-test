<rule_activation id="29c6e2a5-e3bd-4711-9861-ba5514ee721c" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Feature Tests Placed" applies_to="tests/**/*.php">
These rules are ALWAYS ACTIVE for all PHP test files in the tests/ directory.
</rule_activation>

### Rules

- **R-TEST-001** MUST: All feature tests MUST be placed in the tests/Feature directory for end-to-end scenario validation.

### Verify

```bash
# Count unit tests
grep -r "class.*Test extends" tests/Unit/ | wc -l

# Count feature tests
grep -r "class.*Test extends" tests/Feature/ | wc -l

# Run unit tests with fail-fast
php artisan test --testsuite=unit --stop-on-failure

# Run feature tests with fail-fast
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both unit and feature test directories exist and contain test files following the *Test.php naming convention
- PHPUnit configuration defines separate test suites for unit and feature tests
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings

<enforcement>
Claude Code MUST NOT skip or defer verification. Test organization violations MUST block pull requests until resolved.
</enforcement>
