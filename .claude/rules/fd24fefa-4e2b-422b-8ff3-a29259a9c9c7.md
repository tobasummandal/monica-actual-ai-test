These rules are ALWAYS ACTIVE for all files matching domain models, resource classes, and data transfer objects within the application.
</rule_activation>

### Rules

- **R-DDD-001** SHOULD: Resource transformation logic (converting between domain models and external formats) SHOULD be encapsulated within dedicated resource classes.

### Verify

```bash
# Count domain models in app/Models directory
find app/Models -name '*.php' -type f | wc -l

# Count resource classes in domain-specific directories
grep -r 'class.*Resource' app/Domains/ --include='*.php' | wc -l

# Verify DAV domain structure exists
find app/Domains -type d -name 'Dav' | wc -l
```

**Accept when:**
- All domain entities have corresponding model classes in `app/Models/` or domain-specific directories
- External protocol integrations use dedicated resource classes separate from core models
- Domain organization follows consistent directory structure with clear bounded contexts
- Resource transformation methods use consistent naming conventions (e.g., `toVCard()`, `fromVCard()`)
- Models are organized within `app/Domains/{DomainName}/` subdirectories to maintain bounded contexts

<enforcement>
Claude Code MUST verify model organization and resource class separation during code review. Violations flagged by static analysis or CI pipeline checks MUST be resolved before merge. Architecture review is required for new domain contexts to ensure consistent application of this pattern.
</enforcement>
