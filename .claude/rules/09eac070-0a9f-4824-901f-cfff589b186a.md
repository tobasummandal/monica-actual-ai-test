<rule_activation id="09eac070-0a9f-4824-901f-cfff589b186a" title="Adopt Laravel Fortify for Authentication Action Standardization: Feature Tests Authentication" applies_to="**/*">
These rules are ALWAYS ACTIVE for all Laravel authentication implementations, particularly in app/Actions/Fortify, app/Domains/Settings, and feature tests validating authentication behavior.
</rule_activation>

### Rules

- **R-FORTIFY-001** SHOULD: Feature tests for authentication operations SHOULD verify behavior independently of presentation layer to ensure deployment target flexibility.

### Verify

```bash
# Verify Fortify action classes are properly extended
grep -r "extends.*Fortify" app/Actions/Fortify/ | wc -l

# Verify domain services exist in proper structure
find app/Domains -name "*Service.php" -path "*/Services/*" | wc -l

# Verify Hash facade is used consistently for password operations
grep -r "use Illuminate\\Support\\Facades\\Hash" app/Actions/Fortify app/Domains/Settings | wc -l

# Run authentication and password feature tests
php artisan test --filter=Auth --filter=Password --filter=Account
```

**Accept when:**
- All authentication actions in app/Actions/Fortify extend appropriate Fortify contracts and are registered in FortifyServiceProvider
- Domain-specific user management services exist in app/Domains/*/Services and delegate to Fortify actions for password operations
- Feature tests for authentication operations pass and cover both web and API scenarios without presentation layer dependencies
- Password validation uses Laravel Hash facade consistently across all authentication touchpoints

<enforcement>
Claude Code MUST verify all authentication implementations comply with Fortify standardization patterns. Verification is mandatory before accepting authentication-related changes. CI pipeline enforcement includes automated checks for Fortify action classes, domain services, Hash facade usage, and feature test coverage.
</enforcement>
