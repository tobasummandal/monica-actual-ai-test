<rule_activation id="c7d508f8-a653-4b4e-81f9-abb9a93be690" title="Adopt HTTP Client Libraries for External API Integration: Http Client Implementations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. All outbound HTTP/HTTPS requests to external APIs and services MUST use established HTTP client libraries with proper middleware patterns for authentication, logging, and error handling.
</rule_activation>

### Rules

- **R-HTTP-001** SHOULD: HTTP client implementations SHOULD support middleware patterns for cross-cutting concerns like logging, retry logic, and authentication.

### Scope

**In scope:**
- All outbound HTTP/HTTPS requests to external APIs and services
- OAuth provider integrations (Google, Facebook, GitHub, etc.)
- WebDAV, CalDAV, and CardDAV protocol communications
- Third-party REST API consumption (Wikipedia, documentation services, etc.)
- vCard and vCalendar data import/export operations

**Out of scope:**
- Internal service-to-service communication within the same application
- Database connections and queries
- File system operations
- Message queue or event bus communications
- WebSocket connections (unless using HTTP upgrade mechanism)

**Exceptions:**
- EXC-001: Legacy code maintenance where refactoring risk exceeds benefit
- EXC-002: Performance-critical scenarios where library overhead is demonstrably prohibitive

### Verify

```bash
# Verify Socialite library usage for OAuth flows
grep -r "use.*Socialite" app/ --include="*.php" | wc -l

# Verify Sabre DAV/VObject libraries for DAV protocol and vCard/vCalendar
grep -r "use.*Sabre" app/ --include="*.php" | wc -l

# Verify no raw cURL or socket implementations
grep -r "curl_exec\|fsockopen" app/ --include="*.php" | wc -l
```

**Accept when:**
- Socialite library usage is detected in OAuth authentication flows
- Sabre DAV/VObject libraries are used for DAV protocol and vCard/vCalendar operations
- No raw cURL or socket implementations are found in new external API integration code
- Service classes encapsulate HTTP client library usage with clear domain interfaces
- HTTP clients are configured with appropriate timeouts, retry policies, and error handling strategies
- Dependency injection is used to provide HTTP client instances for testability
- External API calls include logging and monitoring for performance tracking

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated code review checks MUST scan for raw HTTP implementation patterns (curl_exec, fsockopen). Dependency analysis MUST ensure approved HTTP client libraries are present in composer.json. Manual code review MUST focus on external API integration patterns and library usage. Unit test coverage is REQUIRED for service classes wrapping external API calls. CI pipeline MUST fail if raw HTTP implementations are detected in new code without documented exceptions.
</enforcement>
