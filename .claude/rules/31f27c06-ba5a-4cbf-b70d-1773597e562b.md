<rule_activation id="31f27c06-ba5a-4cbf-b70d-1773597e562b" title="Adopt Laravel Fortify for Authentication Action Standardization: Authentication Actions Password" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching authentication actions, domain services, and feature tests related to user lifecycle and password management operations.
</rule_activation>

### Rules

- **R-FORTIFY-001** MUST: All authentication actions (password reset, password update, user creation) MUST be implemented as Laravel Fortify action classes in the app/Actions/Fortify namespace.
- **R-FORTIFY-002** MUST: Domain-specific user management services MUST be placed in app/Domains/{DomainName}/Services and follow single-responsibility principle, handling one user lifecycle operation per service.
- **R-FORTIFY-003** MUST: Use Laravel's validation rules for password requirements (min:8, confirmed, etc.) consistently across all authentication actions.
- **R-FORTIFY-004** MUST: Use Laravel's Hash facade consistently across all authentication touchpoints for password hashing operations.
- **R-FORTIFY-005** SHOULD: Feature tests SHOULD use Laravel's authentication testing helpers (actingAs, assertAuthenticated) and test both success and failure scenarios.
- **R-FORTIFY-006** SHOULD: Feature tests SHOULD cover both web and API scenarios without presentation layer dependencies.
- **R-FORTIFY-007** SHOULD: Document the decision boundary between Fortify actions (framework-level authentication) and domain services (business-specific user management) in team guidelines.

### Verify

```bash
# Count Fortify action classes extending appropriate contracts
grep -r "extends.*Fortify" app/Actions/Fortify/ | wc -l

# Count domain-specific user management services
find app/Domains -name "*Service.php" -path "*/Services/*" | wc -l

# Verify Hash facade usage across authentication touchpoints
grep -r "use Illuminate\\Support\\Facades\\Hash" app/Actions/Fortify app/Domains/Settings | wc -l

# Run authentication and password feature tests
php artisan test --filter=Auth --filter=Password --filter=Account
```

**Accept when:**
- All authentication actions in app/Actions/Fortify extend appropriate Fortify contracts and are registered in FortifyServiceProvider
- Domain-specific user management services exist in app/Domains/*/Services and delegate to Fortify actions for password operations
- Feature tests for authentication operations pass and cover both web and API scenarios without presentation layer dependencies
- Password validation uses Laravel Hash facade consistently across all authentication touchpoints
- No authentication logic is detected in controllers without corresponding Fortify action or domain service
