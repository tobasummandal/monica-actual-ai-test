<rule_activation id="7faedac6-afc3-4945-b346-b17b95bc401f" title="Adopt Laravel Migrations as Standard Database Schema Management: Migrations Include Data" applies_to="database/migrations/**/*.php">
These rules are ALWAYS ACTIVE for all database schema changes across the application. All schema modifications MUST be implemented through Laravel migration files.
</rule_activation>

### Rules

- **R-LMIG-001** MUST: All table creation, modification, and deletion operations be implemented through Laravel migration files.
- **R-LMIG-002** MUST: All column additions, modifications, and removals be implemented through Laravel migration files.
- **R-LMIG-003** MUST: All index creation and removal operations be implemented through Laravel migration files.
- **R-LMIG-004** MUST: All foreign key constraint definitions be implemented through Laravel migration files.
- **R-LMIG-005** MUST: All database-level configuration changes affecting schema structure be implemented through Laravel migration files.
- **R-LMIG-006** MUST: Each migration file contain both up() and down() methods using Schema Builder API.
- **R-LMIG-007** MUST: Migration files follow Laravel's timestamp-based naming convention (YYYY_MM_DD_HHMMSS_description.php).
- **R-LMIG-008** MUST: Migrations be tested locally with both 'migrate' and 'migrate:rollback' commands before committing.
- **R-LMIG-009** MAY: Migrations include data seeding operations when necessary for schema-dependent reference data, though seeders are preferred for test data.
- **R-LMIG-010** SHOULD: Use Laravel's migration methods like 'foreignId()', 'timestamps()', 'softDeletes()' for consistency with framework conventions.
- **R-LMIG-011** SHOULD: Separate schema changes from data migrations into distinct migration files for clarity when performing complex data transformations.
- **R-LMIG-012** SHOULD: Document any database-specific SQL used in migrations with comments explaining compatibility implications.

### Verify

```bash
# Count migration files
find database/migrations -name '*.php' -type f | wc -l | grep -E '^[0-9]+$'

# Verify Schema Builder usage
grep -r 'Schema::create\|Schema::table\|Schema::drop' database/migrations/ | wc -l

# Check migration status
php artisan migrate:status 2>&1 | grep -E 'Ran|Pending'

# Verify up() and down() methods exist
ls database/migrations/*.php 2>/dev/null | head -5 | xargs grep -l 'function up()' | xargs grep -l 'function down()'
```

**Accept when:**
- All migration files exist in database/migrations directory and follow Laravel naming convention with timestamps
- Each migration file contains both up() and down() methods using Schema Builder API
- Migration status command executes successfully showing tracked migrations
- No direct SQL schema modifications are found in application code outside migration files
- Migration files use Schema Builder methods rather than raw SQL for schema operations
- Complex data transformations are separated into distinct migration files
