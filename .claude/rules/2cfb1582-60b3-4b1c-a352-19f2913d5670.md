These rules are ALWAYS ACTIVE for all files matching public API contracts, DTOs, interfaces, and exception handlers across the codebase.
</rule_activation>

### Rules

- **R-API-001** SHOULD_NOT: Public API contracts SHOULD NOT expose internal domain models directly; always use DTOs or resource representations.

### Verify

```bash
# Count DTO classes in domain layer
grep -r "class.*Dto" app/Domains --include="*.php" | wc -l

# Count interface definitions with I prefix
grep -r "interface I[A-Z]" app/Domains --include="*.php" | wc -l

# Count custom exception classes
grep -r "class.*Exception extends" app/Exceptions --include="*.php" | wc -l

# Count ViewHelper classes
find app/Domains -name "*ViewHelper.php" -type f | wc -l
```

**Accept when:**
- All public API endpoints have corresponding interface definitions with explicit method signatures
- All API request/response payloads use dedicated DTO classes rather than exposing domain models
- All public API error conditions throw domain-specific exceptions with clear messages
- Grep commands show consistent presence of DTOs, interfaces, custom exceptions, and ViewHelpers across API-related code
- No direct domain model exposure detected in API controllers or public service methods
- All interface methods include PHP type hints and return type declarations
- All public interfaces and DTOs include PHPDoc annotations with @api tag

<enforcement>
Claude Code MUST NOT skip or defer verification. All public API contracts must comply with interface-based DTO and exception handling patterns before code review approval. Violations trigger CI build failures and code review blocks.
</enforcement>
