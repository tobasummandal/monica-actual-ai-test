<rule_activation id="cd5178e5-b2ff-4f5b-92f3-46eb906290d3" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Domain Specific Tests" applies_to="tests/**/*.php">
These rules are ALWAYS ACTIVE for all PHP test files in the tests/ directory. Domain-specific tests MUST be organized in subdirectories reflecting the application's domain structure, with clear separation between Unit and Feature tests to enable faster feedback loops and improved maintainability.
</rule_activation>

### Rules

- **R-TEST-001** SHOULD: Domain-specific tests SHOULD be organized in subdirectories reflecting the application's domain structure (Contact, DAV, Jetstream, etc.).
- **R-TEST-002** SHOULD: Unit tests SHOULD be located in `tests/Unit/` directory with domain-specific subdirectories.
- **R-TEST-003** SHOULD: Feature tests SHOULD be located in `tests/Feature/` directory with domain-specific subdirectories.
- **R-TEST-004** SHOULD: All test files SHOULD follow the `*Test.php` naming convention.
- **R-TEST-005** SHOULD: PHPUnit configuration SHOULD define separate test suites for 'unit' and 'feature' with appropriate directory mappings.
- **R-TEST-006** SHOULD: CI/CD pipeline SHOULD execute unit tests first (php artisan test --testsuite=unit) followed by feature tests (php artisan test --testsuite=feature).
- **R-TEST-007** MAY: Legacy tests that predate this standard and require significant refactoring MAY be exempted via exception process (EX-001).
- **R-TEST-008** MAY: Experimental or spike tests explicitly marked as temporary MAY be exempted via exception process (EX-002).

### Verify

```bash
# Count unit tests
grep -r "class.*Test extends" tests/Unit/ | wc -l

# Count feature tests
grep -r "class.*Test extends" tests/Feature/ | wc -l

# Execute unit tests with fail-fast
php artisan test --testsuite=unit --stop-on-failure

# Execute feature tests with fail-fast
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both `tests/Unit/` and `tests/Feature/` directories exist and contain test files following the `*Test.php` naming convention
- PHPUnit configuration (phpunit.xml) defines separate test suites for 'unit' and 'feature' tests with correct directory mappings
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings
- Domain-specific subdirectories are present and organized consistently (e.g., tests/Unit/Contact/, tests/Feature/DAV/)
