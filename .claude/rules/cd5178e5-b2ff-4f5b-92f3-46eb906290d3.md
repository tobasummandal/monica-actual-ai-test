<rule_activation id="cd5178e5-b2ff-4f5b-92f3-46eb906290d3" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Domain Specific Tests" applies_to="**/*">
These rules are ALWAYS ACTIVE for all test files and CI/CD pipeline configurations.
</rule_activation>

### Rules

- **R-TEST-ORG-001** SHOULD: Domain-specific tests SHOULD be organized in subdirectories reflecting the application's domain structure (e.g., Contact, DAV, Jetstream)
- **R-TEST-ORG-002** MUST: Unit tests MUST be placed in tests/Unit/ directory
- **R-TEST-ORG-003** MUST: Feature tests MUST be placed in tests/Feature/ directory
- **R-TEST-ORG-004** MUST: Test files MUST follow the *Test.php naming convention
- **R-TEST-ORG-005** MUST: PHPUnit configuration MUST define separate test suites for 'unit' and 'feature' with appropriate directory mappings
- **R-TEST-ORG-006** MUST: CI/CD pipeline MUST execute unit tests first (php artisan test --testsuite=unit) followed by feature tests (php artisan test --testsuite=feature)

### Scope

**In scope:**
- All PHP test files in tests/Unit and tests/Feature directories
- CI/CD pipeline configuration files (e.g., .github/workflows, .gitlab-ci.yml, phpunit.xml)
- Test execution scripts and automation tools
- PHPUnit configuration and test suite definitions

**Out of scope:**
- Manual testing procedures and QA processes
- End-to-end browser testing frameworks (e.g., Selenium, Cypress)
- Performance and load testing suites
- Third-party package tests within vendor directories

**Exceptions:**
- EX-001: Legacy tests that predate this standard and require significant refactoring
- EX-002: Experimental or spike tests that are explicitly marked as temporary

### Verify

```bash
# Count unit test files
grep -r "class.*Test extends" tests/Unit/ | wc -l

# Count feature test files
grep -r "class.*Test extends" tests/Feature/ | wc -l

# Execute unit test suite
php artisan test --testsuite=unit --stop-on-failure

# Execute feature test suite
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both unit and feature test directories exist and contain test files following the *Test.php naming convention
- PHPUnit configuration defines separate test suites for unit and feature tests
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated CI/CD pipeline checks MUST fail builds if tests are not properly organized. Code reviews MUST verify test placement and categorization before merge.
</enforcement>
