<rule_activation id="22f64611-6976-4b62-8033-98aa33072ed3" title="Standardize External API Integration with DAV Protocol and DTO Pattern: Protocol Specific Operations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API integrations, particularly DAV, CardDAV, and CalDAV protocol implementations, as well as data transfer operations between external systems and internal domain models.
</rule_activation>

### Rules

- **R-DAV-001** MUST: Protocol-specific operations MUST be abstracted behind interface contracts (e.g., IDAVBackend) to enable multiple implementations and improve testability.
- **R-DAV-002** MUST: All external API integrations MUST use DTO classes for data transfer with at least one DTO per external entity type.
- **R-DAV-003** MUST: Domain-specific exception types MUST exist for common API failure scenarios (permission, compliance, limits) and MUST be properly caught in controllers.
- **R-DAV-004** MUST: ViewHelper classes MUST be present for domains that expose external APIs and MUST be used in controller response preparation.
- **R-DAV-005** MUST: Permission validation and error handling MUST be implemented for all public-facing API endpoints that interact with external systems.
- **R-DAV-006** SHOULD: When creating new external API integrations, start by defining DTO classes that represent the external data format, then create mappers to internal domain models.
- **R-DAV-007** SHOULD: Define backend interfaces before implementing concrete classes; use dependency injection to provide implementations to consumers.
- **R-DAV-008** SHOULD: Create domain-specific exception types in the appropriate domain namespace with descriptive names and error messages.
- **R-DAV-009** SHOULD: Add the Loggable trait to API client classes to ensure consistent logging of external API interactions for debugging and monitoring.

### Verify

```bash
# Count DTO classes in external API integration paths
grep -r "class.*Dto" app/Domains/*/DavClient/Services/Utils/Model/ | wc -l

# Count backend interface definitions
grep -r "interface.*Backend" app/Domains/*/Dav/Web/Backend/ | wc -l

# Count domain-specific exception types for common failure scenarios
grep -r "class.*Exception extends" app/Domains/ | grep -E "(Permission|Compliant|Maximum)" | wc -l

# Count ViewHelper classes in domains with external APIs
find app/Domains -name "*ViewHelper.php" -type f | wc -l
```

**Accept when:**
- All external API integrations use DTO classes for data transfer with at least one DTO per external entity type
- Protocol-specific operations are abstracted behind interface contracts with at least one concrete implementation
- Domain-specific exception types exist for common API failure scenarios (permission, compliance, limits) and are properly caught in controllers
- ViewHelper classes are present for domains that expose external APIs and are used in controller response preparation
- All external API client classes include the Loggable trait for consistent logging
- No direct external API usage exists without DTO abstraction in new code
