<rule_activation id="4033e547-681d-462f-b7f2-0bd187f9ccf8" title="Adopt Domain-Driven Controller Organization for Journal Management: Each Distinct Entity" applies_to="app/Domains/Vault/ManageJournals/Web/Controllers/**/*.php">
These rules are ALWAYS ACTIVE for all web controllers within the Vault/ManageJournals domain.

**In scope:**
- All web controllers within the Vault domain
- Controllers handling journal, post, photo, metric, and slice of life entities
- New controllers added to the ManageJournals bounded context
- API and web interface controllers for journal management

**Out of scope:**
- Service classes and business logic layers
- Data transfer objects and view models
- Repository implementations
- Console commands and CLI controllers
- Background job handlers

**Exceptions:**
- EX-001: A controller handles cross-domain concerns that cannot be reasonably placed within a single domain boundary
- EX-002: Legacy controllers exist outside this structure and refactoring would introduce significant risk
</rule_activation>

### Rules

- **R-DDD-CTRL-001** MUST: Each distinct entity or concern within journal management (journals, posts, photos, metrics, slices of life) MUST have a dedicated controller class.
- **R-DDD-CTRL-002** MUST: All controller files in the ManageJournals domain MUST be located under `app/Domains/Vault/ManageJournals/Web/Controllers`.
- **R-DDD-CTRL-003** MUST: Controller namespaces MUST match their directory structure following the pattern `App\Domains\Vault\ManageJournals\Web\Controllers`.
- **R-DDD-CTRL-004** MUST: Each controller MUST have a single, clear responsibility corresponding to an entity or entity-concern combination (single responsibility principle).
- **R-DDD-CTRL-005** SHOULD: Use a base controller class at `app/Domains/Vault/ManageJournals/Web/Controllers/Controller.php` to share common functionality across domain controllers.
- **R-DDD-CTRL-006** SHOULD: Use Laravel route grouping to organize routes by domain: `Route::group(['namespace' => 'App\\Domains\\Vault\\ManageJournals\\Web\\Controllers'], ...)`.
- **R-DDD-CTRL-007** SHOULD: Use PHP traits for cross-cutting concerns like authorization, validation, and response formatting to avoid duplication across controllers.
- **R-DDD-CTRL-008** MUST NOT: Create controllers outside the designated domain structure unless an approved exception (EX-001 or EX-002) applies.
- **R-DDD-CTRL-009** MUST NOT: Combine unrelated entities or concerns into a single controller (prevents controller bloat).

## Rationale Summary

- Domain-driven organization improves code discoverability by grouping related controllers together based on business capabilities
- Separating controllers by entity and concern prevents controller bloat and maintains single responsibility principle
- The Web/Controllers subdirectory structure allows for future expansion to include API controllers, GraphQL resolvers, or other interface types
- Pattern demonstrates consistent application across 8 files with 79.75% confidence, indicating established architectural standard

## Risks and Mitigations

| Risk | Mitigation | Owner |
|------|------------|-------|
| Inconsistent controller organization | Implement automated checks in CI pipeline, provide clear documentation | Engineering team |
| Over-fragmentation leading to excessive indirection | Establish guidelines for when to create new controllers vs. adding methods | Architecture team |
| Tight coupling between controllers and domain structure | Use route naming and dependency injection to decouple route definitions | Engineering team |
