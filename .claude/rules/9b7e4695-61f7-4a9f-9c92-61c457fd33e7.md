<rule_activation id="9b7e4695-61f7-4a9f-9c92-61c457fd33e7" title="Adopt Eloquent ORM Models as Standard Data Modeling Pattern: Domain Entities That" applies_to="app/Models/**/*.php">
These rules are ALWAYS ACTIVE for all data modeling activities within the application layer. All domain entities that map to database tables MUST be represented as Eloquent Model classes.
</rule_activation>

### Rules

- **R-29-001** MUST: All domain entities that map to database tables MUST be represented as Eloquent Model classes extending `Illuminate\Database\Eloquent\Model`.
- **R-29-002** MUST: Configure mass assignment protection immediately when creating models by defining `$fillable` or `$guarded` arrays.
- **R-29-003** MUST: Define relationships in dedicated methods using Eloquent relationship types and document inverse relationships for bidirectional navigation.
- **R-29-004** SHOULD: Use model observers or events for cross-cutting concerns like logging, caching, or notifications rather than duplicating logic across controllers.
- **R-29-005** SHOULD: Leverage Laravel's model factories for test data generation to improve test maintainability.
- **R-29-006** SHOULD: Implement query monitoring in development and use Laravel Debugbar to detect N+1 queries.
- **R-29-007** SHOULD: Establish code review checklist for relationship loading patterns to prevent N+1 query performance issues.
- **R-29-008** MUST: Extract business logic to service classes; do not allow models to become bloated with too many responsibilities.

### Verify

```bash
# Verify all model files extend Eloquent Model
find app/Models -type f -name '*.php' | xargs grep -L 'extends Model' | wc -l | grep -q '^0$'

# Verify proper namespace usage
grep -r 'namespace App\\Models' app/Models/*.php | wc -l

# Verify model class structure
php artisan tinker --execute="echo count(get_declared_classes())" 2>&1 | grep -q '[0-9]'
```

**Accept when:**
- All PHP files in `app/Models` directory extend `Illuminate\Database\Eloquent\Model` class
- Model classes are properly namespaced under `App\Models` and follow PSR-4 autoloading standards
- No direct database queries using `DB` facade exist in controller methods where Eloquent models are available
- All models have `$fillable` or `$guarded` arrays defined for mass assignment protection
- Relationships are properly eager-loaded to prevent N+1 query problems
- Code review checklist includes verification of mass assignment protection and relationship eager loading
- Business logic is extracted to service classes, not embedded in models

<enforcement>
Claude Code MUST verify all rules in this activation block. Violations of R-29-001 through R-29-008 MUST be flagged during code review. CI pipeline MUST fail if models are detected outside `app/Models` namespace or not extending base Model class. Code review MUST block merge if models contain business logic beyond data access concerns.
</enforcement>
