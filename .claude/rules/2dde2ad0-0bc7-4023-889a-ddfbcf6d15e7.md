<rule_activation id="2dde2ad0-0bc7-4023-889a-ddfbcf6d15e7" title="Standardize Exception and Logging Formatting for External API Responses: Exception Classes Exposed" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API endpoints and exception handling components. All new exception classes and logging utilities MUST comply with the formatting standards defined herein.
</rule_activation>

### Rules

- **R-API-001** MUST: All exception classes exposed through external APIs MUST implement a consistent formatter interface or trait that standardizes error response structure.
- **R-API-002** MUST: All custom exception classes that can be thrown from external API endpoints MUST follow the standardized formatter pattern.
- **R-API-003** MUST: Logging utilities and traits used within API request/response lifecycle MUST implement the same formatting methods as exception classes.
- **R-API-004** MUST: Error response middleware and exception handlers for public APIs MUST enforce consistent error response formatting.
- **R-API-005** MUST: API documentation and OpenAPI specifications MUST describe standardized error formats.
- **R-API-006** SHOULD: Create a base Formattable interface or trait defining methods like toArray(), toJson(), and getHttpStatusCode().
- **R-API-007** SHOULD: Establish a standard error response schema (e.g., {error: {code, message, status, timestamp, context}}).
- **R-API-008** SHOULD: Refactor existing exception classes to serve as reference implementations of the formatter pattern.
- **R-API-009** SHOULD: Create generator/scaffold commands for new exception classes that automatically include formatter implementation.
- **R-API-010** MAY: Use centralized exception handler middleware as a complementary approach to provide fallback formatting for unexpected exceptions.

### Verify

```bash
# Verify all exception classes in API routes implement Formattable interface
grep -r "class.*Exception" app/ | xargs -I {} sh -c 'grep -l "Formattable\|toArray\|toJson" {}'

# Run exception formatter tests
php artisan test --filter ExceptionFormatterTest

# Verify Loggable trait uses consistent formatting
grep -r "use.*Loggable" app/ | xargs -I {} sh -c 'grep -l "format\|toArray" {}'
```

**Accept when:**
- All exception classes in app/Exceptions/ that are thrown from API routes implement the Formattable interface or equivalent formatter trait
- Automated tests verify that exception responses match the documented JSON schema with required fields (code, message, status, timestamp)
- The Loggable trait and all exception formatters produce structurally consistent output as verified by integration tests
- Static analysis tools (PHPStan/Psalm) confirm Formattable interface requirement on exception classes
- API contract tests validate error response structures against schema
