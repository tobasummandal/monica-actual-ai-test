<rule_activation id="b347b046-c7f7-499b-886e-1ebe42d85499" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: Background Jobs That" applies_to="app/Domains/**/*.php,app/Helpers/**/*.php">
These rules are ALWAYS ACTIVE for all files in domain services (app/Domains/*/Services/), view helpers (app/Domains/*/Web/ViewHelpers/), background jobs (app/Domains/*/Jobs/), and global helpers (app/Helpers/).

**In scope:**
- All domain service classes in app/Domains/*/Services/
- All view helper classes in app/Domains/*/Web/ViewHelpers/
- All background jobs in app/Domains/*/Jobs/
- Global helper files in app/Helpers/
- Any code that reads from or writes to the primary application database

**Out of scope:**
- Third-party library code in vendor/
- Database migrations and seeders
- Cache layer implementations
- External API integrations that don't touch the primary datastore
- Read-only reporting queries in dedicated analytics modules

**Exceptions:**
- EXC-001: Performance-critical queries require raw SQL optimization
- EXC-002: Legacy code refactoring is planned but not yet completed
</rule_activation>

### Rules

- **R-DA-001** MUST: Background jobs that access datastores MUST implement proper error handling and transaction management.
- **R-DA-002** MUST: Use Laravel Eloquent models as the primary ORM abstraction for all domain entities.
- **R-DA-003** MUST: Inject model dependencies into service constructors rather than using static calls or facades for better testability.
- **R-DA-004** SHOULD: For view helpers that need data, prefer calling service layer methods or creating dedicated query classes.
- **R-DA-005** MUST: Background jobs should wrap datastore operations in database transactions where data consistency is critical.
- **R-DA-006** MUST: Create shared helper utilities in app/Helpers/ for common query patterns (e.g., ScoutHelper for search functionality).
- **R-DA-007** MUST: Document any raw SQL queries with comments explaining why ORM was insufficient.

### Verify

```bash
# Check for undocumented raw SQL usage
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access tests
php artisan test --filter=DataAccessTest

# Run static analysis
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections

<enforcement>
Claude Code MUST NOT skip or defer verification.

**Automated verification:**
- CI pipeline runs static analysis (PHPStan) to detect direct SQL usage
- Pre-commit hooks run linting rules that flag non-compliant data access
- CI build fails if static analysis detects unapproved direct SQL queries

**Code review:**
- Code review checklist includes verification of datastore access patterns
- Pull requests with violations are blocked until corrected or exception is documented

**Exception process:**
1. Developer creates exception request with performance justification and benchmark data
2. Tech lead reviews and approves/rejects based on documented criteria
3. Approved exceptions are documented in code comments with ticket references
4. Exception registry is maintained and reviewed quarterly for potential refactoring

**Periodic audit:**
- Quarterly code audits identify and prioritize refactoring of non-compliant legacy code
</enforcement>
