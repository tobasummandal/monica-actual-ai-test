<rule_activation id="b347b046-c7f7-499b-886e-1ebe42d85499" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: Background Jobs That" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching domain services, view helpers, background jobs, and global helpers that access primary datastores.
</rule_activation>

### Rules

- **R-DATASTORE-001** MUST: Background jobs that access datastores MUST implement proper error handling and transaction management.
- **R-DATASTORE-002** MUST: Use Laravel Eloquent models as the primary ORM abstraction for all domain entities.
- **R-DATASTORE-003** MUST: Inject model dependencies into service constructors rather than using static calls or facades for better testability.
- **R-DATASTORE-004** SHOULD: For view helpers that need data, prefer calling service layer methods or creating dedicated query classes.
- **R-DATASTORE-005** SHOULD: Wrap datastore operations in database transactions where data consistency is critical.
- **R-DATASTORE-006** SHOULD: Create shared helper utilities in app/Helpers/ for common query patterns.
- **R-DATASTORE-007** MUST: Document any raw SQL queries with comments explaining why ORM was insufficient.

### Verify

```bash
# Detect direct SQL usage without performance exception comments
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access pattern tests
php artisan test --filter=DataAccessTest

# Static analysis for data access patterns
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections
- Background jobs implement proper error handling and transaction management
- Model dependencies are injected into service constructors

<enforcement>
Claude Code MUST NOT skip or defer verification. All datastore access patterns MUST comply with R-DATASTORE rules. CI pipeline enforcement is mandatory: builds fail if static analysis detects unapproved direct SQL queries, and pull requests are blocked until violations are corrected or documented exceptions are approved.
</enforcement>
