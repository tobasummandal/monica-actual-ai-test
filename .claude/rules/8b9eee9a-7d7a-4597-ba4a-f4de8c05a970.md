<rule_activation id="8b9eee9a-7d7a-4597-ba4a-f4de8c05a970" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: Helper Classes Provide" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching domain services, view helpers, background jobs, and global helper files that interact with primary datastores.
</rule_activation>

### Rules

- **R-DS-001** MAY: Helper classes MAY provide utility functions for common datastore query patterns, but MUST remain stateless and reusable.

### Verify

```bash
# Detect direct SQL usage without performance exception comments
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access pattern tests
php artisan test --filter=DataAccessTest

# Static analysis for data access patterns
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections
- Helper classes remain stateless and reusable across multiple contexts

<enforcement>
Claude Code MUST NOT skip or defer verification. All datastore access patterns MUST comply with R-DS-001 before code is accepted. Violations block CI builds and pull requests until corrected or formally documented exceptions are approved.
</enforcement>
