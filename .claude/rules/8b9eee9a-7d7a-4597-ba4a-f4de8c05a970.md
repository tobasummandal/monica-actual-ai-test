<rule_activation id="8b9eee9a-7d7a-4597-ba4a-f4de8c05a970" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: Helper Classes Provide" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in the codebase, specifically:
- All domain service classes in app/Domains/*/Services/
- All view helper classes in app/Domains/*/Web/ViewHelpers/
- All background jobs in app/Domains/*/Jobs/
- Global helper files in app/Helpers/
- Any code that reads from or writes to the primary application database

Out of scope: Third-party library code in vendor/, database migrations and seeders, cache layer implementations, external API integrations that don't touch the primary datastore, read-only reporting queries in dedicated analytics modules.

Exceptions: EXC-001 (Performance-critical queries require raw SQL optimization), EXC-002 (Legacy code refactoring is planned but not yet completed).
</rule_activation>

### Rules

- **R-DAS-001** MAY: Helper classes MAY provide utility functions for common datastore query patterns, but MUST remain stateless and reusable.
- **R-DAS-002** MUST: Use Laravel Eloquent models as the primary ORM abstraction for all domain entities.
- **R-DAS-003** SHOULD: Inject model dependencies into service constructors rather than using static calls or facades for better testability.
- **R-DAS-004** SHOULD: For view helpers that need data, prefer calling service layer methods or creating dedicated query classes.
- **R-DAS-005** SHOULD: Background jobs SHOULD wrap datastore operations in database transactions where data consistency is critical.
- **R-DAS-006** MUST: Document any raw SQL queries with comments explaining why ORM was insufficient and include performance justification.
- **R-DAS-007** MUST: Create shared helper utilities in app/Helpers/ for common query patterns (e.g., ScoutHelper for search functionality).

### Verify

```bash
# Check for undocumented direct SQL usage
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access tests
php artisan test --filter=DataAccessTest

# Run static analysis to detect direct SQL usage
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections

<enforcement>
Claude Code MUST verify these rules before completing any changes to domain services, view helpers, background jobs, or helper files. Verification MUST NOT be skipped or deferred. CI pipeline will fail if static analysis detects unapproved direct SQL queries. Pull requests with violations are blocked until corrected or exception is documented.
</enforcement>
