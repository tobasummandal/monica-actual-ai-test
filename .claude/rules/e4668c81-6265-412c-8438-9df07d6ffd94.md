<rule_activation id="e4668c81-6265-412c-8438-9df07d6ffd94" title="Adopt Laravel Migrations as Standard Database Schema Management: Migrations Include Appropriate" applies_to="database/migrations/**/*.php">
These rules are ALWAYS ACTIVE for all database schema changes across the application. All schema modifications MUST be implemented through Laravel migration files.
</rule_activation>

### Rules

- **R-LMIG-001** SHOULD: Migrations SHOULD include appropriate indexes, foreign key constraints, and default values as part of the schema definition.

### Verify

```bash
# Count migration files in database/migrations directory
find database/migrations -name '*.php' -type f | wc -l | grep -E '^[0-9]+$'

# Verify Schema Builder API usage across migrations
grep -r 'Schema::create\|Schema::table\|Schema::drop' database/migrations/ | wc -l

# Check migration status
php artisan migrate:status 2>&1 | grep -E 'Ran|Pending'

# Verify both up() and down() methods exist in migration files
ls database/migrations/*.php 2>/dev/null | head -5 | xargs grep -l 'function up()' | xargs grep -l 'function down()'
```

**Accept when:**
- All migration files exist in `database/migrations/` directory and follow Laravel naming convention with timestamps (YYYY_MM_DD_HHMMSS_description.php)
- Each migration file contains both `up()` and `down()` methods using Schema Builder API
- Migration status command executes successfully showing tracked migrations
- No direct SQL schema modifications are found in application code outside migration files
- Migrations include appropriate indexes, foreign key constraints, and default values as part of schema definition

<enforcement>
Claude Code MUST NOT skip or defer verification. All database schema changes MUST be implemented through Laravel migrations. Direct SQL schema modifications outside migration files are violations and must be flagged.
</enforcement>
