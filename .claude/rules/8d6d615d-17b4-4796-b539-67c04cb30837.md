<rule_activation id="8d6d615d-17b4-4796-b539-67c04cb30837" title="Adopt Eloquent ORM Models as Standard Data Access Layer: Each Model Correspond" applies_to="**/*">
These rules are ALWAYS ACTIVE for all database-backed entities in the application. All data access operations MUST use Eloquent ORM models as the primary abstraction layer.

**In scope:**
- All persistent domain entities stored in relational database tables
- CRUD operations for File, Account, ContactInformationType, GiftOccasion, CallReasonType, PostTemplateSection, QuickFact, and similar entities
- Relationship definitions between domain entities
- Data validation rules at the model layer
- Entity-specific business logic and computed properties

**Out of scope:**
- Complex analytical queries requiring raw SQL for performance optimization
- Data transfer objects (DTOs) used for API responses or inter-service communication
- Read-only views or materialized views without corresponding base tables
- Temporary or session-based data not persisted to the database
- Third-party API integrations where data is not stored locally

**Exceptions:**
- EXC-001: Performance-critical queries require raw SQL optimization that cannot be achieved through Eloquent query builder
- EXC-002: Legacy database schemas with complex naming conventions incompatible with Eloquent conventions
</rule_activation>

### Rules

- **R-ELOQUENT-001** MUST: Each model MUST correspond to a single database table with the table name following Laravel's naming conventions (plural, snake_case)
- **R-ELOQUENT-002** MUST: All model files MUST exist in app/Models namespace and extend Illuminate\Database\Eloquent\Model
- **R-ELOQUENT-003** MUST: All models MUST define either $fillable or $guarded properties for mass assignment protection
- **R-ELOQUENT-004** MUST: Direct DB facade calls (DB::select, DB::insert, DB::update, DB::delete) for CRUD operations MUST NOT be used in controllers or services except for approved exceptions tagged with 'raw query approved' comment
- **R-ELOQUENT-005** SHOULD: Use 'php artisan make:model' command to generate new models following Laravel conventions automatically
- **R-ELOQUENT-006** SHOULD: Document relationship methods with PHPDoc annotations specifying return types for better IDE support and static analysis
- **R-ELOQUENT-007** SHOULD: Use model events (creating, created, updating, updated) for cross-cutting concerns like logging and auditing rather than duplicating logic in controllers
- **R-ELOQUENT-008** SHOULD: Leverage Laravel's attribute casting ($casts property) to automatically convert database values to appropriate PHP types (dates, JSON, booleans)
- **R-ELOQUENT-009** SHOULD: Consider using model factories for testing to generate realistic test data without manual array construction
- **R-ELOQUENT-010** SHOULD: Implement query monitoring in development environment, enforce eager loading code reviews, and add automated tests detecting N+1 patterns to prevent performance degradation

### Verify

```bash
# Count models extending Model class
grep -r 'extends Model' app/Models/ | wc -l

# Find models missing proper namespace
find app/Models -type f -name '*.php' | xargs grep -L 'namespace App\\Models'

# Show all model table mappings
php artisan model:show --all | grep -E '(Table|Database)'

# Detect unapproved direct DB facade usage in application layer
grep -r 'DB::select\|DB::insert\|DB::update\|DB::delete' app/Http/Controllers/ app/Services/ | grep -v 'raw query approved'
```

**Accept when:**
- All model files exist in app/Models namespace and extend Illuminate\Database\Eloquent\Model
- No direct DB facade calls for CRUD operations found in controllers or services (excluding approved exceptions)
- Model count matches database table count for domain entities (excluding pivot tables and migrations table)
- All models define either $fillable or $guarded properties for mass assignment protection

<enforcement>
Claude Code MUST NOT skip or defer verification. Violations are enforced through:
- Automated CI pipeline checks using PHPStan or Psalm to detect direct DB facade usage in application layer
- Code review checklist requiring verification of model existence for new database tables
- Laravel Telescope monitoring in staging environment to identify raw SQL queries
- Monthly architecture review examining new models for compliance with naming and structure conventions
- CI pipeline fails if direct DB facade calls detected in controllers/services without exception documentation
- Pull requests blocked until models are created for new database tables

**Exception process:**
1. Developer documents performance requirement or technical constraint in code comments
2. Tech Lead reviews exception request with performance benchmarks or technical justification
3. Approved exceptions tagged with 'raw query approved' comment for CI exclusion
4. Exception registry maintained in architecture documentation with review date for reassessment
</enforcement>
