<rule_activation id="d6a96770-7969-44b9-accd-17e20f488207" title="Organize Domain Logic Using Domain-Driven Design Bounded Contexts: Domains Contain Additional" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Domain logic must be organized using Domain-Driven Design bounded contexts with clear separation between Web controllers, Services, and domain logic within domain-specific namespaces.
</rule_activation>

### Rules

- **R-DDD-001** MAY: Domains MAY contain additional subdirectories for domain-specific concerns such as Events, Repositories, or ValueObjects.
- **R-DDD-002** MUST: All new business logic and feature development must be organized within appropriate domain bounded contexts.
- **R-DDD-003** MUST: Service classes must encapsulate business operations and be located in Services subdirectories within their respective domains.
- **R-DDD-004** MUST: Web controllers must be located in Web/Controllers subdirectories within their respective domains.
- **R-DDD-005** MUST: Controllers must be thin adapters that validate input, call the appropriate service, and format the response.
- **R-DDD-006** SHOULD: Use dependency injection to provide services with their dependencies rather than instantiating them directly.
- **R-DDD-007** SHOULD: Consider using domain events to communicate between bounded contexts rather than direct service-to-service calls.
- **R-DDD-008** SHOULD: Service classes should follow a command pattern with a single public execute() or handle() method that encapsulates the business operation.
- **R-DDD-009** MUST NOT: Infrastructure concerns such as database connections, caching, or logging should not be placed within domain logic.
- **R-DDD-010** MUST NOT: Shared utility functions with no domain-specific logic should not be placed within domain boundaries.

### Verify

```bash
# Verify all controllers are in Web/Controllers subdirectories
find app/Domains -type f -name '*Controller.php' | xargs grep -L 'namespace.*\\Web\\Controllers' | wc -l | grep -q '^0$'

# Count service classes in Services subdirectories
find app/Domains -type f -name '*Service.php' -path '*/Services/*' | wc -l

# Verify no controllers exist outside Web/Controllers namespaces
grep -r 'class.*Controller' app/Domains --include='*.php' | grep -v 'namespace.*\\Web\\Controllers' | wc -l | grep -q '^0$'
```

**Accept when:**
- All controllers are located in Web/Controllers subdirectories within their respective domains
- Service classes are located in Services subdirectories and contain business logic separate from HTTP concerns
- New features added to the codebase follow the domain structure pattern with at least 95% compliance
- Code review checklist includes verification of proper domain organization
- Domain boundaries are clearly defined and documented
- Cross-domain communication uses domain events or dependency inversion rather than direct coupling

<enforcement>
Claude Code MUST verify domain organization compliance before accepting code changes. Violations must be resolved through refactoring or documented exceptions before merge. Automated static analysis and code review processes are mandatory.
</enforcement>
