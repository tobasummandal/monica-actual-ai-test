<rule_activation id="49fd204f-153c-4534-a56d-10b74d0b99cb" title="Adopt Domain-Driven DAV/CardDAV Integration Pattern for External Contact Synchronization: Data Transfer Between" applies_to="**/*">
These rules are ACTIVE for all external API integrations involving contact synchronization via DAV/CardDAV protocols within domain-bounded contexts.
</rule_activation>

### Rules

- **R-DAV-001** MUST: Data transfer between external DAV systems and internal domains MUST use dedicated DTO objects (ContactDto, ContactDeleteDto) to enforce boundary isolation.

### Verify

```bash
# Verify DTO classes exist in Contact domain DavClient services
grep -r "class.*Dto" app/Domains/Contact/DavClient/Services/Utils/Model/ | wc -l

# Verify IDAVBackend interface is defined
grep -r "interface.*Backend" app/Domains/Contact/Dav/Web/Backend/ | grep -c "IDAVBackend"

# Verify DavServerNotCompliantException exists
grep -r "DavServerNotCompliantException" app/Domains/Contact/DavClient/Services/Utils/Dav/ | wc -l

# Verify separate resource classes for import operations
find app/Domains/Contact/Dav -name "*Resource.php" -type f | wc -l
```

**Accept when:**
- At least 2 DTO classes exist in Contact domain DavClient services for data transfer
- IDAVBackend interface is defined and implemented by at least one concrete backend class
- DavServerNotCompliantException exists and is used in DAV client error handling
- Separate resource classes exist for import operations (ImportResource, ImportVCardResource)

<enforcement>
Claude Code MUST NOT skip or defer verification. All verify commands MUST pass before accepting changes to external DAV/CardDAV integrations. Code review MUST block merge if DTOs are not used for external data transfer. CI pipeline MUST fail if external DAV calls are detected outside designated service layers.
</enforcement>
