<rule_activation id="e8db1dff-0699-4788-9314-f5b96fea88a7" title="Adopt Modular Architecture with Factory-Based Component Generation: Domain Modules Organized" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in the application. Domain modules must follow a consistent modular architecture with factory-based component generation organized under a clear namespace hierarchy.
</rule_activation>

### Rules

- **R-MOD-001** MUST: All domain modules MUST be organized under a clear namespace hierarchy following the pattern `app/Domains/{Domain}/{Subdomain}/{Layer}`
- **R-MOD-002** MUST: All PHP files in `app/Domains` directory MUST use the correct `App\Domains` namespace hierarchy
- **R-MOD-003** MUST: All factory classes in `database/factories` MUST extend the framework's base `Factory` class
- **R-MOD-004** MUST: All setup commands in `app/Console/Commands` MUST extend the framework's `Command` class and follow naming conventions (Setup*.php)
- **R-MOD-005** SHOULD: Domain names SHOULD be singular nouns (Contact, not Contacts)
- **R-MOD-006** SHOULD: Subdomain names SHOULD describe the capability (ManageContact)
- **R-MOD-007** SHOULD: Layer names SHOULD be standard (Web, Console, Database)
- **R-MOD-008** SHOULD: Factory classes SHOULD be updated when domain models evolve to maintain test data validity
- **R-MOD-009** MAY: Simplified module structure MAY be used for simple CRUD modules with documented justification

### Verify

```bash
# Verify all PHP files in app/Domains use correct namespace
find app/Domains -type f -name '*.php' | xargs grep -L 'namespace App\\Domains' | wc -l | grep -q '^0$'

# Verify all factory classes extend base Factory class
find database/factories -type f -name '*Factory.php' | xargs grep -c 'extends Factory' | grep -v ':0'

# Verify all setup commands extend Command class
find app/Console/Commands -type f -name 'Setup*.php' | xargs grep -c 'extends Command' | grep -v ':0'
```

**Accept when:**
- All PHP files in `app/Domains` directory use the correct `App\Domains` namespace hierarchy
- All factory classes in `database/factories` extend the framework's base `Factory` class
- All setup commands in `app/Console/Commands` extend the framework's `Command` class and follow naming conventions
- Module structure includes factory classes for test data generation when needed
- Setup commands are present for modules requiring initialization
- View helpers are placed in the Web layer
- No namespace violations are detected by PHPStan or Psalm
