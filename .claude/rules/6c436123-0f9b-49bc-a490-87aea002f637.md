These rules are ALWAYS ACTIVE for all PHP files, with focus on controller and service layer implementations.

**Status:** Active
**Date:** 2024-01-09

## Context

Controllers serve as primary entry points for user requests and must validate permissions before executing business logic. Authorization enforcement at controller and service boundaries provides defense-in-depth, ensuring authorization checks occur even if one layer is bypassed.

## Scope

**In scope:**
- All HTTP controller methods in web and API layers
- Service layer methods that perform privileged operations or access sensitive data
- Domain service classes that can be invoked from multiple contexts
- RESTful API endpoints and GraphQL resolvers

**Out of scope:**
- Internal helper methods only called after authorization verification
- Read-only public data endpoints not requiring authentication
- System-level background jobs with elevated privileges
- Database query builders and repository methods

**Exceptions:**
- EXC-001: Public API endpoints for unauthenticated access (health checks, public documentation)
- EXC-002: Administrative CLI commands running with system-level privileges outside web request cycle
</rule_activation>

### Rules

- **R-AUTH-001** MUST: Authorization enforcement points MUST be implemented at the earliest possible boundary (controller entry point or service layer) to fail fast on unauthorized requests.

- **R-AUTH-002** MUST: All controller methods that access or modify resources MUST include explicit authorization checks before business logic execution.

- **R-AUTH-003** MUST: Service layer methods performing privileged operations or accessing sensitive data MUST enforce authorization checks.

- **R-AUTH-004** SHOULD: Use Laravel's built-in authorization features (policies and gates) to standardize authorization checks across controllers.

- **R-AUTH-005** SHOULD: Document authorization requirements in controller method docblocks to make security expectations explicit.

- **R-AUTH-006** SHOULD: Implement request-scoped caching for authorization decisions to minimize performance impact of multiple checks.

### Implementation Guidance

- Create base controller classes that enforce authorization check patterns
- Provide helper methods for common authorization scenarios
- Use aspect-oriented programming or decorators for declarative authorization checks
- Create shared authorization service abstractions and reusable policy classes

### Verify

```bash
# Find controller methods without authorization checks
grep -r "public function" app/Domains/*/Web/Controllers/ | grep -v "authorize\|policy\|gate" | head -20

# Find controllers missing authorization patterns
find app/Domains -name "*Controller.php" -exec grep -L "authorize\|policy\|can(" {} \;

# Run static analysis on controllers
phpstan analyse --level=5 app/Domains/*/Web/Controllers/ --error-format=table
```

**Accept when:**
- All controller methods that access or modify resources include explicit authorization checks before business logic execution
- Static analysis tools report zero violations of authorization enforcement patterns in controller classes
- Code review checklist includes verification of authorization checks for all new controller methods

<enforcement>
Claude Code MUST NOT skip or defer authorization verification. All controller and service layer changes MUST be verified for proper authorization enforcement before completion.

**Verification method:**
- Automated static analysis in CI pipeline scanning for controller methods without authorization checks
- Security-focused code review requiring explicit authorization verification
- Periodic security audits examining authorization enforcement patterns

**Violation handling:**
- CI pipeline fails if static analysis detects missing authorization checks
- Code review blocks merge requests lacking proper authorization
- Security team conducts remediation review for production violations

**Exception process:**
- Submit exception request with justification to security team
- Security team reviews risk and requires alternative controls if needed
- Document approved exceptions in code with inline comments referencing approval ticket
- Maintain exception registry with periodic review
</enforcement>
