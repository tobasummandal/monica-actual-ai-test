<rule_activation id="e5e7767c-690b-4fe2-bebc-1e1d8bb7f6b5" title="Standardize Logging with Laravel Log Facade in DAV and Job Components: Background Jobs Handling" applies_to="app/Domains/Contact/Dav* app/Console/Commands/*">
These rules are ALWAYS ACTIVE for all DAV backend implementations, background jobs in Contact/Dav and Contact/DavClient domains, DavClient service utilities, synchronization services, and console commands for address book and application setup.
</rule_activation>

### Rules

- **R-DAV-001** MUST: Background jobs handling VCard/VCalendar operations MUST log job start, completion, and failure events with contextual data including resource identifiers.
- **R-DAV-002** MUST: Import the Log facade at the top of each class: `use Illuminate\Support\Facades\Log;`
- **R-DAV-003** MUST: Use appropriate log levels: `Log::debug()` for detailed tracing, `Log::info()` for significant events, `Log::warning()` for recoverable issues, `Log::error()` for failures requiring attention.
- **R-DAV-004** MUST: Include structured context as second parameter: `Log::info('VCard synchronized', ['contact_id' => $id, 'addressbook_id' => $addressbookId])`
- **R-DAV-005** SHOULD: For DAV operations, consider using a dedicated channel configured in config/logging.php: `Log::channel('dav')->info('Sync started')`
- **R-DAV-006** SHOULD: In job classes, log at the beginning and end of handle() method with job-specific context to enable job execution tracking.
- **R-DAV-007** SHOULD: Avoid logging in tight loops - consider sampling or aggregating log messages for bulk operations.

### Verify

```bash
# Verify Log facade imports in DAV and console command files
grep -r "use Illuminate\\Support\\Facades\\Log" app/Domains/Contact/Dav* app/Console/Commands/ | wc -l

# Verify Log method calls with appropriate levels
grep -r "Log::" app/Domains/Contact/Dav* app/Console/Commands/ | grep -E "(debug|info|warning|error)" | wc -l

# Verify Laravel Log facade class availability
php artisan tinker --execute="echo class_exists('Illuminate\\Support\\Facades\\Log') ? 'PASS' : 'FAIL';"
```

**Accept when:**
- Log facade import statements are present in all DAV backend classes, DavClient services, and relevant console commands
- Log method calls (debug/info/warning/error) are present in job handle() methods and synchronization service methods
- Laravel's Log facade class is available and properly configured in the application
- All background jobs handling VCard/VCalendar operations include logging at job start, completion, and failure with contextual data
- Structured context data includes resource identifiers (contact_id, addressbook_id, etc.)

<enforcement>
Clause Code MUST NOT skip or defer verification. All DAV and job components MUST comply with R-DAV-001 through R-DAV-007. Violations are caught via code review checklist, static analysis with PHPStan/Psalm rules, and automated CI pipeline grep-based verification. Failed checks block PR merge.
</enforcement>
