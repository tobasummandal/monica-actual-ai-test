These rules are ALWAYS ACTIVE for all controller files in domain-driven directories matching `**/app/Domains/**/Web/Controllers/**/*.php`.

### Rules

- **R-DDCO-001** SHOULD: Related controllers handling sub-resources SHOULD use composite naming that reflects the parent-child relationship (e.g., PostMetricController, PostSliceOfLifeController).

### Context

- Controllers are organized within domain boundaries under `app/Domains/{Domain}/{Context}/Web/Controllers`
- Journal management demonstrates this pattern with specialized controllers for journals, posts, photos, metrics, and slices of life
- This organization separates concerns by entity and maintains single responsibility principle
- In scope: All web controllers within domain boundaries, controllers for journal/post/photo/metric/slice of life entities, API and web interface controllers
- Out of scope: Service classes, DTOs, repositories, console commands, background jobs

### Exceptions

- **EX-001**: A controller handles cross-domain concerns that cannot be reasonably placed within a single domain boundary
- **EX-002**: Legacy controllers exist outside this structure and refactoring would introduce significant risk

### Verify

```bash
# Verify controllers are in correct domain structure
find app/Domains/Vault/ManageJournals/Web/Controllers -name '*Controller.php' | wc -l

# Check namespace consistency
grep -r 'namespace App\\Domains\\Vault\\ManageJournals\\Web\\Controllers' app/Domains/Vault/ManageJournals/Web/Controllers/*.php | wc -l

# Verify route registration
php artisan route:list --path=journal --columns=Action | grep 'App\\Domains\\Vault\\ManageJournals\\Web\\Controllers'
```

**Accept when:**
- All controller files in the ManageJournals domain are located under `app/Domains/Vault/ManageJournals/Web/Controllers`
- Each controller has a single, clear responsibility corresponding to an entity or entity-concern combination
- Controller namespaces match their directory structure and follow the established pattern
- Route definitions correctly reference controllers using the domain-based namespace

### Implementation Notes

- Create base controller class at `app/Domains/Vault/ManageJournals/Web/Controllers/Controller.php` for shared functionality
- Use Laravel route grouping: `Route::group(['namespace' => 'App\\Domains\\Vault\\ManageJournals\\Web\\Controllers'], ...)`
- Use PHP traits for cross-cutting concerns (authorization, validation, response formatting)
- Document controller organization pattern in architecture documentation
