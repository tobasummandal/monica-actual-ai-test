<rule_activation id="e91301f7-fcbc-4ffc-8527-1ad9bb6d6235" title="Adopt Laravel Migrations as Standard Database Schema Management: Migration Files Use" applies_to="database/migrations/**/*.php">
These rules are ALWAYS ACTIVE for all database schema changes across the application. All schema modifications MUST be implemented through Laravel migration files.
</rule_activation>

### Rules

- **R-LMIG-001** MUST: Migration files MUST use Laravel's Schema Builder API (Schema::create, Schema::table, etc.) rather than raw SQL for database-agnostic operations.
- **R-LMIG-002** MUST: All table creation, modification, and deletion operations MUST be implemented through migrations.
- **R-LMIG-003** MUST: Column additions, modifications, and removals MUST be implemented through migrations.
- **R-LMIG-004** MUST: Index creation and removal MUST be implemented through migrations.
- **R-LMIG-005** MUST: Foreign key constraint definitions MUST be implemented through migrations.
- **R-LMIG-006** MUST: Each migration file MUST contain both up() and down() methods.
- **R-LMIG-007** MUST: Migration files MUST follow Laravel's timestamp-based naming convention (YYYY_MM_DD_HHMMSS_description.php).
- **R-LMIG-008** SHOULD: Use 'php artisan make:migration' command to generate new migration files with proper timestamp and structure.
- **R-LMIG-009** SHOULD: Always test migrations locally with both 'migrate' and 'migrate:rollback' commands before committing.
- **R-LMIG-010** SHOULD: For complex data transformations, separate schema changes from data migrations into distinct migration files.
- **R-LMIG-011** SHOULD: Use Laravel's migration methods like 'foreignId()', 'timestamps()', 'softDeletes()' for consistency with framework conventions.
- **R-LMIG-012** SHOULD: Document any database-specific SQL used in migrations with comments explaining compatibility implications.

### Verify

```bash
# Count migration files in standard location
find database/migrations -name '*.php' -type f | wc -l | grep -E '^[0-9]+$'

# Verify Schema Builder API usage
grep -r 'Schema::create\|Schema::table\|Schema::drop' database/migrations/ | wc -l

# Check migration status
php artisan migrate:status 2>&1 | grep -E 'Ran|Pending'

# Verify both up() and down() methods exist
ls database/migrations/*.php 2>/dev/null | head -5 | xargs grep -l 'function up()' | xargs grep -l 'function down()'
```

**Accept when:**
- All migration files exist in database/migrations directory and follow Laravel naming convention with timestamps
- Each migration file contains both up() and down() methods using Schema Builder API
- Migration status command executes successfully showing tracked migrations
- No direct SQL schema modifications are found in application code outside migration files
- All schema changes are implemented through migrations, not raw SQL scripts
