<rule_activation id="bec188a2-d96a-4b97-b5a1-e6dc13f4a3ad" title="Standardize Password Hashing for Authentication Operations: Test Suites Verify" applies_to="**/*">
These rules are ALWAYS ACTIVE for all authentication-related files dealing with password operations including account creation, password resets, password updates, invitation acceptance flows, Fortify action handlers, and domain service classes.
</rule_activation>

### Rules

- **R-AUTH-001** MUST: All password assignment operations in authentication code paths MUST use `Hash::make()` or `bcrypt()` helper before storing passwords.
  - In scope: Account creation workflows, password reset operations, password update operations, invitation acceptance flows, Fortify action handlers (ResetUserPassword, UpdateUserPassword), domain service classes (CreateAccount, AcceptInvitation)
  - Out of scope: API token generation, OAuth flows, session management, 2FA tokens, password reset token generation
  - Implementation: Use `Hash::make($password)` in Fortify action classes before `$user->forceFill(['password' => ...])->save()`; apply hashing in domain service classes before user model creation or password updates

- **R-AUTH-002** SHOULD: Test suites SHOULD verify password hashing behavior in authentication feature tests.
  - Feature tests should use `Hash::check($plainPassword, $user->password)` to verify hashing occurred correctly
  - Tests should cover: UpdatePasswordTest, ResetPasswordTest, account creation, invitation acceptance

### Verify

```bash
# Check for unhashed password assignments
grep -r "'password'\s*=>\s*\$" app/ --include='*.php' | grep -v 'Hash::make' | grep -v 'bcrypt(' | grep -v '// ' || echo 'No unhashed password assignments found'

# Count password hashing usage in authentication code
grep -r "Hash::make\|bcrypt(" app/Actions/Fortify/ app/Domains/Settings/ --include='*.php' | wc -l

# Verify password-related tests exist and run
php artisan test --filter=Password --coverage-text | grep -E '(UpdatePasswordTest|ResetPasswordTest)'
```

**Accept when:**
- All password assignment operations in authentication code paths use `Hash::make()` or `bcrypt()` helper
- Feature tests verify that stored passwords are hashed (`Hash::check` returns true for original password)
- Code review checklist includes verification of password hashing for any authentication-related changes
- No unhashed password assignments detected by grep verification commands

<enforcement>
Claude Code MUST verify password hashing patterns when working with authentication code. CI pipeline fails if grep patterns detect potential unhashed password assignments. No exceptions permitted for production authentication code; password hashing is a non-negotiable security requirement. Test fixtures and seeding may use simplified hashing with documented security warnings only with security team approval.
</enforcement>
