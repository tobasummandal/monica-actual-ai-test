<rule_activation id="c55d7160-bcb3-4435-b28e-dc312f0cccc8" title="Use Laravel Hash Facade for Password Credential Storage: Applications Implement Automatic" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in Laravel applications handling user authentication and password management.
</rule_activation>

### Rules

- **R-HASH-001** MUST: Use `Hash::make($password)` when storing passwords in all user account creation workflows, password reset flows, password update operations, and user invitation acceptance with password setting.
- **R-HASH-002** MUST: Use `Hash::check($plaintext, $hashedValue)` for password verification during authentication operations.
- **R-HASH-003** MUST: Never use direct `password_hash()` calls in application code; use Laravel Hash facade exclusively.
- **R-HASH-004** MUST: Never store plain-text passwords in the database or assign passwords without hashing.
- **R-HASH-005** SHOULD: Use `Hash::fake()` in test environments to avoid expensive hashing operations and speed up test execution.
- **R-HASH-006** SHOULD: Review `config/hashing.php` to ensure appropriate algorithm (bcrypt or argon2id) and work factor for security requirements.
- **R-HASH-007** MAY: Implement automatic password rehashing on login if the configured algorithm or work factor changes.

### Verify

```bash
# Verify Hash::make usage in password-related code
grep -r "Hash::make" app/ --include="*.php" | wc -l

# Verify no direct password_hash usage found
grep -r "password_hash" app/ --include="*.php" || echo "No direct password_hash usage found (good)"

# Verify no plain-text password assignments
grep -r "'password'.*=>.*\$" app/ --include="*.php" | grep -v "Hash::make" | grep -v "bcrypt" || echo "No plain-text password assignments found (good)"

# Verify hashing driver configuration
php artisan tinker --execute="echo config('hashing.driver');"
```

**Accept when:**
- All password storage operations use `Hash::make()` as verified by grep showing consistent usage across authentication files
- No direct `password_hash()` calls found in application code (framework usage only)
- Hash facade configuration is properly set in `config/hashing.php` with bcrypt or argon2id driver
- Test suite includes verification that passwords are hashed before database storage
- No plain-text password assignments detected in authentication-related code

Claude Code MUST NOT skip or defer verification. All password-related code changes MUST pass the verify commands above. CI pipeline MUST fail if plain-text password storage patterns are detected. Pull requests MUST be blocked until Hash facade usage is corrected.
</enforcement>
