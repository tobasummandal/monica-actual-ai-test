<rule_activation id="38d91987-5e27-47b8-8c41-f87de9584b4c" title="Standardize Public API Contract Design with Interface-Based DTOs and Exception Handling: Data Crossing Public" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase that interact with public API boundaries, including REST API endpoints, WebDAV/CardDAV integration interfaces, DTOs, custom exceptions, and ViewHelper classes.
</rule_activation>

### Rules

- **R-API-001** MUST: Data crossing public API boundaries MUST be encapsulated in dedicated Data Transfer Objects (DTOs) with clearly defined properties and validation rules.
- **R-API-002** MUST: Public API interfaces MUST use interface-based contracts (e.g., IDAVBackend) to enable dependency inversion and provide clear API boundaries.
- **R-API-003** MUST: Public API error conditions MUST throw domain-specific custom exceptions (e.g., NotEnoughPermissionException, MaximumNumberOfUsersInVaultException) rather than generic exception types.
- **R-API-004** MUST: DTOs MUST be suffixed with 'Dto', interfaces MUST be prefixed with 'I', and exceptions MUST be suffixed with 'Exception'.
- **R-API-005** MUST: All interface methods MUST use PHP type hints and return type declarations to enforce contract compliance at runtime.
- **R-API-006** MUST: All public interfaces and DTOs MUST be documented with PHPDoc annotations including @api tag to clearly mark public contracts.
- **R-API-007** MUST: Domain models MUST NOT be exposed directly through public APIs without a DTO layer.

### In Scope

- All REST API endpoints exposed to external consumers
- WebDAV/CardDAV integration interfaces and backends
- Data transfer objects used in API request/response payloads
- Custom exception classes thrown by public API methods
- ViewHelper classes that prepare data for API responses
- Service layer interfaces that define public contracts

### Out of Scope

- Internal domain models and entities not exposed via APIs
- Private service methods used only within domain boundaries
- Database repositories and data access layers
- Internal event handlers and message queue consumers
- Administrative CLI commands and internal tools

### Exceptions

- **EXC-001**: Legacy API endpoints that predate this ADR and have established external consumers
- **EXC-002**: Prototype or experimental APIs explicitly marked as unstable/alpha

### Verify

```bash
# Count DTO classes in domains
grep -r "class.*Dto" app/Domains --include="*.php" | wc -l

# Count interface definitions
grep -r "interface I[A-Z]" app/Domains --include="*.php" | wc -l

# Count custom exception classes
grep -r "class.*Exception extends" app/Exceptions --include="*.php" | wc -l

# Count ViewHelper files
find app/Domains -name "*ViewHelper.php" -type f | wc -l
```

**Accept when:**
- All public API endpoints have corresponding interface definitions with explicit method signatures
- All API request/response payloads use dedicated DTO classes rather than exposing domain models
- All public API error conditions throw domain-specific exceptions with clear messages
- Grep commands show consistent presence of DTOs, interfaces, custom exceptions, and ViewHelpers across API-related code
- No direct domain model exposure detected in API controllers by static analysis

<enforcement>
Claude Code MUST NOT skip or defer verification. CI pipeline tests MUST validate DTO serialization/deserialization contracts. Code review MUST block merges if DTOs are not used for API boundaries or if public API methods lack interface definitions. Static analysis warnings for direct domain model exposure MUST be escalated to errors.
</enforcement>
