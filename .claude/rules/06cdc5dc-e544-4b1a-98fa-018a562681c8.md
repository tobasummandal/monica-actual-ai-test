<rule_activation id="06cdc5dc-e544-4b1a-98fa-018a562681c8" title="Standardize Eloquent Models as Primary Data Access Layer with Public API Contracts: Models Define Relationships" applies_to="**/*">
These rules are ALWAYS ACTIVE for all data modeling and database access patterns within the application codebase.
</rule_activation>

### Rules

- **R-ELOQUENT-001** SHOULD: Models SHOULD define relationships using Eloquent relationship methods (hasMany, belongsTo, etc.) rather than manual joins
- **R-ELOQUENT-002** MUST: All model classes MUST extend Illuminate\Database\Eloquent\Model
- **R-ELOQUENT-003** MUST: Raw SQL queries (DB::raw, DB::select, DB::statement) outside models MUST include documented justification
- **R-ELOQUENT-004** SHOULD: Models SHOULD use the $casts property to ensure consistent type handling for attributes (dates, booleans, JSON)
- **R-ELOQUENT-005** SHOULD: Public methods, relationships, and custom attributes SHOULD be documented in PHPDoc blocks to establish clear API contracts
- **R-ELOQUENT-006** SHOULD: Query scopes SHOULD be used to encapsulate common filtering patterns and improve query readability
- **R-ELOQUENT-007** SHOULD: Laravel model factories SHOULD be used for test data generation
- **R-ELOQUENT-008** SHOULD: Model events (creating, updating, etc.) SHOULD be used for cross-cutting concerns like auditing

### Scope

**In scope:**
- All persistent domain entities requiring database storage
- Data access operations for CRUD functionality
- Relationship definitions between domain entities
- Data validation and transformation at the model layer
- Query building and data retrieval patterns

**Out of scope:**
- Temporary data structures not persisted to database
- View models or DTOs used solely for presentation
- External API response objects
- Performance-critical bulk operations requiring raw SQL
- Database migrations and schema definitions

### Exceptions

- **EXC-001**: Performance profiling demonstrates that Eloquent overhead causes unacceptable latency (>100ms) for high-frequency queries
- **EXC-002**: Complex analytical queries requiring database-specific features not supported by Eloquent query builder

**Exception process:**
1. Developer documents performance issue or technical constraint in ticket
2. Technical lead reviews justification and approves exception
3. Exception is documented in code comments with ticket reference
4. Exception is logged in architecture decision log for future review

### Verify

```bash
# Count model classes extending Model
grep -r "class.*extends.*Model" app/Models/ | wc -l

# Check for syntax errors in model files
find app/Models -name '*.php' -exec php -l {} \; | grep -v 'No syntax errors'

# Count raw database queries outside models (should be minimal)
grep -r "DB::raw\|DB::select\|DB::statement" app/ --exclude-dir=Models | wc -l
```

**Accept when:**
- All model classes in app/Models extend Illuminate\Database\Eloquent\Model
- No syntax errors in model files and all models are loadable by PHP parser
- Raw database queries outside models are documented with justification or count is below threshold (e.g., <5 instances)

### Risks & Mitigations

**Risk**: N+1 query problems causing performance degradation as data volume grows
- **Mitigation**: Implement query monitoring, use Laravel Debugbar in development, enforce eager loading in code reviews, add automated tests for query counts

**Risk**: Model classes becoming bloated with business logic violating single responsibility principle
- **Mitigation**: Models handle data access and simple transformations; complex business logic belongs in service classes or domain objects

**Risk**: Breaking changes to model public API contracts affecting dependent code
- **Mitigation**: Treat model public methods as API contracts, use deprecation notices before removal, maintain comprehensive test coverage
