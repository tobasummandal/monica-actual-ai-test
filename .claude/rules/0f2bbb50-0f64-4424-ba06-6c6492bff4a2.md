<rule_activation id="0f2bbb50-0f64-4424-ba06-6c6492bff4a2" title="Enforce Public API Contract Testing in CI/CD Pipeline: Public Contract Tests" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files. Public API contract tests MUST be executed as part of the CI/CD pipeline before any code can be merged to main branches.
</rule_activation>

### Rules

- **R-API-001** MUST: Public API contract tests MUST be executed as part of the CI/CD pipeline before any code can be merged to main branches.
- **R-API-002** MUST: All public API endpoints exposed to external consumers or other services MUST have contract tests.
- **R-API-003** MUST: Service layer contracts that form domain boundaries MUST have contract tests.
- **R-API-004** MUST: API controllers handling HTTP requests and responses MUST have contract tests.
- **R-API-005** MUST: ViewHelper contracts that provide data transformation for presentation layers MUST have contract tests.
- **R-API-006** MUST: Any interface or contract marked as @api or explicitly documented as public MUST have contract tests.
- **R-API-007** MUST: Public API endpoints MUST have at least 80% code coverage with contract tests.
- **R-API-008** MUST: CI/CD pipeline MUST include a dedicated stage for contract tests that must pass before merge approval.
- **R-API-009** MUST: Code review checklist MUST include verification that new or modified public APIs have corresponding contract tests.
- **R-API-010** SHOULD: Contract test execution SHOULD complete within acceptable time limits (e.g., under 5 minutes for the full suite).
- **R-API-011** SHOULD: Contract tests SHOULD follow naming conventions (e.g., *ControllerTest.php for API controllers, *ServiceTest.php for service contracts).

### In Scope

- All public API endpoints exposed to external consumers or other services
- Service layer contracts that form domain boundaries
- API controllers handling HTTP requests and responses
- ViewHelper contracts that provide data transformation for presentation layers
- Any interface or contract marked as @api or explicitly documented as public

### Out of Scope

- Internal private methods not exposed outside their containing class
- Implementation details that do not affect external contracts
- Database schema changes that do not impact API response structures
- UI-only changes that do not modify underlying API contracts
- Experimental or feature-flagged APIs not yet released to production

### Exceptions

- **EXC-001**: Emergency hotfixes addressing critical production incidents where contract changes are unavoidable
- **EXC-002**: Deprecated APIs scheduled for removal where breaking changes are intentional and communicated

### Verify

```bash
# Count contract test files
find tests/Unit -name '*ControllerTest.php' -o -name '*ServiceTest.php' -o -name '*ViewHelperTest.php' | wc -l

# Count test methods in Settings domain
grep -r 'public function test' tests/Unit/Domains/Settings/ | wc -l

# Check code coverage for API Controllers
phpunit --testsuite=unit --coverage-text --coverage-filter='app/Domains/*/Api/Controllers' | grep 'Lines:' | awk '{print $2}'
```

**Accept when:**

- All public API endpoints in the Settings domain have corresponding unit tests with at least 80% code coverage
- CI/CD pipeline includes a dedicated stage for contract tests that must pass before merge approval
- Contract test execution completes within acceptable time limits (e.g., under 5 minutes for the full suite)
- Code review checklist includes verification that new or modified public APIs have corresponding contract tests

<enforcement>
Claude Code MUST NOT skip or defer verification. Contract tests are mandatory for all public API changes before merge. Automated CI/CD pipeline execution on every pull request and commit to protected branches MUST verify contract test presence and coverage thresholds.
</enforcement>
