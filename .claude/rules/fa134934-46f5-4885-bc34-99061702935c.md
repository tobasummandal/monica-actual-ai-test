These rules are ALWAYS ACTIVE for all authentication and user management implementations. All new user registration, profile updates, and authentication flows MUST follow the patterns defined herein.
</rule_activation>

### Rules

- **R-FORTIFY-001** MUST_NOT: Authentication logic MUST NOT be duplicated outside of Fortify Actions.

### Verify

```bash
# Verify Fortify usage across codebase
grep -r "use Laravel\\Fortify" app/Actions/ app/Providers/ | wc -l

# Verify validation logic in Fortify Actions
grep -r "Validator::make\|validate(" app/Actions/Fortify/ | wc -l

# Verify FortifyServiceProvider exists
test -f app/Providers/FortifyServiceProvider.php && echo 'FortifyServiceProvider exists' || echo 'MISSING'

# Verify Fortify routes are registered
php artisan route:list | grep -E '(login|register|password)' | grep -c fortify
```

**Accept when:**
- All authentication-related Actions use Laravel Fortify imports and are registered in FortifyServiceProvider
- Each Fortify Action contains explicit validation logic using Laravel's validation mechanisms
- Fortify routes are registered and accessible in the application routing table
- No duplicate authentication logic exists outside of Fortify Actions
- User registration and account creation flows use Fortify Actions
- User profile information updates use Fortify Actions
- Password reset and recovery flows use Fortify Actions
- Email verification processes use Fortify Actions
- Two-factor authentication setup uses Fortify Actions
- All user input validation in authentication contexts is centralized in Fortify Actions

<enforcement>
Claude Code MUST NOT skip or defer verification. All authentication implementations MUST be verified against these rules before acceptance. Violations must be remediated before deployment to production.
</enforcement>
