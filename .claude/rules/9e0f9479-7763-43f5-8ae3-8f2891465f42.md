<rule_activation id="9e0f9479-7763-43f5-8ae3-8f2891465f42" title="Organize Test Files by Domain and Feature Modules: Domain Boundaries Enforced" applies_to="tests/Unit/Domains/**/*">
These rules are ALWAYS ACTIVE for all test files under tests/Unit/Domains/ to enforce domain-driven test organization and enable selective CI/CD test execution.
</rule_activation>

### Rules

- **R-DOM-001** SHOULD: Domain boundaries SHOULD be enforced in CI/CD pipelines to enable selective test execution by domain or feature module.
- **R-DOM-002** MUST: Test files under tests/Unit/Domains/ MUST mirror the production code structure from app/Domains/ or src/Domains/.
- **R-DOM-003** MUST: Test file names MUST append 'Test' suffix to production class names (e.g., SettingsTest.php for Settings.php).
- **R-DOM-004** MUST: Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) MUST be represented as subdirectories within their respective domains.
- **R-DOM-005** SHOULD: Test file paths SHOULD mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix.
- **R-DOM-006** MAY: Shared test utilities or base test classes that serve multiple domains MAY be exempted from strict domain boundaries (EXC-001).
- **R-DOM-007** MAY: Legacy test files being refactored into domain structure MAY be exempted during migration period (EXC-002).

### Verify

```bash
# Verify test files exist under tests/Unit/Domains/ with correct structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify test namespace conventions
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are represented as subdirectories
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- CI/CD pipeline checks verify test file locations match production code structure
- Code review checklist confirms new tests follow domain organization pattern
- Automated linting rules validate test file naming and location conventions
- Pre-commit hooks verify test files are placed in correct domain directories

Claude Code MUST NOT skip or defer verification of test file organization against domain boundaries. All new test files MUST be placed in the correct tests/Unit/Domains/ subdirectory matching their production code location. Violations MUST be flagged during code review and CI pipeline execution.
