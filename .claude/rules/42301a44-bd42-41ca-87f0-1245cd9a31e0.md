<rule_activation id="42301a44-bd42-41ca-87f0-1245cd9a31e0" title="Enforce Authorization Checks at Controller Entry Points: Services That Can" applies_to="**/*Controller.php">
These rules are ALWAYS ACTIVE for all controller implementations and service layer authorization enforcement points within the application codebase.
</rule_activation>

### Rules

- **R-AUTH-001** SHOULD: Services that can be invoked from multiple entry points SHOULD implement their own authorization checks to ensure defense-in-depth.

### Verify

```bash
# Detect controller methods without authorization checks
grep -r "public function" app/Domains/*/Web/Controllers/ | grep -v "authorize\|policy\|gate" | head -20

# Find all controller files lacking authorization patterns
find app/Domains -name "*Controller.php" -exec grep -L "authorize\|policy\|can(" {} \;

# Static analysis for authorization enforcement patterns
phpstan analyse --level=5 app/Domains/*/Web/Controllers/ --error-format=table
```

**Accept when:**
- All controller methods that access or modify resources include explicit authorization checks before business logic execution
- Static analysis tools report zero violations of authorization enforcement patterns in controller classes
- Code review checklist includes verification of authorization checks for all new controller methods
- Services invoked from multiple entry points implement their own authorization checks

<enforcement>
Claude Code MUST NOT skip or defer verification of authorization checks in controller entry points and multi-context services. Violations block CI pipeline and code review merge requests.
</enforcement>
