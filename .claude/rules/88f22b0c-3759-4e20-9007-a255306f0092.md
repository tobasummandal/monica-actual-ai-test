<rule_activation id="88f22b0c-3759-4e20-9007-a255306f0092" title="Use Laravel Hash Facade for Password Credential Storage: Hash Facade Configuration" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*` in Laravel authentication workflows.
</rule_activation>

### Rules

- **R-HASH-001** SHOULD: The Hash facade configuration SHOULD use bcrypt or argon2id algorithms with framework-recommended work factors.

### Verify

```bash
# Verify Hash::make usage across authentication files
grep -r "Hash::make" app/ --include="*.php" | wc -l

# Verify no direct password_hash usage (framework only)
grep -r "password_hash" app/ --include="*.php" || echo "No direct password_hash usage found (good)"

# Verify no plain-text password assignments
grep -r "'password'.*=>.*\$" app/ --include="*.php" | grep -v "Hash::make" | grep -v "bcrypt" || echo "No plain-text password assignments found (good)"

# Verify Hash facade configuration
php artisan tinker --execute="echo config('hashing.driver');"
```

**Accept when:**
- All password storage operations use Hash::make() as verified by grep showing consistent usage across authentication files
- No direct password_hash() calls found in application code (framework usage only)
- Hash facade configuration is properly set in config/hashing.php with bcrypt or argon2id driver
- Test suite includes verification that passwords are hashed before database storage

<enforcement>
Claude Code MUST NOT skip or defer verification of Hash facade usage in password-related code. All authentication workflows storing or verifying passwords MUST use Laravel's Hash facade with bcrypt or argon2id algorithms.
</enforcement>
