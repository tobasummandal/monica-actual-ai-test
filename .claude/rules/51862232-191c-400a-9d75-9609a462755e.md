### Rules

- **R-DOM-001** MAY: CI/CD pipelines MAY implement domain-specific test stages that execute only tests for changed domains.
- **R-DOM-002** MUST: Test files under tests/Unit/Domains/ MUST mirror the production code structure from app/Domains/ or src/Domains/.
- **R-DOM-003** MUST: Test file names MUST append 'Test' suffix to production class names (e.g., UserTest.php for User.php).
- **R-DOM-004** MUST: Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) MUST be represented as subdirectories within their respective domains.
- **R-DOM-005** MUST: Test file paths MUST mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix.
- **R-DOM-006** SHOULD: Domain and module directory names SHOULD be concise yet descriptive to minimize path length.
- **R-DOM-007** SHOULD: CI/CD pipelines SHOULD support domain-based test execution using path filters (e.g., phpunit --filter tests/Unit/Domains/Settings/).
- **R-DOM-008** SHOULD: IDE templates or code generation tools SHOULD be implemented to automatically create test files in the correct location based on production code paths.
- **R-DOM-009** MAY: Shared test utilities or base test classes that serve multiple domains MAY be organized as exceptions (EXC-001).
- **R-DOM-010** MAY: Legacy tests being refactored into domain structure MAY be organized as exceptions during migration period (EXC-002).
