<rule_activation id="bb7998e4-4841-498c-99e8-aa8427fdddf6" title="Standardize External API Integration with DAV Protocol and DTO Pattern: External Integrations Define" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API integrations including DAV, CardDAV, and CalDAV protocols, data transfer operations, resource import/export, permission validation, and backend interface implementations.
</rule_activation>

### Rules

- **R-EXT-001** MUST: External API integrations MUST define domain-specific exception types that extend base exception classes and provide meaningful error context for API-specific failures.
- **R-EXT-002** MUST: All external API integrations use DTO classes for data transfer with at least one DTO per external entity type.
- **R-EXT-003** MUST: Protocol-specific operations MUST be abstracted behind interface contracts with at least one concrete implementation.
- **R-EXT-004** MUST: Domain-specific exception types MUST exist for common API failure scenarios (permission, compliance, limits) and be properly caught in controllers.
- **R-EXT-005** MUST: ViewHelper classes MUST be present for domains that expose external APIs and used in controller response preparation.
- **R-EXT-006** SHOULD: When creating new external API integrations, start by defining DTO classes that represent the external data format, then create mappers to internal domain models.
- **R-EXT-007** SHOULD: Define backend interfaces before implementing concrete classes; use dependency injection to provide implementations to consumers.
- **R-EXT-008** SHOULD: Create domain-specific exception types in the appropriate domain namespace with descriptive names and error messages.
- **R-EXT-009** SHOULD: Add the Loggable trait to API client classes to ensure consistent logging of external API interactions for debugging and monitoring.

### Verify

```bash
# Count DTO classes in external API integrations
grep -r "class.*Dto" app/Domains/*/DavClient/Services/Utils/Model/ | wc -l

# Count backend interface definitions
grep -r "interface.*Backend" app/Domains/*/Dav/Web/Backend/ | wc -l

# Count domain-specific exception types
grep -r "class.*Exception extends" app/Domains/ | grep -E "(Permission|Compliant|Maximum)" | wc -l

# Count ViewHelper classes
find app/Domains -name "*ViewHelper.php" -type f | wc -l
```

**Accept when:**
- All external API integrations use DTO classes for data transfer with at least one DTO per external entity type
- Protocol-specific operations are abstracted behind interface contracts with at least one concrete implementation
- Domain-specific exception types exist for common API failure scenarios (permission, compliance, limits) and are properly caught in controllers
- ViewHelper classes are present for domains that expose external APIs and are used in controller response preparation

<enforcement>
Claude Code MUST NOT skip or defer verification. All external API integrations MUST comply with R-EXT-001 through R-EXT-009. Pull requests introducing external API integrations without proper DTO/interface patterns MUST be blocked until refactored. Critical violations (missing permission checks, generic exceptions) require immediate remediation before deployment.
</enforcement>
