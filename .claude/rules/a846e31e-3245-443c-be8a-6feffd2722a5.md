<rule_activation id="a846e31e-3245-443c-be8a-6feffd2722a5" title="Standardize Password Hashing for Authentication Operations: Password Hashing Occur" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in authentication workflows, domain services, and Fortify action handlers.
</rule_activation>

### Rules

- **R-AUTH-001** MUST: Password hashing MUST occur before persisting user credentials to the database in all authentication workflows (account creation, password reset, password update, invitation acceptance).
- **R-AUTH-002** MUST: Use Hash::make($password) or bcrypt() helper for all password hashing operations in authentication code paths.
- **R-AUTH-003** MUST: Configure bcrypt cost factor in config/hashing.php and review periodically as computing power increases.
- **R-AUTH-004** MUST: In Fortify action classes (ResetUserPassword, UpdateUserPassword), ensure password hashing occurs before calling $user->forceFill(['password' => ...])->save().
- **R-AUTH-005** MUST: In domain service classes (CreateAccount, AcceptInvitation), apply hashing before user model creation or password updates.
- **R-AUTH-006** MUST: No exceptions permitted for production authentication code; password hashing is a non-negotiable security requirement.

### Verify

```bash
# Detect potential unhashed password assignments in authentication code
grep -r "'password'\s*=>\s*\$" app/ --include='*.php' | grep -v 'Hash::make' | grep -v 'bcrypt(' | grep -v '// ' || echo 'No unhashed password assignments found'

# Count Hash::make and bcrypt usage in Fortify and Settings domains
grep -r "Hash::make\|bcrypt(" app/Actions/Fortify/ app/Domains/Settings/ --include='*.php' | wc -l

# Verify password-related feature tests exist and pass
php artisan test --filter=Password --coverage-text | grep -E '(UpdatePasswordTest|ResetPasswordTest)'
```

**Accept when:**
- All password assignment operations in authentication code paths use Hash::make() or bcrypt() helper
- Feature tests verify that stored passwords are hashed (Hash::check returns true for original password)
- Code review checklist includes verification of password hashing for any authentication-related changes
- No grep patterns detect potential unhashed password assignments in CI pipeline
- Static analysis confirms password hashing in all authentication workflows (account creation, password reset, password update, invitation acceptance)

<enforcement>
Claude Code MUST NOT skip or defer verification. All password hashing operations MUST be verified before accepting authentication code changes. Violations in production code are non-negotiable security failures.
</enforcement>
