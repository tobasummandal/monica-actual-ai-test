<rule_activation id="3b65e938-0634-4eed-9ec2-c56a84cd3a8e" title="Adopt Domain-Driven Controller Organization for Journal Management: Domains Organize Controllers" applies_to="**/*Controller.php">
These rules are ALWAYS ACTIVE for all controller files in domain-driven Laravel applications.

**In scope:**
- All web controllers within the Vault domain
- Controllers handling journal, post, photo, metric, and slice of life entities
- New controllers added to the ManageJournals bounded context
- API and web interface controllers for journal management

**Out of scope:**
- Service classes and business logic layers
- Data transfer objects and view models
- Repository implementations
- Console commands and CLI controllers
- Background job handlers
</rule_activation>

### Rules

- **R-DDC-001** MAY: Domains MAY organize controllers into further subdirectories if the number of controllers exceeds 10 within a single domain.

**Exceptions:**
- **EX-001**: A controller handles cross-domain concerns that cannot be reasonably placed within a single domain boundary
- **EX-002**: Legacy controllers exist outside this structure and refactoring would introduce significant risk

### Context

Controllers should be organized within domain-driven architecture with bounded contexts (e.g., `app/Domains/Vault/ManageJournals/Web/Controllers`). This separates journal management concerns from other vault-related domains while maintaining Laravel framework compatibility.

Key principles:
- Domain-driven organization improves code discoverability by grouping related controllers based on business capabilities
- Single responsibility controllers prevent controller bloat
- Controllers should be organized by entity and concern (journals, posts, photos, metrics)
- The Web/Controllers subdirectory structure allows for future expansion to API controllers or other interface types

### Verify

```bash
# Count controller files in the ManageJournals domain
find app/Domains/Vault/ManageJournals/Web/Controllers -name '*Controller.php' | wc -l

# Verify namespace declarations match directory structure
grep -r 'namespace App\\Domains\\Vault\\ManageJournals\\Web\\Controllers' app/Domains/Vault/ManageJournals/Web/Controllers/*.php | wc -l

# Verify routes reference controllers using domain-based namespace
php artisan route:list --path=journal --columns=Action | grep 'App\\Domains\\Vault\\ManageJournals\\Web\\Controllers'
```

**Accept when:**
- All controller files in the ManageJournals domain are located under `app/Domains/Vault/ManageJournals/Web/Controllers`
- Each controller has a single, clear responsibility corresponding to an entity or entity-concern combination
- Controller namespaces match their directory structure and follow the established pattern
- Route definitions correctly reference controllers using the domain-based namespace

<enforcement>
Claude Code MUST verify controller organization follows domain-driven structure.

**Verification:**
- Automated CI checks using grep and find commands verify controller placement
- Code review checklist requires verification of controller organization for new features
- PHPStan or Psalm static analysis rules enforce namespace conventions

**Violation handling:**
- CI pipeline fails if controllers are placed outside the designated domain structure
- Pull requests are blocked until controllers are moved to correct locations
- Architecture team is notified of repeated violations for coaching and documentation improvements

**Exception process:**
- Developer creates an exception request documenting the rationale for non-standard placement
- Architecture team reviews the request within 2 business days
- If approved, exception is documented in ADR exceptions log with expiration date or migration plan
- Exceptions are reviewed quarterly to determine if they can be resolved
</enforcement>
