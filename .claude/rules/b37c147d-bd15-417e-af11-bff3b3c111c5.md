<rule_activation id="b37c147d-bd15-417e-af11-bff3b3c111c5" title="Standardize Password Hashing for Authentication Operations: Password Validation Rules" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching authentication operations, domain services, and Fortify action handlers that handle password creation, updates, and resets.
</rule_activation>

### Rules

- **R-AUTH-001** MUST: Password validation rules MUST be enforced before hashing (minimum length, complexity requirements).
- **R-AUTH-002** MUST: Use Hash::make($password) for all password hashing operations; configure cost factor in config/hashing.php.
- **R-AUTH-003** MUST: In Fortify action classes (ResetUserPassword, UpdateUserPassword), ensure password hashing occurs before calling $user->forceFill(['password' => ...])->save().
- **R-AUTH-004** MUST: In domain service classes (CreateAccount, AcceptInvitation), apply hashing before user model creation or password updates.
- **R-AUTH-005** MUST: Feature tests MUST use Hash::check($plainPassword, $user->password) to verify hashing occurred correctly.
- **R-AUTH-006** SHOULD: Consider using Laravel's validation rule 'Password::min(8)->mixedCase()->numbers()' to enforce password complexity before hashing.

### Verify

```bash
# Detect unhashed password assignments in authentication code
grep -r "'password'\s*=>\s*\$" app/ --include='*.php' | grep -v 'Hash::make' | grep -v 'bcrypt(' | grep -v '// ' || echo 'No unhashed password assignments found'

# Count Hash::make and bcrypt usage in Fortify and Settings domains
grep -r "Hash::make\|bcrypt(" app/Actions/Fortify/ app/Domains/Settings/ --include='*.php' | wc -l

# Verify password-related feature tests exist and pass
php artisan test --filter=Password --coverage-text | grep -E '(UpdatePasswordTest|ResetPasswordTest)'
```

**Accept when:**
- All password assignment operations in authentication code paths use Hash::make() or bcrypt() helper
- Feature tests verify that stored passwords are hashed (Hash::check returns true for original password)
- Code review checklist includes verification of password hashing for any authentication-related changes
- No unhashed password assignments detected in grep verification
- Password-related feature tests pass with adequate coverage

<enforcement>
Claude Code MUST NOT skip or defer verification. All password hashing operations MUST comply with R-AUTH-001 through R-AUTH-006. Violations in production authentication code are non-negotiable security failures. CI pipeline MUST fail if grep patterns detect potential unhashed password assignments. Code review MUST block merge if password hashing is not verified.
</enforcement>
