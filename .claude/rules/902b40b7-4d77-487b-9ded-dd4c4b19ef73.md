<rule_activation id="902b40b7-4d77-487b-9ded-dd4c4b19ef73" title="Adopt Domain-Driven Resource Modeling for Data Access Layer: Domain Entities Represented" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the application to ensure consistent domain-driven modeling patterns across the data access layer.
</rule_activation>

### Rules

- **R-DDR-001** MUST: All domain entities MUST be represented by dedicated model classes that encapsulate data structure and basic persistence logic.

- **R-DDR-002** MUST: Place core domain models in app/Models/ directory with clear, singular naming (e.g., File.php, User.php).

- **R-DDR-003** MUST: Organize domain-specific models and resources within app/Domains/{DomainName}/ subdirectories to maintain bounded contexts.

- **R-DDR-004** MUST: Create dedicated resource classes (e.g., VCardResource, VCalendarResource) for external protocol transformations in appropriate domain subdirectories.

- **R-DDR-005** SHOULD: Use consistent method naming for resource transformations (e.g., toVCard(), fromVCard()) to establish predictable APIs.

**In scope:**
- All Eloquent models representing persistent domain entities
- Resource classes for DAV protocol integration (VCard, VCalendar)
- Data transfer objects used for external API communication
- Domain-specific model classes within bounded contexts

**Out of scope:**
- View models or presentation layer DTOs
- Temporary data structures used only within single methods
- Third-party library models or external package entities
- Database migration files and schema definitions

### Verify

```bash
# Count domain models in app/Models directory
find app/Models -name '*.php' -type f | wc -l

# Count resource classes in domain directories
grep -r 'class.*Resource' app/Domains/ --include='*.php' | wc -l

# Verify domain organization with Dav subdirectories
find app/Domains -type d -name 'Dav' | wc -l
```

**Accept when:**
- All domain entities have corresponding model classes in app/Models/ or domain-specific directories
- External protocol integrations use dedicated resource classes separate from core models
- Domain organization follows consistent directory structure with clear bounded contexts
