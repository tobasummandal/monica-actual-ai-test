These rules are ALWAYS ACTIVE for all files in the application to ensure consistent domain-driven resource modeling across the data access layer.
</rule_activation>

### Rules

- **R-DDD-001** MUST: All domain entities MUST be represented by dedicated model classes that encapsulate data structure and basic persistence logic.

### Verify

```bash
# Count Eloquent models in app/Models directory
find app/Models -name '*.php' -type f | wc -l

# Count resource classes in app/Domains
grep -r 'class.*Resource' app/Domains/ --include='*.php' | wc -l

# Verify domain-specific Dav directories exist
find app/Domains -type d -name 'Dav' | wc -l
```

**Accept when:**
- All domain entities have corresponding model classes in `app/Models/` or domain-specific directories
- External protocol integrations use dedicated resource classes separate from core models
- Domain organization follows consistent directory structure with clear bounded contexts
- Core domain models are placed in `app/Models/` with clear, singular naming (e.g., `File.php`, `User.php`)
- Domain-specific models and resources are organized within `app/Domains/{DomainName}/` subdirectories
- Resource classes for external protocols (e.g., `VCardResource`, `VCalendarResource`) are in appropriate domain subdirectories
- Resource transformation methods use consistent naming (e.g., `toVCard()`, `fromVCard()`)

Automated linting failures block merge until models are reorganized according to pattern. Architecture review is required for new domain contexts to ensure consistent application of pattern.
