<rule_activation id="015101c2-2871-413e-8ddb-7015623f7147" title="Adopt CardDAV/WebDAV Protocol for External Contact Synchronization" applies_to="app/Domains/Contact/**/*">
These rules are ALWAYS ACTIVE for all external contact synchronization integrations and DAV protocol implementations within the Contact domain.
</rule_activation>

### Rules

- **R-CARDDAV-001** MUST: All external contact synchronization MUST use CardDAV/WebDAV protocols as the standard integration mechanism.
- **R-CARDDAV-002** MUST: All DAV backend implementations MUST implement the IDAVBackend interface.
- **R-CARDDAV-003** MUST: Contact DTO models (ContactDto, ContactDeleteDto) MUST be used consistently across all DAV client services for external API communication.
- **R-CARDDAV-004** MUST: Error handling MUST distinguish between network errors, authentication failures, and protocol compliance issues using DavServerNotCompliantException.
- **R-CARDDAV-005** MUST: vCard import and export operations MUST be handled through dedicated resource handlers (ImportResource, ImportVCardResource) to maintain single responsibility principle.
- **R-CARDDAV-006** SHOULD: Implement batch processing with configurable batch sizes for large-scale contact synchronization operations.
- **R-CARDDAV-007** SHOULD: Add request throttling to respect server rate limits and use background job queues for large sync operations.
- **R-CARDDAV-008** SHOULD: Create integration tests verifying compatibility with major CardDAV implementations (Nextcloud, Radicale, Apple Calendar Server).
- **R-CARDDAV-009** MAY: Use vCard extension fields (X-*) for custom data where standard vCard fields are insufficient.

### Verify

```bash
# Verify IDAVBackend interface implementation
grep -r "IDAVBackend" app/Domains/Contact/Dav/ --include="*.php" | wc -l

# Verify ContactDto and ContactDeleteDto usage
grep -r "ContactDto\|ContactDeleteDto" app/Domains/Contact/DavClient/ --include="*.php" | wc -l

# Verify DavServerNotCompliantException presence and usage
grep -r "DavServerNotCompliantException" app/Domains/Contact/ --include="*.php" | wc -l

# Verify import resource handlers exist
find app/Domains/Contact/Dav* -name "*Import*Resource.php" -o -name "*VCard*.php" | wc -l
```

**Accept when:**
- All DAV backend implementations implement the IDAVBackend interface (verify command 1 returns > 0)
- Contact DTO models are consistently used across DavClient services (verify command 2 returns >= 2 for both DTOs)
- DavServerNotCompliantException is present and used for error handling (verify command 3 returns > 0)
- Import resource handlers exist for DAV and vCard operations (verify command 4 returns >= 2)

<enforcement>
Claude Code MUST NOT skip or defer verification. All four verification commands MUST pass before accepting changes to external contact synchronization code. CI pipeline MUST fail if DAV backend classes do not implement IDAVBackend interface. Pull requests MUST be blocked if external API calls bypass DTO models. Architecture review MUST be triggered if new contact synchronization code is added outside the DavClient namespace.
</enforcement>
