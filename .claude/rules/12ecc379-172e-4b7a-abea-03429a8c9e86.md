<rule_activation id="12ecc379-172e-4b7a-abea-03429a8c9e86" title="Adopt Mock-Based Unit Testing for External Service Dependencies in CI/CD Pipeline: Integration Tests That" applies_to="**/*Test.php">
These rules are ALWAYS ACTIVE for all unit test files in the codebase. Mock-based testing is the standard pattern for isolating external service dependencies in CI/CD pipelines.
</rule_activation>

### Rules

- **R-MOCK-001** SHOULD: Integration tests that verify real external service interactions SHOULD be separated from unit tests and run in dedicated CI/CD stages.
- **R-MOCK-002** MUST: Unit tests for HTTP clients, API wrappers, and service integrations MUST use mock/stub/fake patterns for external dependencies.
- **R-MOCK-003** MUST: Tests for jobs and background workers that call external services MUST use mocking to isolate external service calls.
- **R-MOCK-004** MUST: Tests for synchronization utilities that interact with remote data sources MUST use mocking to prevent real network calls.
- **R-MOCK-005** MUST: Tests for authentication and authorization flows involving external providers MUST use mocking for external provider interactions.
- **R-MOCK-006** SHOULD: Use the testing framework's native mocking capabilities (PHPUnit's createMock/getMockBuilder for PHP projects) for consistency.
- **R-MOCK-007** SHOULD: Create reusable mock factories or test helpers for commonly mocked external services to reduce duplication.
- **R-MOCK-008** SHOULD: Document expected external service behavior in test comments to help future maintainers understand mock setup.
- **R-MOCK-009** SHOULD: Organize tests into clear unit test and integration test directories with separate CI/CD execution stages.
- **R-MOCK-010** MAY: Use builder patterns or fluent interfaces for complex mock setup to improve test readability.
- **R-MOCK-EXC-001** Exception: Testing framework-level HTTP client configuration or connection pooling behavior that cannot be adequately simulated may use real service calls with documented justification.

### Verify

```bash
# Check for unmocked external service calls in unit tests
grep -r "new.*Client\|->connect\|->request" tests/Unit/ | grep -v "Mock\|Stub\|Fake" | wc -l

# Count unit test files using mocking patterns
find tests/Unit -name '*Test.php' -exec grep -l 'createMock\|getMockBuilder\|shouldReceive' {} \; | wc -l

# Verify no network-dependent tests in unit suite
phpunit --testsuite=unit --no-coverage --testdox | grep -i 'network\|connection\|timeout' || echo 'No network-dependent tests found'

# Measure unit test execution time
phpunit --testsuite=unit --no-coverage --testdox 2>&1 | grep -i 'time'
```

**Accept when:**
- Unit tests execute successfully without network connectivity (verified by running tests with network disabled)
- Unit test suite completes in under 30 seconds for typical project size, indicating no real external service calls
- Grep verification shows that unit tests use mock/stub/fake patterns for external service dependencies
- CI/CD pipeline unit test stage has >95% success rate over 30-day period, indicating stable, non-flaky tests
- No direct instantiation of HTTP clients or external service classes found in unit test files (except in mock setup)
- All external service interactions in unit tests are verified through mock assertions

<enforcement>
Claude Code MUST NOT skip or defer verification. All unit tests MUST use mocking for external service dependencies. Code review MUST block merges that violate these rules. CI/CD pipeline MUST fail if unit tests exceed 30-second execution threshold or show network-dependent behavior.
</enforcement>
