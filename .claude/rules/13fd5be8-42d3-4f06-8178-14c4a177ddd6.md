<rule_activation id="13fd5be8-42d3-4f06-8178-14c4a177ddd6" title="Adopt HTTP Client Libraries for External API Integration: Http Client Configurations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`.
</rule_activation>

### Rules

- **R-HTTP-001** SHOULD: HTTP client configurations SHOULD be externalized to configuration files or environment variables for different environments.
- **R-HTTP-002** SHOULD: Wrap HTTP client library usage in service classes to encapsulate external API logic and provide domain-specific interfaces.
- **R-HTTP-003** SHOULD: Configure HTTP clients with appropriate timeouts, retry policies, and error handling strategies based on the reliability requirements of each external service.
- **R-HTTP-004** SHOULD: Use dependency injection to provide HTTP client instances, enabling easy mocking in unit tests and configuration flexibility across environments.
- **R-HTTP-005** SHOULD: Document authentication patterns for each integration type (OAuth, Basic Auth, API keys) with examples in the codebase.
- **R-HTTP-006** SHOULD: Implement logging and monitoring for external API calls to track performance, errors, and usage patterns.

### Scope

**In scope:**
- All outbound HTTP/HTTPS requests to external APIs and services
- OAuth provider integrations (Google, Facebook, GitHub, etc.)
- WebDAV, CalDAV, and CardDAV protocol communications
- Third-party REST API consumption (Wikipedia, documentation services, etc.)
- vCard and vCalendar data import/export operations

**Out of scope:**
- Internal service-to-service communication within the same application
- Database connections and queries
- File system operations
- Message queue or event bus communications
- WebSocket connections (unless using HTTP upgrade mechanism)

**Exceptions:**
- EXC-001: Legacy code maintenance where refactoring risk exceeds benefit
- EXC-002: Performance-critical scenarios where library overhead is demonstrably prohibitive

### Verify

```bash
# Check for Socialite library usage in OAuth flows
grep -r "use.*Socialite" app/ --include="*.php" | wc -l

# Check for Sabre DAV/VObject library usage
grep -r "use.*Sabre" app/ --include="*.php" | wc -l

# Check for raw HTTP implementations (should be avoided in new code)
grep -r "curl_exec\|fsockopen" app/ --include="*.php" | wc -l
```

**Accept when:**
- Socialite library usage is detected in OAuth authentication flows
- Sabre DAV/VObject libraries are used for DAV protocol and vCard/vCalendar operations
- No raw cURL or socket implementations are found in new external API integration code
- Service classes encapsulate HTTP client library usage with clear domain interfaces

<enforcement>
Claude Code MUST verify that HTTP client configurations are externalized and that appropriate libraries (Socialite, Sabre DAV) are used for external API integration. Raw HTTP implementations (curl_exec, fsockopen) in new code require documented exception approval.
</enforcement>
