<rule_activation id="48558b7e-de26-4299-9c39-2c689a830397" title="Adopt Laravel Fortify for Authentication Action Standardization: Authentication Action Classes" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the project implementing authentication and user management operations.

This ADR establishes Laravel Fortify as the standard approach for authentication action classes, ensuring separation between authentication logic and presentation concerns to enable deployment flexibility across web, API, and mobile targets.

**In scope:**
- All password management operations (reset, update, validation)
- User account lifecycle operations (creation, cancellation, invitation acceptance)
- Authentication action classes in app/Actions/Fortify
- Domain service classes handling user management in app/Domains/Settings
- Feature tests validating authentication behavior

**Out of scope:**
- Frontend authentication UI components
- Session management and cookie handling
- OAuth and social authentication providers
- Authorization and permission logic
- API token generation and management
</rule_activation>

### Rules

- **R-FORTIFY-001** MUST_NOT: Authentication action classes MUST NOT contain presentation logic (views, redirects, session management) to maintain separation between authentication logic and deployment target concerns

### Verify

```bash
# Check that Fortify actions properly extend Fortify contracts
grep -r "extends.*Fortify" app/Actions/Fortify/ | wc -l

# Verify domain services exist in proper directory structure
find app/Domains -name "*Service.php" -path "*/Services/*" | wc -l

# Confirm consistent use of Laravel Hash facade
grep -r "use Illuminate\\\\Support\\\\Facades\\\\Hash" app/Actions/Fortify app/Domains/Settings | wc -l

# Run authentication-related feature tests
php artisan test --filter=Auth --filter=Password --filter=Account
```

**Accept when:**
- All authentication actions in app/Actions/Fortify extend appropriate Fortify contracts and are registered in FortifyServiceProvider
- Domain-specific user management services exist in app/Domains/*/Services and delegate to Fortify actions for password operations
- Feature tests for authentication operations pass and cover both web and API scenarios without presentation layer dependencies
- Password validation uses Laravel Hash facade consistently across all authentication touchpoints

<enforcement>
Claude Code MUST verify compliance with these rules when:
- Creating or modifying authentication action classes
- Implementing user management operations
- Adding password reset or update functionality
- Creating feature tests for authentication flows

Claude Code MUST NOT:
- Skip verification of these rules for authentication-related changes
- Add presentation logic (views, redirects, session management) to authentication action classes
- Implement authentication logic directly in controllers without corresponding Fortify actions or domain services
- Use direct password hashing without Laravel's Hash facade

Violations MUST be flagged during code generation with specific guidance on how to refactor to comply with the Fortify pattern.
</enforcement>
