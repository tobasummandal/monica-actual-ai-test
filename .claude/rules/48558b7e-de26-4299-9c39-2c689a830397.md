<rule_activation id="48558b7e-de26-4299-9c39-2c689a830397" title="Adopt Laravel Fortify for Authentication Action Standardization: Authentication Action Classes" applies_to="app/Actions/Fortify/**,app/Domains/Settings/**">
These rules are ALWAYS ACTIVE for all authentication action classes in Laravel Fortify and domain service implementations handling user lifecycle operations.
</rule_activation>

### Rules

- **R-FORTIFY-001** MUST NOT: Authentication action classes MUST NOT contain presentation logic (views, redirects, session management) to maintain separation between authentication logic and deployment target concerns.

### Verify

```bash
# Verify Fortify action classes are properly extending Fortify contracts
grep -r "extends.*Fortify" app/Actions/Fortify/ | wc -l

# Verify domain-specific user management services exist
find app/Domains -name "*Service.php" -path "*/Services/*" | wc -l

# Verify Hash facade is used consistently for password operations
grep -r "use Illuminate\\Support\\Facades\\Hash" app/Actions/Fortify app/Domains/Settings | wc -l

# Run authentication and password feature tests
php artisan test --filter=Auth --filter=Password --filter=Account
```

**Accept when:**
- All authentication actions in `app/Actions/Fortify/` extend appropriate Fortify contracts and are registered in `FortifyServiceProvider`
- Domain-specific user management services exist in `app/Domains/*/Services/` and delegate to Fortify actions for password operations
- Feature tests for authentication operations pass and cover both web and API scenarios without presentation layer dependencies
- Password validation uses Laravel Hash facade consistently across all authentication touchpoints
- No presentation logic (views, redirects, session management) is detected in authentication action classes

<enforcement>
Claude Code MUST verify all rules before accepting authentication-related changes. Verification is mandatory and MUST NOT be skipped or deferred.
</enforcement>
