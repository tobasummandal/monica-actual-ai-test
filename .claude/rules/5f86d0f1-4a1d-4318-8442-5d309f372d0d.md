<rule_activation id="5f86d0f1-4a1d-4318-8442-5d309f372d0d" title="Adopt Encrypted Secrets Management in CI/CD Pipeline: Teams Use Environment" applies_to="**/*">
These rules are ALWAYS ACTIVE for all CI/CD pipeline configurations and deployment workflows.
</rule_activation>

### Rules

- **R-SEC-001** MAY: Teams MAY use environment-specific secret namespaces to isolate development, staging, and production credentials

### Verify

```bash
# Check for plaintext secrets in pipeline configuration files
grep -r "password\|secret\|api[_-]key" .github/workflows/ .gitlab-ci.yml Jenkinsfile | grep -v "\${{" | grep -v "\${" || echo 'No plaintext secrets found'

# Check git history for exposed secrets
git log -p | grep -E "(password|secret|api[_-]?key)\s*=\s*['\"][^'\"]{8,}" || echo 'No secrets in git history'

# Count secrets management references in configuration files
find . -name '*.yml' -o -name '*.yaml' | xargs grep -l 'secrets\|vault\|encrypted' | wc -l
```

**Accept when:**
- No plaintext secrets are found in pipeline configuration files when scanning with grep patterns
- All secrets are referenced using platform-specific variable syntax (e.g., `${{ secrets.NAME }}`, `${VAULT_SECRET}`)
- Pipeline logs demonstrate secret masking with values replaced by `***` or `[REDACTED]` markers
- Secrets management documentation exists with inventory of all secrets, their purpose, and rotation schedule
- Automated secret scanning tools (truffleHog, git-secrets, detect-secrets) are integrated in pre-commit hooks and CI pipelines
- Secrets management solution is configured (GitHub Secrets, GitLab CI/CD variables, AWS Secrets Manager, or HashiCorp Vault)

<enforcement>
Claude Code MUST verify encrypted secrets management is properly implemented in all CI/CD pipeline configurations. Verification is mandatory before accepting pipeline configurations or deployment workflows. Violations must be flagged and remediation guidance provided.
</enforcement>
