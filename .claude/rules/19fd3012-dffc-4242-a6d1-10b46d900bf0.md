<rule_activation id="19fd3012-dffc-4242-a6d1-10b46d900bf0" title="Adopt Laravel Migrations as Standard Database Schema Management: Database Schema Changes" applies_to="**/*">
These rules are ALWAYS ACTIVE for all database schema changes across the application. All schema modifications MUST be implemented through Laravel migration files.
</rule_activation>

### Rules

- **R-LMIG-001** MUST: All database schema changes MUST be implemented using Laravel migration files stored in the database/migrations directory.
- **R-LMIG-002** MUST: All table creation, modification, and deletion operations MUST use Laravel migrations.
- **R-LMIG-003** MUST: Column additions, modifications, and removals MUST be implemented through migrations.
- **R-LMIG-004** MUST: Index creation and removal MUST be implemented through migrations.
- **R-LMIG-005** MUST: Foreign key constraint definitions MUST be implemented through migrations.
- **R-LMIG-006** MUST: Database-level configuration changes affecting schema structure MUST be implemented through migrations.
- **R-LMIG-007** SHOULD: Use 'php artisan make:migration' command to generate new migration files with proper timestamp and structure.
- **R-LMIG-008** SHOULD: Always test migrations locally with both 'migrate' and 'migrate:rollback' commands before committing to ensure down() method works correctly.
- **R-LMIG-009** SHOULD: Use Laravel's migration methods like 'foreignId()', 'timestamps()', 'softDeletes()' for consistency with framework conventions.
- **R-LMIG-010** SHOULD: Document any database-specific SQL used in migrations with comments explaining compatibility implications.
- **R-LMIG-011** MAY: For complex data transformations, consider separating schema changes from data migrations into distinct migration files for clarity.

### Verify

```bash
# Count migration files
find database/migrations -name '*.php' -type f | wc -l | grep -E '^[0-9]+$'

# Verify Schema Builder usage
grep -r 'Schema::create\|Schema::table\|Schema::drop' database/migrations/ | wc -l

# Check migration status
php artisan migrate:status 2>&1 | grep -E 'Ran|Pending'

# Verify up() and down() methods exist
ls database/migrations/*.php 2>/dev/null | head -5 | xargs grep -l 'function up()' | xargs grep -l 'function down()'
```

**Accept when:**
- All migration files exist in database/migrations directory and follow Laravel naming convention with timestamps (YYYY_MM_DD_HHMMSS_description.php)
- Each migration file contains both up() and down() methods using Schema Builder API
- Migration status command executes successfully showing tracked migrations
- No direct SQL schema modifications are found in application code outside migration files
- Migration files follow chronological ordering and prevent conflicts through timestamp-based naming

<enforcement>
Claude Code MUST verify all database schema changes are implemented through Laravel migrations before accepting any modifications. Violations must be flagged and rejected. Emergency exceptions require post-incident review and compensating migration within 24 hours.
</enforcement>
