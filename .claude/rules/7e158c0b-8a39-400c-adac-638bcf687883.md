<rule_activation id="7e158c0b-8a39-400c-adac-638bcf687883" title="Adopt Domain-Driven DAV/CardDAV Integration Pattern for External Contact Synchronization: External Dav Carddav" applies_to="**/*">
These rules are ACTIVE for all external API integrations involving contact synchronization via DAV/CardDAV protocols within domain-bounded contexts.

**In scope:**
- All DAV/CardDAV protocol integrations for contact synchronization
- External API integrations requiring domain boundary enforcement
- VCard import/export operations across system boundaries
- Contact data synchronization with third-party DAV servers

**Out of scope:**
- Internal domain-to-domain communication within the application
- REST API endpoints for web/mobile clients
- Database-level data access patterns
- Non-contact related external integrations

**Exceptions:**
- EXC-001: Legacy DAV server integration requires direct database access for performance optimization
</rule_activation>

### Rules

- **R-DAV-001** MUST: External DAV/CardDAV integrations MUST be encapsulated within domain-specific service layers (e.g., Contact domain DavClient services)
- **R-DAV-002** MUST: DTO objects MUST be used for data transfer across domain boundaries for contact synchronization
- **R-DAV-003** MUST: Interface contracts (e.g., IDAVBackend) MUST be defined for all DAV backend implementations
- **R-DAV-004** MUST: Specific exception types (e.g., DavServerNotCompliantException) MUST be used for DAV server error handling
- **R-DAV-005** SHOULD: Separate resource classes SHOULD be implemented for distinct import operations (ImportResource, ImportVCardResource)
- **R-DAV-006** SHOULD: ViewHelper classes SHOULD be used to separate presentation concerns from domain logic
- **R-DAV-007** SHOULD: Explicit validation rules and transformation methods SHOULD be implemented in DTO classes for conversion to/from domain entities

### Verify

```bash
# Check for DTO classes in Contact domain DavClient services
grep -r "class.*Dto" app/Domains/Contact/DavClient/Services/Utils/Model/ | wc -l

# Verify IDAVBackend interface exists
grep -r "interface.*Backend" app/Domains/Contact/Dav/Web/Backend/ | grep -c "IDAVBackend"

# Check for DavServerNotCompliantException
grep -r "DavServerNotCompliantException" app/Domains/Contact/DavClient/Services/Utils/Dav/ | wc -l

# Count resource classes for import operations
find app/Domains/Contact/Dav -name "*Resource.php" -type f | wc -l
```

**Accept when:**
- At least 2 DTO classes exist in Contact domain DavClient services for data transfer
- IDAVBackend interface is defined and implemented by at least one concrete backend class
- DavServerNotCompliantException exists and is used in DAV client error handling
- Separate resource classes exist for import operations (ImportResource, ImportVCardResource)
