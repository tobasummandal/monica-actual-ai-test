<rule_activation id="789d6235-3c0c-4729-93d1-14dc6c01dece" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: View Helpers Retrieve" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching domain services, view helpers, background jobs, and global helpers that interact with primary datastores.
</rule_activation>

### Rules

- **R-DATASTORE-001** SHOULD: View helpers SHOULD retrieve data through service layer methods rather than directly querying datastores when business logic is involved.

### Verify

```bash
# Detect direct SQL queries without performance exception comments
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access pattern tests
php artisan test --filter=DataAccessTest

# Static analysis for data access violations
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections

Claude Code MUST NOT skip or defer verification. CI pipeline enforcement includes automated static analysis, code review checklists, and pre-commit hooks. Violations block pull requests until corrected or documented exceptions are approved.
</enforcement>
