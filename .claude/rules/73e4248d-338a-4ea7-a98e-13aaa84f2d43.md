<rule_activation id="73e4248d-338a-4ea7-a98e-13aaa84f2d43" title="Adopt Eloquent ORM Models as Standard Data Access Layer: Model Classes Placed" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in the Laravel application. They ensure consistent use of Eloquent ORM models as the standard data access layer with proper namespace placement, inheritance, and mass assignment protection.
</rule_activation>

### Rules

- **R-ELQ-001** MUST: Model classes MUST be placed in the app/Models namespace following Laravel conventions.
- **R-ELQ-002** MUST: All model files in app/Models MUST extend Illuminate\Database\Eloquent\Model.
- **R-ELQ-003** MUST: Models MUST define either $fillable or $guarded properties for mass assignment protection.
- **R-ELQ-004** MUST: Direct database queries outside models MUST be documented with exception justifications (EXC-001: Legacy schemas requiring raw SQL; EXC-002: Read-only reporting queries with complex joins).

### In Scope

- All database-backed domain entities requiring CRUD operations
- Entities with relationships to other database tables
- Data structures requiring validation, casting, or transformation
- Objects requiring query builder functionality and collection operations

### Out of Scope

- Value objects without database persistence
- Data Transfer Objects (DTOs) used for API communication
- Temporary data structures for in-memory processing
- External service integrations not backed by application database

### Implementation Guidance

- Use `php artisan make:model` command to generate new models with consistent structure
- Define relationships using type-hinted return types (e.g., `public function posts(): HasMany`) for better IDE support
- Leverage model factories for testing to ensure consistent test data generation
- Document complex query scopes and custom accessors with PHPDoc blocks
- Consider using model observers for cross-cutting concerns rather than cluttering model methods
- Watch for N+1 query problems: enforce eager loading in code reviews and use Laravel Debugbar in development
- Prevent model bloat: establish service layer pattern for complex business logic and refactor models exceeding 300 lines

### Verify

```bash
# Count model classes extending Model
grep -r "extends Model" app/Models/ | wc -l

# Find model files not in App\Models namespace
find app/Models -name '*.php' -exec grep -L 'namespace App\\Models' {} \;

# Show all models
php artisan model:show --all 2>&1 | grep -c 'class'

# Find direct database queries outside models without exception comments
grep -r "DB::table\|DB::select" app/Http app/Services | grep -v "// Exception" | wc -l
```

**Accept when:**
- All model files in app/Models extend Illuminate\Database\Eloquent\Model
- At least 7 model classes exist matching the detected pattern (File, PostTemplateSection, ContactInformationType, GiftOccasion, CallReasonType, Account, QuickFact)
- Models define either $fillable or $guarded properties for mass assignment protection
- Direct database queries outside models are documented with exception justifications
