<rule_activation id="fc0d3991-cc10-47be-94f4-a1972a1fc8d2" title="Adopt Domain-Driven Resource Modeling for Data Access Layer: Model Classes Organized" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching domain models, resources, and data access layer code.
</rule_activation>

### Rules

- **R-DDM-001** SHOULD: Model classes SHOULD be organized by domain context (e.g., Contact, File) to maintain clear bounded contexts
- **R-DDM-002** SHOULD: Place core domain models in app/Models/ directory with clear, singular naming (e.g., File.php, User.php)
- **R-DDM-003** SHOULD: Organize domain-specific models and resources within app/Domains/{DomainName}/ subdirectories to maintain bounded contexts
- **R-DDM-004** SHOULD: Create dedicated resource classes (e.g., VCardResource, VCalendarResource) for external protocol transformations in appropriate domain subdirectories
- **R-DDM-005** SHOULD: Use consistent method naming for resource transformations (e.g., toVCard(), fromVCard()) to establish predictable APIs
- **R-DDM-006** MUST: Separate domain models from protocol-specific resources to maintain single responsibility principle
- **R-DDM-007** MUST: Keep external protocol integrations separate from core domain models

### Verify

```bash
# Count domain models in app/Models/
find app/Models -name '*.php' -type f | wc -l

# Count resource classes in app/Domains/
grep -r 'class.*Resource' app/Domains/ --include='*.php' | wc -l

# Verify domain-specific organization exists
find app/Domains -type d -name 'Dav' | wc -l
```

**Accept when:**
- All domain entities have corresponding model classes in app/Models/ or domain-specific directories
- External protocol integrations use dedicated resource classes separate from core models
- Domain organization follows consistent directory structure with clear bounded contexts
- Resource classes use consistent transformation method naming patterns (toVCard(), fromVCard(), etc.)
- No protocol-specific logic is mixed into core domain model classes

<enforcement>
Claude Code MUST verify model organization against domain boundaries during code review. Static analysis tools MUST check model class locations match domain structure. CI pipeline MUST ensure resource classes are properly separated from domain models. Violations block merge until models are reorganized according to pattern.
</enforcement>
