<rule_activation id="fedd36ec-71d8-4caf-a5ba-8494d965142d" title="Adopt Eloquent ORM Models as Standard Data Access Layer: Business Logic Not" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in the application, particularly those in app/Models and data access layers.
</rule_activation>

### Rules

- **R-ELOQUENT-001** MUST_NOT: Business logic MUST NOT be tightly coupled to model classes; models should focus on data representation and persistence.
- **R-ELOQUENT-002** MUST: All database-backed domain entities requiring CRUD operations MUST use Eloquent ORM models extending Illuminate\Database\Eloquent\Model.
- **R-ELOQUENT-003** MUST: All model classes MUST be placed in the app/Models namespace.
- **R-ELOQUENT-004** MUST: All models MUST define either $fillable or $guarded properties for mass assignment protection.
- **R-ELOQUENT-005** SHOULD: Define relationships using type-hinted return types (e.g., public function posts(): HasMany) for better IDE support and static analysis.
- **R-ELOQUENT-006** SHOULD: Use model factories for testing to ensure consistent test data generation across the test suite.
- **R-ELOQUENT-007** SHOULD: Document complex query scopes and custom accessors with PHPDoc blocks explaining their purpose and usage.
- **R-ELOQUENT-008** SHOULD: Consider using model observers for cross-cutting concerns like logging, caching, or event dispatching rather than cluttering model methods.
- **R-ELOQUENT-009** MAY: Use raw SQL queries or Query Builder directly for legacy database schemas that cannot be efficiently expressed through Eloquent (EXC-001).
- **R-ELOQUENT-010** MAY: Use raw SQL or query builder for read-only reporting queries spanning multiple complex joins (EXC-002).

### Verify

```bash
# Count models extending Eloquent
grep -r "extends Model" app/Models/ | wc -l

# Find models not in correct namespace
find app/Models -name '*.php' -exec grep -L 'namespace App\\Models' {} \;

# Show all models
php artisan model:show --all 2>&1 | grep -c 'class'

# Count direct database queries outside models (excluding documented exceptions)
grep -r "DB::table\|DB::select" app/Http app/Services | grep -v "// Exception" | wc -l
```

**Accept when:**
- All model files in app/Models extend Illuminate\Database\Eloquent\Model
- At least 7 model classes exist matching the detected pattern (File, PostTemplateSection, ContactInformationType, GiftOccasion, CallReasonType, Account, QuickFact)
- Models define either $fillable or $guarded properties for mass assignment protection
- Direct database queries outside models are documented with exception justifications (EXC-ID references)
- No business logic methods are present in model classes that should be in service layer
- Model files do not exceed 300 lines of code

<enforcement>
Claude Code MUST verify all rules before accepting model implementations. Violations of R-ELOQUENT-001 through R-ELOQUENT-004 are blocking. Code review MUST check for mass assignment protection and proper namespace placement. CI pipeline MUST fail if models are created outside app/Models namespace or lack mass assignment protection. Performance monitoring MUST alert on N+1 query patterns. Exceptions require EXC-ID documentation and technical lead approval.
</enforcement>
