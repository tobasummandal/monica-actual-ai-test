<rule_activation id="f9afa568-fb15-4902-99a0-47e7a6d5a0a5" title="Adopt Eloquent ORM Models as Standard Data Modeling Pattern: Model Classes Placed" applies_to="app/Models/**/*.php">
These rules are ALWAYS ACTIVE for all data modeling implementations in the application layer. All domain entities requiring database persistence MUST be represented using Eloquent ORM models.
</rule_activation>

### Rules

- **R-ELOQUENT-001** MUST: Model classes MUST be placed in the app/Models directory following Laravel namespace conventions.
- **R-ELOQUENT-002** MUST: All model files in app/Models directory MUST extend Illuminate\Database\Eloquent\Model.
- **R-ELOQUENT-003** MUST: Define $fillable or $guarded properties in each model to control mass assignment. Prefer $fillable for explicit whitelisting.
- **R-ELOQUENT-004** SHOULD: Use $casts property to define attribute type casting (e.g., 'is_active' => 'boolean', 'metadata' => 'array', 'published_at' => 'datetime').
- **R-ELOQUENT-005** SHOULD: Define relationships using Eloquent methods (hasMany, belongsTo, belongsToMany, morphMany, etc.) with proper return type hints.
- **R-ELOQUENT-006** SHOULD: Use query scopes (scopeActive, scopeRecent, etc.) for reusable query logic specific to the model.
- **R-ELOQUENT-007** SHOULD: Leverage model events (creating, created, updating, updated, deleting, deleted) for cross-cutting concerns like logging or cache invalidation.
- **R-ELOQUENT-008** MUST: Use eager loading (with() method) to prevent N+1 query problems when accessing relationships.
- **R-ELOQUENT-009** SHOULD: Consider using API resources or transformers for serialization rather than exposing raw model attributes.
- **R-ELOQUENT-010** MUST: Place business logic in service classes or domain services, not in model classes, to maintain single responsibility principle.

### Verify

```bash
# Count model classes extending Eloquent Model
grep -r "extends Model" app/Models/ | wc -l

# Find model files missing Eloquent Model use statement
find app/Models -type f -name '*.php' -exec grep -L 'use Illuminate\\Database\\Eloquent\\Model' {} \;

# Display model structure summary
php artisan model:show --all 2>&1 | grep -E '(class|table)' | head -20

# Verify all models have fillable or guarded properties
grep -r "\$fillable\|\$guarded" app/Models/ | wc -l

# Check for N+1 query patterns (missing eager loading)
grep -r "->get()" app/Models/ | grep -v "with(" | head -10
```

**Accept when:**
- All model files in app/Models directory extend Illuminate\Database\Eloquent\Model
- Each model class corresponds to a database table and follows Laravel naming conventions (singular, PascalCase)
- Models define appropriate fillable/guarded properties for mass assignment protection
- Models define appropriate casts for type safety
- Relationships between entities are defined using Eloquent relationship methods with proper return type hints
- Query scopes are used for reusable query logic specific to the model
- No raw SQL queries exist where Eloquent could reasonably be used instead
- Eager loading (with() method) is used to prevent N+1 query problems
- Business logic is placed in service classes or domain services, not in model classes
