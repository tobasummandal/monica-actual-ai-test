<rule_activation id="4a32e367-d695-4f9c-a7f7-4940cdff5890" title="Use Laravel Hash Facade for Password Credential Storage: Password Hashing Occur" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in Laravel authentication workflows, service layers, and Fortify action classes.
</rule_activation>

### Rules

- **R-HASH-001** MUST: Password hashing MUST occur in service layer classes or Fortify action classes, never in controllers or views.
- **R-HASH-002** MUST: Always use `Hash::make($password)` when storing passwords in service classes like CreateAccount or AcceptInvitation.
- **R-HASH-003** MUST: Use `Hash::check($plaintext, $hashedValue)` for password verification during authentication.
- **R-HASH-004** MUST: No direct `password_hash()` calls permitted in application code; use Laravel Hash facade exclusively.
- **R-HASH-005** MUST: Verify `config/hashing.php` is configured with bcrypt or argon2id driver before deployment.
- **R-HASH-006** SHOULD: Use `Hash::fake()` in test environments to avoid expensive hashing operations and speed up test execution.
- **R-HASH-007** SHOULD: Consider implementing password rehashing on successful login to automatically upgrade legacy hashes when algorithm configuration changes.

### Verify

```bash
# Count Hash::make usage across authentication files
grep -r "Hash::make" app/ --include="*.php" | wc -l

# Verify no direct password_hash usage found
grep -r "password_hash" app/ --include="*.php" || echo "No direct password_hash usage found (good)"

# Verify no plain-text password assignments
grep -r "'password'.*=>.*\$" app/ --include="*.php" | grep -v "Hash::make" | grep -v "bcrypt" || echo "No plain-text password assignments found (good)"

# Check hashing driver configuration
php artisan tinker --execute="echo config('hashing.driver');"
```

**Accept when:**
- All password storage operations use `Hash::make()` as verified by grep showing consistent usage across authentication files
- No direct `password_hash()` calls found in application code (framework usage only)
- Hash facade configuration is properly set in `config/hashing.php` with bcrypt or argon2id driver
- Test suite includes verification that passwords are hashed before database storage
- Password hashing occurs exclusively in service layer classes or Fortify action classes, never in controllers or views
