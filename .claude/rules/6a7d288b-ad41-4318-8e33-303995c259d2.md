These rules are ALWAYS ACTIVE for all files matching `**/*`.
</rule_activation>

### Rules

- **R-HTTP-001** MAY: Projects MAY implement custom HTTP client wrappers for domain-specific requirements while maintaining the underlying library usage.

### Verify

```bash
# Verify Socialite library usage in OAuth flows
grep -r "use.*Socialite" app/ --include="*.php" | wc -l

# Verify Sabre DAV/VObject libraries for DAV protocol and vCard/vCalendar
grep -r "use.*Sabre" app/ --include="*.php" | wc -l

# Verify no raw cURL or socket implementations in external API code
grep -r "curl_exec\|fsockopen" app/ --include="*.php" | wc -l
```

**Accept when:**
- Socialite library usage is detected in OAuth authentication flows
- Sabre DAV/VObject libraries are used for DAV protocol and vCard/vCalendar operations
- No raw cURL or socket implementations are found in new external API integration code
- Service classes encapsulate HTTP client library usage with clear domain interfaces
- HTTP client library usage is wrapped in service classes (e.g., WikipediaHelper, DavClient)
- HTTP clients are configured with appropriate timeouts, retry policies, and error handling strategies
- Dependency injection is used to provide HTTP client instances for testability
- Authentication patterns are documented for each integration type (OAuth, Basic Auth, API keys)
- Logging and monitoring are implemented for external API calls

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated code review checks MUST scan for raw HTTP implementation patterns (curl_exec, fsockopen). Dependency analysis MUST ensure approved HTTP client libraries are present in composer.json. Manual code review MUST focus on external API integration patterns and library usage. Unit test coverage requirements MUST be met for service classes wrapping external API calls. CI pipeline MUST fail if raw HTTP implementations are detected in new code without documented exceptions.
</enforcement>
