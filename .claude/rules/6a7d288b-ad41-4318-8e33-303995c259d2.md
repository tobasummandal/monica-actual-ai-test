<rule_activation id="6a7d288b-ad41-4318-8e33-303995c259d2" title="Adopt HTTP Client Libraries for External API Integration: Projects Implement Custom" applies_to="**/*">
These rules apply to all external API integration code including OAuth flows, WebDAV/CalDAV/CardDAV, REST APIs, and vCard/vCalendar operations.

**In scope:**
- All outbound HTTP/HTTPS requests to external APIs and services
- OAuth provider integrations (Google, Facebook, GitHub, etc.)
- WebDAV, CalDAV, and CardDAV protocol communications
- Third-party REST API consumption (Wikipedia, documentation services, etc.)
- vCard and vCalendar data import/export operations

**Out of scope:**
- Internal service-to-service communication within the same application
- Database connections and queries
- File system operations
- Message queue or event bus communications
- WebSocket connections (unless using HTTP upgrade mechanism)

**Exceptions:**
- EXC-001: Legacy code maintenance where refactoring risk exceeds benefit
- EXC-002: Performance-critical scenarios where library overhead is demonstrably prohibitive (requires benchmarking)
</rule_activation>

### Rules

**Note:** This ADR does not contain explicit R-PREFIX-### rule identifiers. The following rules are synthesized from the Policy Block and Decision sections:

- **R-HTTP-001** MUST: Use established HTTP client libraries (Socialite for OAuth, Sabre DAV/VObject for DAV protocols and vCard/vCalendar) for external API integration.

- **R-HTTP-002** SHOULD: Encapsulate HTTP client library usage in service classes (e.g., WikipediaHelper, DavClient) to provide domain-specific interfaces.

- **R-HTTP-003** MAY: Projects MAY implement custom HTTP client wrappers for domain-specific requirements while maintaining the underlying library usage.

- **R-HTTP-004** MUST NOT: Use raw cURL (curl_exec) or socket (fsockopen) implementations for external API integration without documented exception approval (EXC-001 or EXC-002).

- **R-HTTP-005** MUST: Configure HTTP clients with appropriate timeouts, retry policies, and error handling strategies based on service reliability requirements.

- **R-HTTP-006** MUST: Use dependency injection to provide HTTP client instances, enabling mocking in unit tests and configuration flexibility.

### Verify

```bash
# Verify Socialite library usage for OAuth
grep -r "use.*Socialite" app/ --include="*.php" | wc -l

# Verify Sabre library usage for DAV/vCard/vCalendar
grep -r "use.*Sabre" app/ --include="*.php" | wc -l

# Check for raw cURL or socket implementations (should be zero or have documented exceptions)
grep -r "curl_exec\|fsockopen" app/ --include="*.php" | wc -l
```

**Accept when:**
- Socialite library usage is detected in OAuth authentication flows
- Sabre DAV/VObject libraries are used for DAV protocol and vCard/vCalendar operations
- No raw cURL or socket implementations are found in new external API integration code
- Service classes encapsulate HTTP client library usage with clear domain interfaces

<enforcement>
Claude Code MUST verify HTTP client library usage when working with external API integration code. CI pipeline fails if raw HTTP implementations are detected in new code without documented exceptions. Exception requests require performance benchmarks or technical justification submitted to Technical Lead with documented rationale.
</enforcement>
