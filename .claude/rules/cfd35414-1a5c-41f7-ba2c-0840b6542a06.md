<rule_activation id="cfd35414-1a5c-41f7-ba2c-0840b6542a06" title="Organize Domain Logic Using Domain-Driven Design Bounded Contexts: Service Classes Encapsulate" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in domain-organized codebases following bounded context patterns.
</rule_activation>

### Rules

- **R-DDD-001** MUST: Service classes MUST encapsulate single business operations with clear, action-oriented names (e.g., RemoveContactFromPost, UpdateJournalMetric).
- **R-DDD-002** MUST: All controllers MUST be located in Web/Controllers subdirectories within their respective domains.
- **R-DDD-003** MUST: Service classes MUST be located in Services subdirectories and contain business logic separate from HTTP concerns.
- **R-DDD-004** SHOULD: Service classes SHOULD follow a command pattern with a single public execute() or handle() method that encapsulates the business operation.
- **R-DDD-005** SHOULD: Controllers SHOULD be thin adapters that validate input, call the appropriate service, and format the response.
- **R-DDD-006** SHOULD: Use dependency injection to provide services with their dependencies (repositories, external services) rather than instantiating them directly.
- **R-DDD-007** SHOULD: Consider using domain events to communicate between bounded contexts rather than direct service-to-service calls.
- **R-DDD-008** MAY: Identify truly shared concerns and extract them to a Shared or Common namespace; use dependency inversion for cross-domain communication.

### Verify

```bash
# Verify all controllers are in Web/Controllers subdirectories
find app/Domains -type f -name '*Controller.php' | xargs grep -L 'namespace.*\\Web\\Controllers' | wc -l | grep -q '^0$'

# Count service classes in Services subdirectories
find app/Domains -type f -name '*Service.php' -path '*/Services/*' | wc -l

# Verify no controllers exist outside Web/Controllers namespaces
grep -r 'class.*Controller' app/Domains --include='*.php' | grep -v 'namespace.*\\Web\\Controllers' | wc -l | grep -q '^0$'
```

**Accept when:**
- All controllers are located in Web/Controllers subdirectories within their respective domains
- Service classes are located in Services subdirectories and contain business logic separate from HTTP concerns
- New features added to the codebase follow the domain structure pattern with at least 95% compliance
- Code review checklist includes verification of proper domain organization
- No controllers exist outside domain-specific Web/Controllers namespaces
- Service classes use action-oriented naming conventions

<enforcement>
Claude Code MUST verify domain organization compliance before approving PHP files. Violations of R-DDD-001, R-DDD-002, and R-DDD-003 are blocking. Code review feedback MUST require refactoring to comply with domain structure. CI pipeline checks MUST fail if files are placed outside the domain structure.
</enforcement>
