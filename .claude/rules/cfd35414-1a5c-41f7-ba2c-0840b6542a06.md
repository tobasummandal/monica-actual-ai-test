<rule_activation id="cfd35414-1a5c-41f7-ba2c-0840b6542a06" title="Organize Domain Logic Using Domain-Driven Design Bounded Contexts: Service Classes Encapsulate" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase. Service classes MUST encapsulate single business operations within domain-specific bounded contexts.
</rule_activation>

### Rules

- **R-DDD-001** MUST: Service classes MUST encapsulate single business operations with clear, action-oriented names (e.g., RemoveContactFromPost, UpdateJournalMetric).
- **R-DDD-002** SHOULD: Service classes should follow a command pattern with a single public execute() or handle() method that encapsulates the business operation.
- **R-DDD-003** SHOULD: Use dependency injection to provide services with their dependencies (repositories, external services) rather than instantiating them directly.
- **R-DDD-004** SHOULD: Controllers should be thin adapters that validate input, call the appropriate service, and format the response.
- **R-DDD-005** SHOULD: Consider using domain events to communicate between bounded contexts rather than direct service-to-service calls.
- **R-DDD-006** MUST: When creating a new feature, first identify which domain it belongs to; if no suitable domain exists, consult with the architecture team before creating a new one.

### Verify

```bash
# Verify all controllers are in Web/Controllers subdirectories within their domains
find app/Domains -type f -name '*Controller.php' | xargs grep -L 'namespace.*\\Web\\Controllers' | wc -l | grep -q '^0$'

# Count service classes in Services subdirectories
find app/Domains -type f -name '*Service.php' -path '*/Services/*' | wc -l

# Verify no controllers exist outside Web/Controllers namespace
grep -r 'class.*Controller' app/Domains --include='*.php' | grep -v 'namespace.*\\Web\\Controllers' | wc -l | grep -q '^0$'
```

**Accept when:**
- All controllers are located in Web/Controllers subdirectories within their respective domains
- Service classes are located in Services subdirectories and contain business logic separate from HTTP concerns
- New features added to the codebase follow the domain structure pattern with at least 95% compliance
- Code review checklist includes verification of proper domain organization

<enforcement>
Claude Code MUST NOT skip or defer verification. All controllers MUST be in Web/Controllers subdirectories, and service classes MUST be in Services subdirectories with clear, action-oriented names.
</enforcement>
