<rule_activation id="3d935770-36c9-4777-988b-223bf3e65d48" title="Organize Test Files by Domain and Feature Modules: Test Files Maintain" applies_to="tests/Unit/Domains/**/*">
These rules are ALWAYS ACTIVE for all test files under tests/Unit/Domains/ and related domain-driven test organization.
</rule_activation>

### Rules

- **R-ORG-001** MUST: Test files MUST maintain the same subdirectory structure within feature modules as production code (e.g., Services/, Web/ViewHelpers/, Api/Controllers/)
- **R-ORG-002** MUST: Test files MUST be located under tests/Unit/Domains/ with subdirectories matching production domain structure
- **R-ORG-003** MUST: Test file names MUST consistently append 'Test' suffix to production class names
- **R-ORG-004** MUST: Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) MUST be represented as subdirectories within their respective domains
- **R-ORG-005** MUST: Test file paths MUST mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- **R-ORG-006** SHOULD: Establish naming conventions for domain and module directories that are concise yet descriptive to minimize path length
- **R-ORG-007** SHOULD: Configure CI/CD pipelines to support domain-based test execution using path filters
- **R-ORG-008** MAY: Shared test utilities or base test classes that serve multiple domains may be organized outside strict domain hierarchy (EXC-001)
- **R-ORG-009** MAY: Legacy test files may be organized outside domain structure during migration period (EXC-002)

### Verify

```bash
# Verify test files exist under tests/Unit/Domains/ with correct structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify test namespace conventions
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are represented as subdirectories
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- CI/CD pipeline checks verify test file locations match production code structure
- Code review checklist confirms new tests follow domain organization pattern
- Automated linting rules validate test file naming and location conventions
- Pre-commit hooks verify test files are placed in correct domain directories

<enforcement>
Claude Code MUST verify test file organization against domain structure before accepting test file changes. Violations MUST be flagged and corrected. CI pipeline failures due to test organization MUST NOT be overridden without documented exception approval.
