<rule_activation id="3d935770-36c9-4777-988b-223bf3e65d48" title="Organize Test Files by Domain and Feature Modules: Test Files Maintain" applies_to="tests/**/*">
These rules are ALWAYS ACTIVE for all test files. Test files MUST maintain the same subdirectory structure within feature modules as production code, following domain-driven design principles.
</rule_activation>

### Rules

- **R-TEST-001** MUST: Test files MUST maintain the same subdirectory structure within feature modules as production code (e.g., Services/, Web/ViewHelpers/, Api/Controllers/)
- **R-TEST-002** MUST: Test files MUST be organized under tests/Unit/Domains/ with subdirectories matching production domain structure
- **R-TEST-003** MUST: Test file names MUST consistently append 'Test' suffix to production class names
- **R-TEST-004** MUST: Test file paths MUST mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- **R-TEST-005** MUST: Domain feature modules (e.g., ManageTemplates, ManageUserPreferences, ManageUsers) MUST be represented as subdirectories within their respective domains

### Exceptions

- **EXC-001**: Shared test utilities or base test classes that serve multiple domains
- **EXC-002**: Migration period for legacy tests being refactored into domain structure

### Verify

```bash
# Verify test files exist in domain structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify namespace conventions match domain structure
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify feature modules are present in Settings domain
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix

<enforcement>
Claude Code MUST NOT skip or defer verification. CI pipeline checks MUST verify test file locations match production code structure. Code review MUST confirm new tests follow domain organization pattern. Pre-commit hooks MUST verify test files are placed in correct domain directories.
</enforcement>
