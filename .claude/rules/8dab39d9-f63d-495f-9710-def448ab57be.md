<rule_activation id="8dab39d9-f63d-495f-9710-def448ab57be" title="Standardize Logging with Laravel Log Facade in DAV and Job Components: Console Commands Performing" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in DAV and job components, including:
- DAV backend implementations (CalDAV/CardDAV)
- Background jobs in Contact/Dav and Contact/DavClient domains
- DavClient service utilities and synchronization services
- Console commands for address book and application setup
- Any component performing external DAV server communication

Exceptions:
- EXC-001: Performance-critical hot paths where logging overhead is measured and documented as unacceptable
- EXC-002: Temporary debugging code using dd(), dump(), or var_dump() during active development
</rule_activation>

### Rules

- **R-LOG-001** SHOULD: Console commands performing setup or subscription operations SHOULD log progress milestones and completion status for operational visibility
- **R-LOG-002** MUST: Use Laravel's Log facade (`Illuminate\Support\Facades\Log`) for all logging in DAV and job components
- **R-LOG-003** MUST: Import the Log facade at the top of each class: `use Illuminate\Support\Facades\Log;`
- **R-LOG-004** MUST: Use appropriate log levels: `Log::debug()` for detailed tracing, `Log::info()` for significant events, `Log::warning()` for recoverable issues, `Log::error()` for failures requiring attention
- **R-LOG-005** SHOULD: Include structured context as second parameter: `Log::info('VCard synchronized', ['contact_id' => $id, 'addressbook_id' => $addressbookId])`
- **R-LOG-006** SHOULD: For DAV operations, consider using a dedicated channel configured in config/logging.php: `Log::channel('dav')->info('Sync started')`
- **R-LOG-007** MUST: In job classes, log at the beginning and end of handle() method with job-specific context to enable job execution tracking
- **R-LOG-008** MUST NOT: Log in tight loops - consider sampling or aggregating log messages for bulk operations
- **R-LOG-009** MUST NOT: Log sensitive data (authentication tokens, personal contact information) without appropriate redaction

### Verify

```bash
# Check for Log facade imports in DAV and console command files
grep -r "use Illuminate\\\\Support\\\\Facades\\\\Log" app/Domains/Contact/Dav* app/Console/Commands/ | wc -l

# Check for Log method calls with appropriate levels
grep -r "Log::" app/Domains/Contact/Dav* app/Console/Commands/ | grep -E "(debug|info|warning|error)" | wc -l

# Verify Log facade is available in the application
php artisan tinker --execute="echo class_exists('Illuminate\\\\Support\\\\Facades\\\\Log') ? 'PASS' : 'FAIL';"
```

**Accept when:**
- Log facade import statements are present in all DAV backend classes, DavClient services, and relevant console commands
- Log method calls (debug/info/warning/error) are present in job handle() methods and synchronization service methods
- Laravel's Log facade class is available and properly configured in the application
