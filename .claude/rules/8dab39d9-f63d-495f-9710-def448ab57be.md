<rule_activation id="8dab39d9-f63d-495f-9710-def448ab57be" title="Standardize Logging with Laravel Log Facade in DAV and Job Components: Console Commands Performing" applies_to="app/Domains/Contact/Dav* app/Console/Commands/**/*.php">
These rules are ALWAYS ACTIVE for all DAV backend implementations, background jobs in Contact/Dav and Contact/DavClient domains, DavClient service utilities, synchronization services, and console commands for address book and application setup.
</rule_activation>

### Rules

- **R-DAV-LOG-001** SHOULD: Console commands performing setup or subscription operations SHOULD log progress milestones and completion status for operational visibility.
- **R-DAV-LOG-002** MUST: Import the Log facade at the top of each class: `use Illuminate\Support\Facades\Log;`
- **R-DAV-LOG-003** SHOULD: Use appropriate log levels: `Log::debug()` for detailed tracing, `Log::info()` for significant events, `Log::warning()` for recoverable issues, `Log::error()` for failures requiring attention.
- **R-DAV-LOG-004** SHOULD: Include structured context as second parameter: `Log::info('VCard synchronized', ['contact_id' => $id, 'addressbook_id' => $addressbookId])`
- **R-DAV-LOG-005** SHOULD: For DAV operations, consider using a dedicated channel configured in config/logging.php: `Log::channel('dav')->info('Sync started')`
- **R-DAV-LOG-006** SHOULD: In job classes, log at the beginning and end of handle() method with job-specific context to enable job execution tracking.
- **R-DAV-LOG-007** SHOULD: Avoid logging in tight loops - consider sampling or aggregating log messages for bulk operations.

### Verify

```bash
# Check Log facade imports in DAV and console command files
grep -r "use Illuminate\\Support\\Facades\\Log" app/Domains/Contact/Dav* app/Console/Commands/ | wc -l

# Check Log method calls with appropriate levels
grep -r "Log::" app/Domains/Contact/Dav* app/Console/Commands/ | grep -E "(debug|info|warning|error)" | wc -l

# Verify Log facade class availability
php artisan tinker --execute="echo class_exists('Illuminate\\Support\\Facades\\Log') ? 'PASS' : 'FAIL';"
```

**Accept when:**
- Log facade import statements are present in all DAV backend classes, DavClient services, and relevant console commands
- Log method calls (debug/info/warning/error) are present in job handle() methods and synchronization service methods
- Laravel's Log facade class is available and properly configured in the application
- Console commands performing setup or subscription operations include progress milestone and completion status logging
- Structured context data is included in log calls where applicable
