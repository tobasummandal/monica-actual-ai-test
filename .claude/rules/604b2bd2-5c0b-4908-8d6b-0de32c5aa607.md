<rule_activation id="604b2bd2-5c0b-4908-8d6b-0de32c5aa607" title="Adopt Domain-Driven Service Layer Architecture for Business Operations: Web Controllers Delegate" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in the application. Web controllers MUST delegate business logic execution to domain service classes rather than implementing logic directly. This enforces domain-driven design principles with clear separation between presentation and business logic layers.
</rule_activation>

### Rules

- **R-DDD-001** MUST: Web controllers MUST delegate business logic execution to domain service classes rather than implementing logic directly.

### Verify

```bash
# Count domain service classes
find app/Domains -type f -name '*.php' -path '*/Services/*' | wc -l

# Verify service classes use correct namespace pattern
grep -r 'namespace.*Domains.*Services' app/Domains --include='*.php' | wc -l

# Count controllers in domain structure
find app/Domains -type f -name '*Controller.php' -path '*/Web/Controllers/*' | wc -l
```

**Accept when:**
- Service classes exist in `app/Domains/{Domain}/{Feature}/Services/` directories
- Controllers exist in `app/Domains/{Domain}/{Feature}/Web/Controllers/` directories
- At least 3 domain service classes follow the established pattern
- Controllers contain only request validation, service invocation, and response formatting
- Business logic is isolated in service classes, not in controller methods

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated static analysis checking namespace and directory structure compliance is required. Code review process must verify business logic is in service classes, not controllers. CI pipeline checks for proper file organization using grep and find commands are mandatory.
</enforcement>
