<rule_activation id="604b2bd2-5c0b-4908-8d6b-0de32c5aa607" title="Adopt Domain-Driven Service Layer Architecture for Business Operations: Web Controllers Delegate" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files to enforce domain-driven service layer architecture where web controllers delegate business logic to domain service classes.
</rule_activation>

### Rules

- **R-DDD-001** MUST: Web controllers MUST delegate business logic execution to domain service classes rather than implementing logic directly.
- **R-DDD-002** MUST: Service classes MUST be placed in `app/Domains/{Domain}/{Feature}/Services/` directories.
- **R-DDD-003** MUST: Controllers MUST be placed in `app/Domains/{Domain}/{Feature}/Web/Controllers/` directories.
- **R-DDD-004** MUST: Service classes MUST be named after the business operation they perform (e.g., CreateAccount, AcceptInvitation).
- **R-DDD-005** MUST: Controllers MUST be kept thin by limiting them to request validation, service invocation, and response formatting.
- **R-DDD-006** SHOULD: Use dependency injection to provide services to controllers, avoiding direct instantiation.
- **R-DDD-007** SHOULD: Create domain folders under `app/Domains/` with subfolders for each feature area (e.g., CreateAccount, CancelAccount).

**In scope:**
- All business logic for account management operations
- User invitation and acceptance workflows
- Domain-specific service classes handling core business rules
- Web controllers that serve as entry points for HTTP requests

**Out of scope:**
- Infrastructure-level services (database, caching, queuing)
- Third-party API integrations that don't represent core business logic
- Utility classes and helpers that provide cross-cutting concerns
- Framework-level middleware and request handling

### Verify

```bash
# Check that service classes exist in correct domain directories
find app/Domains -type f -name '*.php' -path '*/Services/*' | wc -l

# Verify service classes use proper namespace convention
grep -r 'namespace.*Domains.*Services' app/Domains --include='*.php' | wc -l

# Check that controllers exist in correct web directory structure
find app/Domains -type f -name '*Controller.php' -path '*/Web/Controllers/*' | wc -l
```

**Accept when:**
- Service classes exist in `app/Domains/{Domain}/{Feature}/Services/` directories
- Controllers exist in `app/Domains/{Domain}/{Feature}/Web/Controllers/` directories
- At least 3 domain service classes follow the established pattern (matching detected evidence)
- Controllers delegate business logic to service classes rather than implementing it directly
- Service classes are properly namespaced within domain boundaries

<enforcement>
Verification is MANDATORY.
- Automated static analysis checks namespace and directory structure compliance
- Code review process verifies business logic is in service classes, not controllers
- CI pipeline checks for proper file organization using grep and find commands
- CI build fails if controllers contain business logic exceeding complexity thresholds
- Pull requests are blocked if service classes are not placed in correct domain directories
- Architecture review required for new domains or significant deviations from pattern

**Exception process:**
- Document exception rationale in ADR amendment or inline code comments
- Obtain approval from tech lead or architecture review board
- Add technical debt ticket if exception is temporary workaround
</enforcement>
