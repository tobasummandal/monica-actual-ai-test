<rule_activation id="5e69175d-a2b5-4801-a227-1c3951c031e6" title="Standardize PHPUnit Test Structure with setUp and Trait-Based Helpers: Test File Naming" applies_to="tests/**/*Test.php">
These rules are ALWAYS ACTIVE for all PHPUnit test files matching `tests/**/*Test.php`.

This ADR establishes standardized test structure conventions for PHPUnit tests, including file naming, class structure, setUp() methods, and trait-based helpers. The pattern ensures consistent, maintainable unit tests across the codebase.

**Scope:**
- All PHPUnit unit tests in the tests/Unit/ directory
- Model test classes testing domain entities
- Helper test classes testing utility functions
- Test initialization and setup logic
- Shared testing traits and utilities
</rule_activation>

### Rules

- **R-PHPUNIT-001** SHOULD: Test file naming SHOULD follow the pattern {ClassName}Test.php matching the class under test
- **R-PHPUNIT-002** SHOULD: Test files in tests/Unit/ SHOULD contain a setUp() method or explicitly document why it's not needed
- **R-PHPUNIT-003** MUST: Test classes MUST extend PHPUnit\Framework\TestCase or a documented base test class
- **R-PHPUNIT-004** SHOULD: Tests SHOULD be organized in directories mirroring the application structure

### Verify

```bash
# Check for test files missing setUp() method
find tests/Unit -name '*Test.php' -type f | xargs grep -L 'function setUp' | wc -l

# Check for test classes not extending PHPUnit\Framework\TestCase
grep -r 'class.*Test extends' tests/Unit/ | grep -v 'PHPUnit\\Framework\\TestCase' | wc -l

# Check for non-test PHP files in test directories
find tests/Unit -type f -name '*.php' ! -name '*Test.php' | wc -l
```

**Accept when:**
- All test files in tests/Unit/ contain a setUp() method or explicitly document why it's not needed
- All test classes extend PHPUnit\Framework\TestCase or a documented base test class
- Test file names match the pattern {ClassName}Test.php and are organized in directories mirroring the application structure
- CI pipeline executes PHPUnit test suite successfully

### Rationale

The pattern appears in 18 files with 82.74% confidence, indicating a well-established testing convention. Standardized test structure improves maintainability, promotes DRY principles through setUp() and traits, and supports reliable CI/CD automation.

### Implementation Guidance

- Create or document standard test traits (e.g., DatabaseTransactions, RefreshDatabase) for common setup patterns
- Use PHPUnit's @before and @after annotations for additional lifecycle hooks when needed
- Leverage Laravel's testing utilities such as factories, seeders, and database transactions
- Keep traits focused on single responsibilities and stateless where possible
- Document trait behavior clearly to avoid hidden coupling between tests
