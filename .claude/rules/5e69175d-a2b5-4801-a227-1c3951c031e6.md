<rule_activation id="5e69175d-a2b5-4801-a227-1c3951c031e6" title="Standardize PHPUnit Test Structure with setUp and Trait-Based Helpers: Test File Naming" applies_to="tests/Unit/**/*.php">
These rules are ALWAYS ACTIVE for all PHPUnit unit test files in the tests/Unit/ directory.
</rule_activation>

### Rules

- **R-PHPUNIT-001** SHOULD: Test file naming SHOULD follow the pattern {ClassName}Test.php matching the class under test.
- **R-PHPUNIT-002** SHOULD: Test classes SHOULD extend PHPUnit\Framework\TestCase or a documented base test class.
- **R-PHPUNIT-003** SHOULD: Test classes SHOULD implement a setUp() method to initialize test dependencies and shared state.
- **R-PHPUNIT-004** SHOULD: Shared test initialization logic SHOULD be extracted into reusable traits to promote DRY principles.
- **R-PHPUNIT-005** SHOULD: Test directory structure SHOULD mirror the application structure (Models, Helpers, etc.).
- **R-PHPUNIT-006** MAY: Use PHPUnit's @before and @after annotations for additional lifecycle hooks when setUp() and tearDown() are insufficient.

### Verify

```bash
# Find test files without setUp() method
find tests/Unit -name '*Test.php' -type f | xargs grep -L 'function setUp' | wc -l

# Verify test classes extend proper base class
grep -r 'class.*Test extends' tests/Unit/ | grep -v 'PHPUnit\\Framework\\TestCase' | wc -l

# Find PHP files not following *Test.php naming convention
find tests/Unit -type f -name '*.php' ! -name '*Test.php' | wc -l
```

**Accept when:**
- All test files in tests/Unit/ follow the {ClassName}Test.php naming pattern
- All test classes extend PHPUnit\Framework\TestCase or a documented base test class
- All test classes contain a setUp() method or explicitly document why it is not needed
- Test directory structure mirrors the application structure (Models, Helpers, etc.)
- Shared initialization logic is extracted into reusable traits
- CI pipeline executes PHPUnit test suite successfully with no test errors

<enforcement>
Claude Code MUST NOT skip or defer verification of test file naming, structure, and setUp() method presence. All violations MUST be flagged during code review and corrected before merge.
</enforcement>
