<rule_activation id="61ca5e06-d3c7-4126-8963-960db57c42ba" title="Adopt Quality Gates Pattern for Domain Service Layer Validation: View Helpers That" applies_to="**/*">
These rules are ALWAYS ACTIVE for all domain service implementations, view helpers, and controller methods that process user input or external data. Quality gates MUST be implemented at service boundaries.
</rule_activation>

### Rules

- **R-QG-001** MUST: View helpers that transform domain data for presentation MUST validate the completeness and structure of input data before transformation.
- **R-QG-002** MUST: All domain service classes in `app/Domains/*/Services/` implement quality gates for methods accepting external input.
- **R-QG-003** MUST: All view helper classes in `app/Domains/*/Web/ViewHelpers/` validate input before data transformation.
- **R-QG-004** MUST: All controller methods in `app/Domains/*/Web/Controllers/` that handle external requests implement quality gates.
- **R-QG-005** MUST: Synchronization and integration services that process external data sources implement quality gates.
- **R-QG-006** MUST: Command and query handlers that accept user input or cross-domain data implement quality gates.
- **R-QG-007** SHOULD: Use descriptive exception types (e.g., InvalidJournalDataException, MalformedWebhookPayloadException) to clearly communicate validation failures.
- **R-QG-008** SHOULD: Extract common validation patterns into reusable validator classes, traits, or value objects to prevent duplication.
- **R-QG-009** SHOULD: Document validation rules in method docblocks to make expectations explicit for API consumers and maintainers.

### Verify

```bash
# Count total service methods across domains
grep -r 'function.*(' app/Domains/*/Services/ app/Domains/*/Web/ViewHelpers/ app/Domains/*/Web/Controllers/ | wc -l

# Count validation statements in service layer
grep -r 'throw new.*Exception\|if.*empty\|if.*null\|assert\|validate' app/Domains/*/Services/ app/Domains/*/Web/ViewHelpers/ | wc -l

# Run validation tests
php artisan test --filter=ValidationTest --testsuite=Unit
```

**Accept when:**
- Ratio of validation statements to service methods is at least 1:1, indicating each method has at least one quality gate check
- All new service methods in code review demonstrate explicit validation of input parameters before business logic execution
- Unit tests exist for validation failure scenarios in addition to happy path tests
- Static analysis tools detect no service methods lacking validation logic in CI pipeline

<enforcement>
Claude Code MUST verify quality gate implementation for all service methods accepting external input. Code review rejection is required for new services lacking quality gates. Violations trigger CI pipeline warnings and require architecture review for exceptions.
</enforcement>
