<rule_activation id="c60e5ecb-fb56-48c2-81be-bf016a5dfe70" title="Adopt Modular Architecture with Factory-Based Component Generation: Module Initialization Logic" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the application codebase to enforce modular architecture with factory-based component generation and centralized module initialization logic.
</rule_activation>

### Rules

- **R-MOD-001** SHOULD: Module initialization logic SHOULD be encapsulated in dedicated setup commands (e.g., SetupApplication, SetupDocumentation) rather than scattered across the codebase.
- **R-MOD-002** SHOULD: All PHP files in app/Domains directory SHOULD use the correct App\Domains namespace hierarchy.
- **R-MOD-003** SHOULD: All factory classes in database/factories SHOULD extend the framework's base Factory class.
- **R-MOD-004** SHOULD: All setup commands in app/Console/Commands SHOULD extend the framework's Command class and follow naming conventions.
- **R-MOD-005** SHOULD: Domain names SHOULD be singular nouns (Contact, not Contacts).
- **R-MOD-006** SHOULD: Subdomain names SHOULD describe the capability (ManageContact).
- **R-MOD-007** SHOULD: Layer names SHOULD be standard (Web, Console, Database).
- **R-MOD-008** SHOULD: Factory classes SHOULD be updated as part of definition of done for model changes.
- **R-MOD-009** SHOULD: Module dependencies SHOULD be documented in a central registry or dependency graph to prevent circular dependencies.

### Verify

```bash
# Verify all PHP files in app/Domains use correct namespace
find app/Domains -type f -name '*.php' | xargs grep -L 'namespace App\\Domains' | wc -l | grep -q '^0$'

# Verify all factory classes extend base Factory class
find database/factories -type f -name '*Factory.php' | xargs grep -c 'extends Factory' | grep -v ':0'

# Verify all setup commands extend Command class
find app/Console/Commands -type f -name 'Setup*.php' | xargs grep -c 'extends Command' | grep -v ':0'
```

**Accept when:**
- All PHP files in app/Domains directory use the correct App\Domains namespace hierarchy
- All factory classes in database/factories extend the framework's base Factory class
- All setup commands in app/Console/Commands extend the framework's Command class and follow naming conventions
- Module structure compliance is verified through code review checklist
- Namespace conventions pass automated CI pipeline checks using PHPStan or Psalm

<enforcement>
Claude Code MUST NOT skip or defer verification. All namespace conventions, factory class inheritance, and setup command structure MUST be validated before accepting code changes. CI pipeline MUST fail if violations are detected, blocking merge until compliance is achieved.
</enforcement>
