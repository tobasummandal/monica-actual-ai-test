<rule_activation id="4a7ac73e-3ee3-43bb-99ba-119d29bca2a7" title="Adopt Domain-Driven Controller Organization for Journal Management: Controller Naming Follow" applies_to="app/Domains/Vault/ManageJournals/Web/Controllers/**/*Controller.php">
These rules are ALWAYS ACTIVE for all web controllers within the Vault domain's ManageJournals bounded context.
</rule_activation>

### Rules

- **R-CTRL-001** SHOULD: Controller naming SHOULD follow the pattern {Entity}Controller or {Entity}{Concern}Controller (e.g., JournalController, PostPhotoController)

### Verify

```bash
# Verify controller files exist in correct location
find app/Domains/Vault/ManageJournals/Web/Controllers -name '*Controller.php' | wc -l

# Verify controller namespaces match directory structure
grep -r 'namespace App\\Domains\\Vault\\ManageJournals\\Web\\Controllers' app/Domains/Vault/ManageJournals/Web/Controllers/*.php | wc -l

# Verify routes reference correct controller namespace
php artisan route:list --path=journal --columns=Action | grep 'App\\Domains\\Vault\\ManageJournals\\Web\\Controllers'
```

**Accept when:**
- All controller files in the ManageJournals domain are located under app/Domains/Vault/ManageJournals/Web/Controllers
- Each controller has a single, clear responsibility corresponding to an entity or entity-concern combination
- Controller namespaces match their directory structure and follow the established pattern
- Route definitions correctly reference controllers using the domain-based namespace
- Controller names follow {Entity}Controller or {Entity}{Concern}Controller naming convention

<enforcement>
Claude Code MUST NOT skip or defer verification. All controllers must be validated against the naming pattern and directory structure before acceptance.
</enforcement>
