<rule_activation id="3b5d15bb-fbad-4257-ba58-11456d441ad3" title="Standardize External API Integration with DAV Protocol and DTO Pattern: External Integrations Implement" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API integrations including DAV, CardDAV, and CalDAV protocols, data transfer operations, resource import/export, permission validation, and backend interface implementations.
</rule_activation>

### Rules

- **R-EXT-001** SHOULD: External API integrations SHOULD implement logging capabilities using traits (e.g., Loggable) for consistent observability across API interactions.
- **R-EXT-002** MUST: All external API integrations use DTO classes for data transfer with at least one DTO per external entity type.
- **R-EXT-003** MUST: Protocol-specific operations are abstracted behind interface contracts with at least one concrete implementation.
- **R-EXT-004** MUST: Domain-specific exception types exist for common API failure scenarios (permission, compliance, limits) and are properly caught in controllers.
- **R-EXT-005** MUST: ViewHelper classes are present for domains that expose external APIs and are used in controller response preparation.
- **R-EXT-006** MUST: Define DTO classes before implementing concrete backend classes; use dependency injection to provide implementations to consumers.
- **R-EXT-007** MUST: Create domain-specific exception types in the appropriate domain namespace with descriptive names and error messages.
- **R-EXT-008** MUST: Add the Loggable trait to API client classes to ensure consistent logging of external API interactions.

### Verify

```bash
# Count DTO classes in external API integration paths
grep -r "class.*Dto" app/Domains/*/DavClient/Services/Utils/Model/ | wc -l

# Count backend interface definitions
grep -r "interface.*Backend" app/Domains/*/Dav/Web/Backend/ | wc -l

# Count domain-specific exception types
grep -r "class.*Exception extends" app/Domains/ | grep -E "(Permission|Compliant|Maximum)" | wc -l

# Count ViewHelper classes
find app/Domains -name "*ViewHelper.php" -type f | wc -l
```

**Accept when:**
- All external API integrations use DTO classes for data transfer with at least one DTO per external entity type
- Protocol-specific operations are abstracted behind interface contracts with at least one concrete implementation
- Domain-specific exception types exist for common API failure scenarios (permission, compliance, limits) and are properly caught in controllers
- ViewHelper classes are present for domains that expose external APIs and are used in controller response preparation
- All API client classes implement the Loggable trait for consistent observability

<enforcement>
Claude Code MUST NOT skip or defer verification. All external API integrations MUST comply with R-EXT-001 through R-EXT-008. Violations in new code are blocking until refactored. Critical violations (missing permission checks, generic exceptions) require immediate remediation before deployment.
</enforcement>
