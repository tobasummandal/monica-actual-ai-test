These rules are ALWAYS ACTIVE for all files in the codebase to ensure consistent unit testing practices using PHPUnit across domain-driven architecture.
</rule_activation>

### Rules

- **R-PHPUNIT-001** MUST: All unit tests MUST be written using PHPUnit as the testing framework.
- **R-PHPUNIT-002** MUST: All test files in tests/Unit/Domains/ MUST follow the {ClassName}Test.php naming convention.
- **R-PHPUNIT-003** MUST: Test directory structure MUST mirror the application domain hierarchy under tests/Unit/Domains/.
- **R-PHPUNIT-004** SHOULD: Unit tests SHOULD be written for service layer components in all domains.
- **R-PHPUNIT-005** SHOULD: Unit tests SHOULD be written for API controllers.
- **R-PHPUNIT-006** SHOULD: Unit tests SHOULD be written for web view helpers.
- **R-PHPUNIT-007** SHOULD: Tests SHOULD use PHPUnit data providers for testing multiple scenarios with the same test logic.
- **R-PHPUNIT-008** MAY: Temporary exceptions for legacy code without tests MAY be documented in technical debt backlog with approval from technical lead.

### Verify

```bash
# Count total test files following PHPUnit convention
find tests/Unit/Domains -name '*Test.php' -type f | wc -l

# Verify PHPUnit TestCase usage across test files
grep -r 'use PHPUnit\\Framework\\TestCase' tests/Unit/Domains/ | wc -l

# Execute PHPUnit test suite with test documentation output
vendor/bin/phpunit --testsuite=unit --testdox
```

**Accept when:**
- All test files in tests/Unit/Domains/ follow the {ClassName}Test.php naming convention
- PHPUnit test execution completes successfully with all tests passing
- Test directory structure mirrors the application domain hierarchy under tests/Unit/Domains/
- Code coverage reports are generated during CI builds
- CI/CD pipeline automated test execution passes on every commit
