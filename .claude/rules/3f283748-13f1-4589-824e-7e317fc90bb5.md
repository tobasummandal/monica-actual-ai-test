<rule_activation id="3f283748-13f1-4589-824e-7e317fc90bb5" title="Adopt Inertia.js for Server-Driven Single Page Application Rendering: Controllers Use Inertia" applies_to="**/Domains/Vault/ManageJournals/Web/Controllers/**/*.php">
These rules are ALWAYS ACTIVE for all web controllers in the ManageJournals domain and SHOULD be applied to new controller implementations across the application.

**In scope:**
- All web controllers in the Vault/ManageJournals domain
- New controller implementations that serve user-facing web interfaces
- Controllers that handle both GET and POST requests for interactive features
- View rendering logic in journal, photo, metric, slice-of-life, and post management

**Out of scope:**
- API controllers that serve mobile applications or third-party integrations
- Webhook endpoints that return JSON responses
- Administrative or internal tools that use traditional server-side rendering
- Legacy controllers outside the ManageJournals domain (until migrated)

**Exceptions:**
- EXC-001: A controller endpoint needs to return raw JSON for AJAX requests from non-Inertia components
- EXC-002: File downloads or binary responses are required
</rule_activation>

### Rules

- **R-INERTIA-001** MUST: Controllers in ManageJournals domain MUST use `Inertia::render()` for view responses.
- **R-INERTIA-002** MUST NOT: Controllers in ManageJournals domain MUST NOT use traditional `view()` calls except for documented exceptions (EXC-001, EXC-002).
- **R-INERTIA-003** SHOULD: Controllers SHOULD use Inertia's lazy loading for expensive data that is not immediately needed on page load.
- **R-INERTIA-004** SHOULD: Use Laravel resource classes to transform models into consistent prop structures.
- **R-INERTIA-005** SHOULD: Implement shared props (user data, flash messages, etc.) using Inertia middleware rather than repeating in each controller.
- **R-INERTIA-006** SHOULD: Document component naming convention (e.g., 'Journals/Index' maps to resources/js/Pages/Journals/Index.vue).
- **R-INERTIA-007** SHOULD: Use TypeScript interfaces to define prop shapes for better type safety between backend and frontend.

### Verify

```bash
# Count Inertia::render usage in ManageJournals controllers
grep -r "Inertia::render" app/Domains/Vault/ManageJournals/Web/Controllers/ | wc -l

# Count traditional view() calls (should be 0)
grep -r "return view(" app/Domains/Vault/ManageJournals/Web/Controllers/ | wc -l

# Verify journal routes are handled by controllers
php artisan route:list --path=journals --json | jq '[.[] | select(.action | contains("Controller"))] | length'
```

**Accept when:**
- All controllers in ManageJournals domain use `Inertia::render()` for view responses (verify command 1 shows expected count)
- No traditional `view()` calls exist in ManageJournals controllers (verify command 2 returns 0)
- All journal-related routes are handled by controllers using Inertia responses
- Code review confirms props are properly structured and lazy loading is used for expensive data
- Exceptions are documented with EXC-001 or EXC-002 references in controller comments

Claude Code MUST NOT skip or defer verification. CI pipeline fails if traditional view() calls are detected in ManageJournals controllers. Pull requests are blocked until Inertia patterns are correctly implemented. Violations in existing code trigger technical debt tickets for refactoring.
