<rule_activation id="264b9c0f-2304-4715-8066-d6511e408482" title="Enforce Authorization Checks at Controller Entry Points: Applications Use Framework" applies_to="**/*Controller.php">
These rules are ALWAYS ACTIVE for all controller implementations and service layer authorization enforcement points within the application codebase.
</rule_activation>

### Rules

- **R-AUTH-001** MAY: Applications MAY use framework-provided authorization middleware (e.g., Laravel policies, gates) to standardize enforcement patterns.
- **R-AUTH-002** MUST: All HTTP controller methods in web and API layers require authorization checks before executing business logic.
- **R-AUTH-003** MUST: Service layer methods that perform privileged operations or access sensitive data must include authorization enforcement.
- **R-AUTH-004** MUST: Domain service classes that can be invoked from multiple contexts (e.g., ImportVCalendar) must enforce authorization checks.
- **R-AUTH-005** MUST: RESTful API endpoints and GraphQL resolvers must include authorization verification at entry points.
- **R-AUTH-006** SHOULD: Use Laravel's built-in authorization features (policies and gates) to standardize authorization checks across controllers.
- **R-AUTH-007** SHOULD: Create base controller classes that enforce authorization check patterns and provide helper methods for common authorization scenarios.
- **R-AUTH-008** SHOULD: Document authorization requirements in controller method docblocks to make security expectations explicit.
- **R-AUTH-009** SHOULD: Implement request-scoped caching for authorization decisions to minimize performance impact of multiple checks.

### Verify

```bash
# Detect controller methods without authorization checks
grep -r "public function" app/Domains/*/Web/Controllers/ | grep -v "authorize\|policy\|gate" | head -20

# Find all controller files lacking authorization patterns
find app/Domains -name "*Controller.php" -exec grep -L "authorize\|policy\|can(" {} \;

# Run static analysis on controller layer
phpstan analyse --level=5 app/Domains/*/Web/Controllers/ --error-format=table
```

**Accept when:**
- All controller methods that access or modify resources include explicit authorization checks before business logic execution
- Static analysis tools report zero violations of authorization enforcement patterns in controller classes
- Code review checklist includes verification of authorization checks for all new controller methods
- Authorization checks are implemented at both controller and service layer boundaries for defense-in-depth
- Request-scoped caching is implemented for authorization decisions to minimize performance overhead

<enforcement>
Claude Code MUST NOT skip or defer verification of authorization enforcement patterns. All controller methods must be validated against the verify commands before acceptance. Violations must be escalated to the security team for remediation review.
</enforcement>
