<rule_activation id="0b08c34c-340d-4856-8ef9-051455af23c8" title="Adopt Domain-Driven Module Boundaries with External API Integration Layers: External Integrations Organized" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API integration implementations and domain boundary definitions within the codebase.
</rule_activation>

### Rules

- **R-DDD-001** MUST: External API integrations MUST be organized within domain-specific modules following the pattern: `app/Domains/{DomainName}/{IntegrationName}/`
- **R-DDD-002** MUST: Backend interfaces MUST exist for all external protocol implementations and be used via dependency injection.
- **R-DDD-003** MUST: No direct external protocol library usage is permitted in core domain entity or business logic classes.
- **R-DDD-004** MUST: All data exchange with external APIs MUST use dedicated DTO classes rather than direct domain entity serialization.
- **R-DDD-005** SHOULD: Define the backend interface contract before implementing concrete clients to ensure testability from the start.
- **R-DDD-006** SHOULD: Create DTOs that match external API schemas closely, then use separate mapper classes to transform between DTOs and domain entities.
- **R-DDD-007** SHOULD: Use dependency injection to provide backend implementations to domain services, enabling easy substitution for testing.
- **R-DDD-008** SHOULD: Document the external API version and protocol specifications in the integration module README for future maintainers.

### Verify

```bash
# Count backend interface implementations
find app/Domains -type f -name '*Client*' -o -name '*Backend*' | xargs grep -l 'interface\|implements' | wc -l

# Count DTO files in proper location
find app/Domains -path '*/Services/Utils/Model/*Dto.php' | wc -l

# Detect direct external protocol usage in domain logic (should return 0)
grep -r 'use.*\\Dav\\' app/Domains --include='*.php' | grep -v 'DavClient\|Dav/' | wc -l
```

**Accept when:**
- All external API integration modules follow the domain-based directory structure with dedicated Services and Utils/Model subdirectories
- Backend interfaces exist for all external protocol implementations and are used via dependency injection
- No direct external protocol library usage is found in core domain entity or business logic classes (grep verification returns 0 violations)
- All data exchange with external APIs uses dedicated DTO classes rather than direct domain entity serialization
- Integration module structure matches: `app/Domains/{DomainName}/{IntegrationName}/Services`, `/Utils/Model`, `/Web/Backend`

<enforcement>
Claude Code MUST verify all rules before accepting external API integration implementations. Verification is mandatory and MUST NOT be skipped or deferred. CI pipeline MUST fail if direct external protocol usage is detected in core domain classes. Code review MUST block merge requests that do not follow the established module structure for new integrations.
</enforcement>
