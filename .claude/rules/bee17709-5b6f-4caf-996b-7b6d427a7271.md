<rule_activation id="bee17709-5b6f-4caf-996b-7b6d427a7271" title="Adopt HTTP Client Libraries for External API Integration: Dav Caldav Carddav" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. External API communication must use standardized HTTP client libraries rather than raw implementations.
</rule_activation>

### Rules

- **R-HTTP-001** MUST: DAV/CalDAV/CardDAV protocol interactions MUST use Sabre DAV client libraries or equivalent standards-compliant implementations.
- **R-HTTP-002** MUST: All outbound HTTP/HTTPS requests to external APIs and services MUST use established HTTP client libraries (Socialite for OAuth, Sabre for DAV protocols, etc.).
- **R-HTTP-003** MUST: OAuth provider integrations (Google, Facebook, GitHub, etc.) MUST use Socialite library or equivalent standards-compliant OAuth client.
- **R-HTTP-004** MUST: vCard and vCalendar data import/export operations MUST use Sabre VObject or equivalent standards-compliant libraries.
- **R-HTTP-005** SHOULD: HTTP client library usage SHOULD be wrapped in service classes (e.g., WikipediaHelper, DavClient) to encapsulate external API logic and provide domain-specific interfaces.
- **R-HTTP-006** SHOULD: HTTP clients SHOULD be configured with appropriate timeouts, retry policies, and error handling strategies based on the reliability requirements of each external service.
- **R-HTTP-007** SHOULD: Dependency injection SHOULD be used to provide HTTP client instances, enabling easy mocking in unit tests and configuration flexibility across environments.
- **R-HTTP-008** SHOULD: Authentication patterns for each integration type (OAuth, Basic Auth, API keys) SHOULD be documented with examples in the codebase.
- **R-HTTP-009** SHOULD: Logging and monitoring SHOULD be implemented for external API calls to track performance, errors, and usage patterns.

### Scope

**In scope:**
- All outbound HTTP/HTTPS requests to external APIs and services
- OAuth provider integrations (Google, Facebook, GitHub, etc.)
- WebDAV, CalDAV, and CardDAV protocol communications
- Third-party REST API consumption (Wikipedia, documentation services, etc.)
- vCard and vCalendar data import/export operations

**Out of scope:**
- Internal service-to-service communication within the same application
- Database connections and queries
- File system operations
- Message queue or event bus communications
- WebSocket connections (unless using HTTP upgrade mechanism)

**Exceptions:**
- EXC-001: Legacy code maintenance where refactoring risk exceeds benefit
- EXC-002: Performance-critical scenarios where library overhead is demonstrably prohibitive (requires benchmarking and Technical Lead approval)

### Verify

```bash
# Check for Socialite library usage in OAuth flows
grep -r "use.*Socialite" app/ --include="*.php" | wc -l

# Check for Sabre library usage in DAV protocol operations
grep -r "use.*Sabre" app/ --include="*.php" | wc -l

# Check for raw HTTP implementations (should return 0 for new code)
grep -r "curl_exec\|fsockopen" app/ --include="*.php" | wc -l
```

**Accept when:**
- Socialite library usage is detected in OAuth authentication flows
- Sabre DAV/VObject libraries are used for DAV protocol and vCard/vCalendar operations
- No raw cURL or socket implementations are found in new external API integration code
- Service classes encapsulate HTTP client library usage with clear domain interfaces
- HTTP clients are configured with appropriate timeouts and error handling
- Dependency injection is used for HTTP client provisioning
- External API calls include logging and monitoring instrumentation

<enforcement>
Claude Code MUST NOT skip or defer verification. All external API integrations MUST comply with R-HTTP-001 through R-HTTP-004 (MUST-level rules). Violations detected by automated checks MUST block CI pipeline. Manual code review MUST flag non-compliant integrations. Exception requests MUST include performance benchmarks or technical justification and require Technical Lead approval.
</enforcement>
