<rule_activation id="eeb09a08-21f6-4132-b777-0ceb11a92b1e" title="Adopt HTTP Client Libraries for External API Integration: External Integrations Wrapped" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. External API integrations must use standardized HTTP client libraries wrapped in service classes to ensure consistent, secure, and maintainable communication with third-party services including OAuth providers, WebDAV/CalDAV servers, and REST APIs.
</rule_activation>

### Rules

- **R-HTTP-001** SHOULD: External API integrations SHOULD be wrapped in service classes that encapsulate the HTTP client library usage.

### Scope

**In scope:**
- All outbound HTTP/HTTPS requests to external APIs and services
- OAuth provider integrations (Google, Facebook, GitHub, etc.)
- WebDAV, CalDAV, and CardDAV protocol communications
- Third-party REST API consumption (Wikipedia, documentation services, etc.)
- vCard and vCalendar data import/export operations

**Out of scope:**
- Internal service-to-service communication within the same application
- Database connections and queries
- File system operations
- Message queue or event bus communications
- WebSocket connections (unless using HTTP upgrade mechanism)

**Exceptions:**
- EXC-001: Legacy code maintenance where refactoring risk exceeds benefit
- EXC-002: Performance-critical scenarios where library overhead is demonstrably prohibitive

### Verify

```bash
# Verify Socialite library usage for OAuth flows
grep -r "use.*Socialite" app/ --include="*.php" | wc -l

# Verify Sabre DAV/VObject libraries for DAV and vCard/vCalendar operations
grep -r "use.*Sabre" app/ --include="*.php" | wc -l

# Verify no raw cURL or socket implementations in external API code
grep -r "curl_exec\|fsockopen" app/ --include="*.php" | wc -l
```

**Accept when:**
- Socialite library usage is detected in OAuth authentication flows
- Sabre DAV/VObject libraries are used for DAV protocol and vCard/vCalendar operations
- No raw cURL or socket implementations are found in new external API integration code
- Service classes encapsulate HTTP client library usage with clear domain interfaces
- HTTP clients are configured with appropriate timeouts, retry policies, and error handling strategies
- Dependency injection is used to provide HTTP client instances for testability
- External API calls include logging and monitoring for performance and error tracking

<enforcement>
Claude Code MUST verify compliance with R-HTTP-001 by:
1. Scanning for raw HTTP implementations (curl_exec, fsockopen) in new code
2. Confirming approved HTTP client libraries are present in dependency manifests
3. Reviewing external API integration patterns for service class encapsulation
4. Validating unit test coverage for service classes wrapping external API calls

Violations MUST be flagged for revision. Exceptions require documented performance benchmarks or technical justification approved by Technical Lead.
</enforcement>
