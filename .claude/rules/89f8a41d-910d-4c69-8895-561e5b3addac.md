<rule_activation id="89f8a41d-910d-4c69-8895-561e5b3addac" title="Adopt PHPUnit for Unit Testing in Domain-Driven Architecture: Unit Test Files" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to ensure consistent unit testing practices using PHPUnit within a domain-driven architecture.
</rule_activation>

### Rules

- **R-PHPUNIT-001** MUST: Unit test files MUST be placed in tests/Unit/Domains/ directory structure mirroring the application domain hierarchy
- **R-PHPUNIT-002** MUST: All test files MUST follow the {ClassName}Test.php naming convention
- **R-PHPUNIT-003** MUST: Unit tests MUST use PHPUnit\Framework\TestCase as the base class
- **R-PHPUNIT-004** SHOULD: Unit tests SHOULD cover service layer components, API controllers, and view helpers across all domains
- **R-PHPUNIT-005** SHOULD: Tests SHOULD use PHPUnit data providers for testing multiple scenarios with the same test logic

### Verify

```bash
# Count test files in the correct directory structure
find tests/Unit/Domains -name '*Test.php' -type f | wc -l

# Verify PHPUnit TestCase usage
grep -r 'use PHPUnit\\Framework\\TestCase' tests/Unit/Domains/ | wc -l

# Execute all unit tests with test documentation
vendor/bin/phpunit --testsuite=unit --testdox
```

**Accept when:**
- All test files in tests/Unit/Domains/ follow the {ClassName}Test.php naming convention
- PHPUnit test execution completes successfully with all tests passing
- Test directory structure mirrors the application domain hierarchy under tests/Unit/Domains/
- All test files extend PHPUnit\Framework\TestCase
- Code coverage reports are generated and tracked during CI builds
