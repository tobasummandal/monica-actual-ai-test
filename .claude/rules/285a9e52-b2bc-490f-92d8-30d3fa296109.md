<rule_activation id="285a9e52-b2bc-490f-92d8-30d3fa296109" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: Datastore Interactions Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching domain services, view helpers, background jobs, and global helpers that interact with the primary datastore.
</rule_activation>

### Rules

- **R-DATASTORE-001** MUST: All datastore interactions MUST use the application's configured primary database connection and MUST NOT hardcode connection strings.
- **R-DATASTORE-002** MUST: Use Laravel Eloquent models as the primary ORM abstraction for all domain entities.
- **R-DATASTORE-003** SHOULD: Inject model dependencies into service constructors rather than using static calls or facades for better testability.
- **R-DATASTORE-004** SHOULD: For view helpers that need data, prefer calling service layer methods or creating dedicated query classes.
- **R-DATASTORE-005** SHOULD: Background jobs should wrap datastore operations in database transactions where data consistency is critical.
- **R-DATASTORE-006** SHOULD: Create shared helper utilities in app/Helpers/ for common query patterns.
- **R-DATASTORE-007** SHOULD: Document any raw SQL queries with comments explaining why ORM was insufficient.

### Verify

```bash
# Detect direct SQL usage without performance exception comments
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access pattern tests
php artisan test --filter=DataAccessTest

# Static analysis for data access patterns
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs in app/Domains/*/Services/, app/Domains/*/Web/ViewHelpers/, app/Domains/*/Jobs/, and app/Helpers/ use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections
- All raw SQL queries (if any) are documented with comments explaining why ORM was insufficient

<enforcement>
Claude Code MUST NOT skip or defer verification. All datastore access patterns MUST comply with R-DATASTORE-001 through R-DATASTORE-007. Violations detected by static analysis or code review MUST be corrected or documented as approved exceptions before acceptance.
</enforcement>
