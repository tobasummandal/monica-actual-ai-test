<rule_activation id="51fddbf5-1ec1-44ce-945a-988df4ef1e58" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Test Files Follow" applies_to="tests/**/*.php">
These rules are ALWAYS ACTIVE for all PHP test files in the tests/ directory.

**Scope:**
- All PHP test files in tests/Unit and tests/Feature directories
- CI/CD pipeline configuration files (e.g., .github/workflows, .gitlab-ci.yml, phpunit.xml)
- Test execution scripts and automation tools
- PHPUnit configuration and test suite definitions

**Out of scope:**
- Manual testing procedures and QA processes
- End-to-end browser testing frameworks (e.g., Selenium, Cypress)
- Performance and load testing suites
- Third-party package tests within vendor directories

**Exceptions:**
- EX-001: Legacy tests that predate this standard and require significant refactoring
- EX-002: Experimental or spike tests that are explicitly marked as temporary
</rule_activation>

### Rules

- **R-TEST-001** SHOULD: Test files SHOULD follow the naming convention *Test.php to ensure automatic discovery

### Context

The codebase contains a structured test suite with clear separation between Unit tests and Feature tests. Test files are organized by domain boundaries (Contact, DAV, Jetstream) following Laravel conventions with tests/Unit and tests/Feature directories.

Key principles:
- Clear separation between unit and feature tests enables faster feedback loops
- Domain-organized test structure aligns with domain-driven design principles
- Standardizing test organization ensures consistent conventions across the team

### Verify

```bash
# Count unit test files
grep -r "class.*Test extends" tests/Unit/ | wc -l

# Count feature test files
grep -r "class.*Test extends" tests/Feature/ | wc -l

# Run unit tests first (fast feedback)
php artisan test --testsuite=unit --stop-on-failure

# Run feature tests
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both unit and feature test directories exist and contain test files following the *Test.php naming convention
- PHPUnit configuration defines separate test suites for unit and feature tests
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings

<enforcement>
Claude Code MUST verify test organization and naming conventions. Violations MUST be flagged during code review.

**Automated verification:**
- CI/CD pipeline checks fail builds if tests are not properly organized
- Code review checklist requires verification of test placement and categorization
- PHPUnit test suite execution reports show separate unit and feature test results
- Static analysis tools check for test file naming conventions and directory structure

**Violation handling:**
- CI/CD pipeline fails if tests are placed in incorrect directories or don't follow naming conventions
- Pull requests are blocked until test organization issues are resolved
- Automated comments on PRs highlight test organization violations with links to documentation
- Monthly audit reports identify non-compliant tests for remediation

**Exception process:**
- Developer submits exception request via ADR amendment or GitHub issue with justification
- Tech Lead reviews exception request and approves/rejects within 2 business days
- Approved exceptions are documented in the codebase with TODO comments and tracked in project management system
- All exceptions are reviewed quarterly to determine if they can be resolved or need extension
</enforcement>
