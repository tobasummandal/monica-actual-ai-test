<rule_activation id="51fddbf5-1ec1-44ce-945a-988df4ef1e58" title="Standardize Unit and Feature Test Organization in CI/CD Pipeline: Test Files Follow" applies_to="tests/**/*">
These rules are ALWAYS ACTIVE for all PHP test files in tests/Unit and tests/Feature directories.
</rule_activation>

### Rules

- **R-TEST-001** SHOULD: Test files SHOULD follow the naming convention `*Test.php` to ensure automatic discovery by PHPUnit.

### Verify

```bash
# Count unit tests
grep -r "class.*Test extends" tests/Unit/ | wc -l

# Count feature tests
grep -r "class.*Test extends" tests/Feature/ | wc -l

# Run unit tests with fail-fast
php artisan test --testsuite=unit --stop-on-failure

# Run feature tests with fail-fast
php artisan test --testsuite=feature --stop-on-failure
```

**Accept when:**
- Both `tests/Unit/` and `tests/Feature/` directories exist and contain test files following the `*Test.php` naming convention
- PHPUnit configuration (`phpunit.xml`) defines separate test suites for `unit` and `feature` with appropriate directory mappings
- CI/CD pipeline successfully executes both test suites sequentially (unit first, then feature) on every commit
- All tests pass in both suites without errors or warnings
- Test files are organized by domain boundaries (Contact, DAV, Jetstream) following domain-driven design principles

<enforcement>
Claude Code MUST verify test organization compliance before accepting changes to test files. Violations block pull requests until resolved. Automated CI/CD checks MUST fail builds if tests are not properly organized or named.
</enforcement>
