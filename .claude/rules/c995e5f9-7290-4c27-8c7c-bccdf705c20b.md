<rule_activation id="c995e5f9-7290-4c27-8c7c-bccdf705c20b" title="Adopt Modular Architecture with Factory-Based Component Generation: Modules Define Their" applies_to="**/*">
These rules are ALWAYS ACTIVE for all application modules, domain components, database factories, console commands, view helpers, and scheduled task definitions.
</rule_activation>

### Rules

- **R-MOD-001** MAY: Modules MAY define their own factory classes for complex nested structures (e.g., ModuleRow within Module).
- **R-MOD-002** MUST: All PHP files in app/Domains directory use the correct App\Domains namespace hierarchy.
- **R-MOD-003** MUST: All factory classes in database/factories extend the framework's base Factory class.
- **R-MOD-004** MUST: All setup commands in app/Console/Commands extend the framework's Command class and follow naming conventions.
- **R-MOD-005** SHOULD: Use singular nouns for domain names (Contact, not Contacts) and descriptive names for subdomains (ManageContact).
- **R-MOD-006** SHOULD: Use standard layer names (Web, Console, Database) for consistent organization.
- **R-MOD-007** SHOULD: Document module dependencies in a central registry or dependency graph to prevent circular dependencies.
- **R-MOD-008** SHOULD: Include factory updates in definition of done for model changes.
- **R-MOD-009** SHOULD: Add CI checks to verify factory-generated data passes model validation.

### Verify

```bash
# Verify all PHP files in app/Domains use correct namespace
find app/Domains -type f -name '*.php' | xargs grep -L 'namespace App\\Domains' | wc -l | grep -q '^0$'

# Verify all factory classes extend base Factory class
find database/factories -type f -name '*Factory.php' | xargs grep -c 'extends Factory' | grep -v ':0'

# Verify all setup commands extend Command class
find app/Console/Commands -type f -name 'Setup*.php' | xargs grep -c 'extends Command' | grep -v ':0'
```

**Accept when:**
- All PHP files in app/Domains directory use the correct App\Domains namespace hierarchy
- All factory classes in database/factories extend the framework's base Factory class
- All setup commands in app/Console/Commands extend the framework's Command class and follow naming conventions
- Module structure compliance is verified through code review checklist
- Namespace conventions are validated by automated CI pipeline (PHPStan or Psalm)
- File placement and class naming patterns pass pre-commit hook validation

<enforcement>
Claude Code MUST NOT skip or defer verification. All namespace conventions, factory class inheritance, and command class structure MUST be validated before accepting module implementations. CI pipeline failures due to namespace violations MUST block merge. Code review approval MUST be withheld until module structure compliance is achieved.
</enforcement>
