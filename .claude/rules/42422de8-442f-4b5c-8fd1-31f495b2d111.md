### Rules

- **R-ORG-001** MUST: Test files MUST be organized under tests/Unit/Domains/ following the same domain structure as production code.
- **R-ORG-002** MUST: Test file names MUST consistently append 'Test' suffix to production class names.
- **R-ORG-003** MUST: Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) MUST be represented as subdirectories within their respective domains.
- **R-ORG-004** MUST: Test file paths MUST mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix.
- **R-ORG-005** SHOULD: Establish naming conventions for domain and module directories that are concise yet descriptive to minimize path length.
- **R-ORG-006** SHOULD: Configure CI/CD pipelines to support domain-based test execution using path filters.
- **R-ORG-007** MAY: Shared test utilities or base test classes that serve multiple domains may be organized outside the strict domain hierarchy (EXC-001).
- **R-ORG-008** MAY: Legacy test files being refactored into domain structure may temporarily exist outside the standard organization during migration (EXC-002).

### Verify

```bash
# Verify test files exist under tests/Unit/Domains/ with correct structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify namespace conventions match domain structure
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are represented as subdirectories
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- CI/CD pipeline checks verify test file locations match production code structure
- Code review checklist confirms new tests follow domain organization pattern
- Automated linting rules validate test file naming and location conventions
- Pre-commit hooks verify test files are placed in correct domain directories
