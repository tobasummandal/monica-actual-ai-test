<rule_activation id="42422de8-442f-4b5c-8fd1-31f495b2d111" title="Organize Test Files by Domain and Feature Modules: Test Files Organized" applies_to="tests/**/*">
These rules are ALWAYS ACTIVE for all test files matching `tests/**/*`.

Test files must follow domain-driven organization to support CI/CD efficiency, selective test execution, and maintainability by mirroring production code structure.
</rule_activation>

### Rules

- **R-TEST-001** MUST: Test files MUST be organized under `tests/Unit/Domains/` following the same domain structure as production code.
- **R-TEST-002** MUST: Test file paths MUST mirror production code paths with `tests/Unit/Domains/` prefix replacing `src/` or `app/` prefix.
- **R-TEST-003** MUST: Test file names MUST consistently append 'Test' suffix to production class names (e.g., `UserService.php` → `UserServiceTest.php`).
- **R-TEST-004** SHOULD: Domain feature modules (e.g., ManageTemplates, ManageUserPreferences, ManageUsers) SHOULD be represented as subdirectories within their respective domain directories.
- **R-TEST-005** SHOULD: CI/CD pipelines SHOULD support domain-based test execution using path filters to enable selective test runs.

### Exceptions

- **EXC-001**: Shared test utilities or base test classes that serve multiple domains may be placed outside domain structure.
- **EXC-002**: Legacy tests being migrated to domain structure are granted temporary exception during migration period.

### Verify

```bash
# Verify test files exist in domain structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify namespace conventions
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are organized correctly
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under `tests/Unit/Domains/` with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with `tests/Unit/Domains/` prefix replacing `src/` or `app/` prefix
- Namespaces follow the pattern `Tests\Unit\Domains\{DomainName}\{ModuleName}`

Claude Code MUST NOT skip or defer verification of test file organization.

Verification is performed by:
- CI pipeline checks verifying test file locations match production code structure
- Code review checklist items confirming new tests follow domain organization pattern
- Automated linting rules that validate test file naming and location conventions
