<rule_activation id="a62f0b80-bf68-497a-917f-a441072b1f9f" title="Adopt Modular Architecture with Factory-Based Component Generation: View Helpers Isolated" applies_to="**/*">
These rules enforce modular architecture patterns with factory-based component generation and proper layer separation across all application modules, database factories, console commands, view helpers, and scheduled tasks.

**In scope:**
- All application modules and domain components
- Database factories for test data generation and seeding
- Console commands for setup, initialization, and maintenance
- View helpers and presentation layer components
- Scheduled task definitions and cron job management

**Out of scope:**
- Third-party vendor packages and external libraries
- Framework core files and base classes
- Configuration files and environment-specific settings
- Static assets and frontend build artifacts

**Exceptions:**
- EX-001: Legacy modules predating this ADR that require significant refactoring effort
- EX-002: Rapid prototyping or proof-of-concept code in designated experimental branches
</rule_activation>

### Rules

- **R-MOD-001** SHOULD: View helpers SHOULD be isolated in dedicated ViewHelper classes within the Web layer of their respective domains.
- **R-MOD-002**: All PHP files in app/Domains directory MUST use the correct App\Domains namespace hierarchy.
- **R-MOD-003**: All factory classes in database/factories MUST extend the framework's base Factory class.
- **R-MOD-004**: All setup commands in app/Console/Commands MUST extend the framework's Command class and follow naming conventions.

### Verify

```bash
# Verify all PHP files in app/Domains use correct namespace
find app/Domains -type f -name '*.php' | xargs grep -L 'namespace App\\Domains' | wc -l | grep -q '^0$'

# Verify all factory classes extend Factory
find database/factories -type f -name '*Factory.php' | xargs grep -c 'extends Factory' | grep -v ':0'

# Verify all setup commands extend Command
find app/Console/Commands -type f -name 'Setup*.php' | xargs grep -c 'extends Command' | grep -v ':0'
```

**Accept when:**
- All PHP files in app/Domains directory use the correct App\Domains namespace hierarchy
- All factory classes in database/factories extend the framework's base Factory class
- All setup commands in app/Console/Commands extend the framework's Command class and follow naming conventions

### Implementation Notes

- Use code generation tools or IDE templates to scaffold new modules with correct directory structure, namespace, and boilerplate factory/command classes
- Establish naming conventions: Domain names should be singular nouns (Contact, not Contacts), subdomain names should describe the capability (ManageContact), layer names should be standard (Web, Console, Database)
- Document module dependencies in a central registry or dependency graph to prevent circular dependencies and clarify initialization order
- Create a module checklist for code reviews: correct namespace, factory present if needed, setup command if initialization required, view helpers in Web layer

<enforcement>
Claude Code MUST verify compliance with namespace conventions, factory inheritance, and command structure before completing any work that creates or modifies domain modules, factory classes, or console commands. Verification MUST NOT be skipped or deferred.

**Enforcement mechanisms:**
- Automated CI pipeline checks using PHPStan or Psalm to verify namespace conventions
- Code review checklist requiring verification of module structure compliance
- Pre-commit hooks validating file placement and class naming patterns

**Violation handling:**
- CI pipeline fails if namespace conventions are violated, blocking merge
- Code review approval withheld until module structure compliance is achieved
- Technical debt tickets created for legacy code violations with prioritized remediation plan

**Exception process:**
- Developer submits exception request to Technical Lead with justification and impact analysis
- Technical Lead reviews with Architecture Review Board if exception affects multiple modules
- Approved exceptions documented in ADR exceptions log with expiration date and migration plan
</enforcement>
