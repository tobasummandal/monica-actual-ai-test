<rule_activation id="bed99b1b-21df-41f4-9ae1-2847b9d3750d" title="Adopt Domain-Driven Resource Modeling for Data Access Layer: Data Models Follow" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in the application. Domain-driven resource modeling ensures consistent data access layer organization across all domain contexts.
</rule_activation>

### Rules

- **R-DDRM-001** MUST: Data models MUST follow a consistent naming convention that reflects their domain purpose (e.g., File.php for file entities, VCardResource.php for vCard protocol resources).
- **R-DDRM-002** MUST: Place core domain models in app/Models/ directory with clear, singular naming (e.g., File.php, User.php).
- **R-DDRM-003** MUST: Organize domain-specific models and resources within app/Domains/{DomainName}/ subdirectories to maintain bounded contexts.
- **R-DDRM-004** MUST: Create dedicated resource classes (e.g., VCardResource, VCalendarResource) for external protocol transformations in appropriate domain subdirectories, separate from core models.
- **R-DDRM-005** SHOULD: Use consistent method naming for resource transformations (e.g., toVCard(), fromVCard()) to establish predictable APIs.
- **R-DDRM-006** MUST: Separate domain models from protocol-specific resources to maintain single responsibility principle.

### Verify

```bash
# Count domain models in app/Models/
find app/Models -name '*.php' -type f | wc -l

# Count resource classes in domain directories
grep -r 'class.*Resource' app/Domains/ --include='*.php' | wc -l

# Verify domain-specific organization exists
find app/Domains -type d -name 'Dav' | wc -l
```

**Accept when:**
- All domain entities have corresponding model classes in app/Models/ or domain-specific directories
- External protocol integrations use dedicated resource classes separate from core models
- Domain organization follows consistent directory structure with clear bounded contexts
- Resource classes use consistent naming patterns reflecting their protocol (VCardResource, VCalendarResource, etc.)
- No protocol transformation logic exists in core domain model classes

<enforcement>
Claude Code MUST verify model organization and naming conventions before accepting changes to data access layer files. Violations of R-DDRM-001 through R-DDRM-006 MUST be flagged during code review. Static analysis and CI pipeline checks are mandatory for enforcement.
</enforcement>
