<rule_activation id="a065e6c8-b715-403c-84d6-552bdaccd738" title="Standardize Logging with Laravel Log Facade in DAV and Job Components: Dav Backend Implementations" applies_to="app/Domains/Contact/Dav* app/Console/Commands/*">
These rules are ALWAYS ACTIVE for all DAV backend implementations, background jobs in Contact/Dav and Contact/DavClient domains, DavClient service utilities, console commands for address book and application setup, and any component performing external DAV server communication.
</rule_activation>

### Rules

- **R-DAV-001** MUST: All DAV backend implementations (CalDAV, CardDAV) MUST use Laravel's Log facade for recording synchronization events, errors, and state transitions.
- **R-DAV-002** MUST: Import the Log facade at the top of each class: `use Illuminate\Support\Facades\Log;`
- **R-DAV-003** MUST: Use appropriate log levels: `Log::debug()` for detailed tracing, `Log::info()` for significant events, `Log::warning()` for recoverable issues, `Log::error()` for failures requiring attention.
- **R-DAV-004** SHOULD: Include structured context as second parameter: `Log::info('VCard synchronized', ['contact_id' => $id, 'addressbook_id' => $addressbookId])`
- **R-DAV-005** SHOULD: For DAV operations, consider using a dedicated channel configured in config/logging.php: `Log::channel('dav')->info('Sync started')`
- **R-DAV-006** SHOULD: In job classes, log at the beginning and end of handle() method with job-specific context to enable job execution tracking.
- **R-DAV-007** MAY: Avoid logging in tight loops - consider sampling or aggregating log messages for bulk operations.

### Exceptions

- **EXC-001**: Performance-critical hot paths where logging overhead is measured and documented as unacceptable.
- **EXC-002**: Temporary debugging code using dd(), dump(), or var_dump() during active development.

### Verify

```bash
# Verify Log facade imports in DAV and console command files
grep -r "use Illuminate\\Support\\Facades\\Log" app/Domains/Contact/Dav* app/Console/Commands/ | wc -l

# Verify Log method calls with appropriate levels
grep -r "Log::" app/Domains/Contact/Dav* app/Console/Commands/ | grep -E "(debug|info|warning|error)" | wc -l

# Verify Log facade class availability
php artisan tinker --execute="echo class_exists('Illuminate\\Support\\Facades\\Log') ? 'PASS' : 'FAIL';"
```

**Accept when:**
- Log facade import statements are present in all DAV backend classes, DavClient services, and relevant console commands.
- Log method calls (debug/info/warning/error) are present in job handle() methods and synchronization service methods.
- Laravel's Log facade class is available and properly configured in the application.
- Structured context data is included in log calls where applicable.
- No sensitive data (authentication tokens, personal information) is logged without redaction.

Claude Code MUST NOT skip or defer verification. All DAV backend implementations and job components MUST comply with R-DAV-001 through R-DAV-007. Code review and static analysis verification is mandatory before acceptance.
