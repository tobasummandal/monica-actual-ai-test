<rule_activation id="a065e6c8-b715-403c-84d6-552bdaccd738" title="Standardize Logging with Laravel Log Facade in DAV and Job Components: Dav Backend Implementations" applies_to="app/Domains/Contact/Dav*/**/*,app/Domains/Contact/DavClient/**/*,app/Console/Commands/**/*">
These rules are ALWAYS ACTIVE for all files matching DAV backend implementations, DavClient services, and console commands performing external DAV server communication.

**In scope:**
- DAV backend implementations (CalDAV/CardDAV)
- Background jobs in Contact/Dav and Contact/DavClient domains
- DavClient service utilities and synchronization services
- Console commands for address book and application setup
- Any component performing external DAV server communication

**Out of scope:**
- Frontend JavaScript logging
- Database query logging (handled by Laravel's query log)
- HTTP middleware logging (handled by web server/framework)
- Third-party package internal logging
- Unit test execution logging

**Exceptions:**
- EXC-001: Performance-critical hot paths where logging overhead is measured and documented as unacceptable
- EXC-002: Temporary debugging code using dd(), dump(), or var_dump() during active development
</rule_activation>

### Rules

- **R-DAV-LOG-001** MUST: All DAV backend implementations (CalDAV, CardDAV) MUST use Laravel's Log facade for recording synchronization events, errors, and state transitions.

- **R-DAV-LOG-002** MUST: Import the Log facade at the top of each class using `use Illuminate\Support\Facades\Log;`

- **R-DAV-LOG-003** MUST: Use appropriate log levels:
  - `Log::debug()` for detailed tracing
  - `Log::info()` for significant events
  - `Log::warning()` for recoverable issues
  - `Log::error()` for failures requiring attention

- **R-DAV-LOG-004** SHOULD: Include structured context as second parameter: `Log::info('VCard synchronized', ['contact_id' => $id, 'addressbook_id' => $addressbookId])`

- **R-DAV-LOG-005** SHOULD: For DAV operations, consider using a dedicated channel configured in config/logging.php: `Log::channel('dav')->info('Sync started')`

- **R-DAV-LOG-006** MUST: In job classes, log at the beginning and end of handle() method with job-specific context to enable job execution tracking.

- **R-DAV-LOG-007** MUST: Avoid logging in tight loops - consider sampling or aggregating log messages for bulk operations.

- **R-DAV-LOG-008** MUST: Never log sensitive data (authentication tokens, personal contact information). Implement log scrubbing for any potentially sensitive context data.

### Verify

```bash
# Check Log facade imports in DAV and console command files
grep -r "use Illuminate\\\\Support\\\\Facades\\\\Log" app/Domains/Contact/Dav* app/Console/Commands/ | wc -l

# Check Log method calls with appropriate levels
grep -r "Log::" app/Domains/Contact/Dav* app/Console/Commands/ | grep -E "(debug|info|warning|error)" | wc -l

# Verify Laravel Log facade is available
php artisan tinker --execute="echo class_exists('Illuminate\\\\Support\\\\Facades\\\\Log') ? 'PASS' : 'FAIL';"
```

**Accept when:**
- Log facade import statements are present in all DAV backend classes, DavClient services, and relevant console commands
- Log method calls (debug/info/warning/error) are present in job handle() methods and synchronization service methods
- Laravel's Log facade class is available and properly configured in the application
- No sensitive data (tokens, credentials, PII) is being logged in context arrays
