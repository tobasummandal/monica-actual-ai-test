<rule_activation id="6a8c4e53-e9eb-4035-bca8-156f4a16bece" title="Standardize Logging with Laravel Log Facade in DAV and Job Components: Components Use Dedicated" applies_to="app/Domains/Contact/Dav* app/Console/Commands/*">
These rules are ALWAYS ACTIVE for all DAV backend implementations, background jobs in Contact/Dav and Contact/DavClient domains, DavClient service utilities, synchronization services, and console commands for address book and application setup.
</rule_activation>

### Rules

- **R-LOG-001** MAY: Components MAY use dedicated log channels for DAV operations to enable separate log routing and retention policies.
- **R-LOG-002** MUST: Import the Log facade at the top of each class: `use Illuminate\Support\Facades\Log;`
- **R-LOG-003** MUST: Use appropriate log levels: `Log::debug()` for detailed tracing, `Log::info()` for significant events, `Log::warning()` for recoverable issues, `Log::error()` for failures requiring attention.
- **R-LOG-004** SHOULD: Include structured context as second parameter: `Log::info('VCard synchronized', ['contact_id' => $id, 'addressbook_id' => $addressbookId])`
- **R-LOG-005** SHOULD: For DAV operations, use a dedicated channel configured in config/logging.php: `Log::channel('dav')->info('Sync started')`
- **R-LOG-006** SHOULD: In job classes, log at the beginning and end of handle() method with job-specific context to enable job execution tracking.
- **R-LOG-007** SHOULD: Avoid logging in tight loops - consider sampling or aggregating log messages for bulk operations.
- **R-LOG-008** MUST NOT: Log sensitive data (authentication tokens, personal contact information) without implementing log scrubbing middleware and redaction patterns.

### Verify

```bash
# Verify Log facade imports in DAV and console command files
grep -r "use Illuminate\\Support\\Facades\\Log" app/Domains/Contact/Dav* app/Console/Commands/ | wc -l

# Verify Log method calls with appropriate levels
grep -r "Log::" app/Domains/Contact/Dav* app/Console/Commands/ | grep -E "(debug|info|warning|error)" | wc -l

# Verify Log facade class availability
php artisan tinker --execute="echo class_exists('Illuminate\\Support\\Facades\\Log') ? 'PASS' : 'FAIL';"
```

**Accept when:**
- Log facade import statements are present in all DAV backend classes, DavClient services, and relevant console commands
- Log method calls (debug/info/warning/error) are present in job handle() methods and synchronization service methods
- Laravel's Log facade class is available and properly configured in the application
- Structured context data is included in log calls
- Sensitive data handling is documented and log scrubbing is configured
