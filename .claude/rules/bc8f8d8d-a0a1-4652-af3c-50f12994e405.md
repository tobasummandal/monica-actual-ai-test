<rule_activation id="bc8f8d8d-a0a1-4652-af3c-50f12994e405" title="Standardize Password Hashing for Authentication Operations: Password Storage Operations" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in authentication operations, including account creation, password reset, password update, and invitation acceptance workflows across domain services and Fortify action handlers.
</rule_activation>

### Rules

- **R-PSW-001** MUST: All password storage operations MUST use Laravel's Hash facade or bcrypt hashing algorithm with appropriate cost factors.

### Verify

```bash
# Check for unhashed password assignments in authentication code
grep -r "'password'\s*=>\s*\$" app/ --include='*.php' | grep -v 'Hash::make' | grep -v 'bcrypt(' | grep -v '// ' || echo 'No unhashed password assignments found'

# Verify Hash::make or bcrypt usage in Fortify and Settings domains
grep -r "Hash::make\|bcrypt(" app/Actions/Fortify/ app/Domains/Settings/ --include='*.php' | wc -l

# Run password-related feature tests with coverage
php artisan test --filter=Password --coverage-text | grep -E '(UpdatePasswordTest|ResetPasswordTest)'
```

**Accept when:**
- All password assignment operations in authentication code paths use Hash::make() or bcrypt() helper
- Feature tests verify that stored passwords are hashed (Hash::check returns true for original password)
- Code review checklist includes verification of password hashing for any authentication-related changes
- No unhashed password assignments detected in grep patterns across app/Actions/Fortify/ and app/Domains/Settings/
- UpdatePasswordTest and ResetPasswordTest pass with password hashing verification

<enforcement>
Claude Code MUST NOT skip or defer verification. All password storage operations require Hash::make() or bcrypt() hashing. Violations in CI pipeline must fail. No exceptions permitted for production authentication code. Password hashing is a non-negotiable security requirement.
</enforcement>
