<rule_activation id="643f3395-d2b2-4c49-8de7-6232adbd4cee" title="Adopt Eloquent ORM Models as Standard Data Modeling Pattern: Models Not Contain" applies_to="app/Models/**/*.php">
These rules are ALWAYS ACTIVE for all data modeling activities within the application layer using Eloquent ORM models.
</rule_activation>

### Rules

- **R-29-008** MUST_NOT: Models MUST NOT contain business logic beyond data access concerns; complex business rules belong in service classes or domain objects.

### Verify

```bash
# Verify all model files extend Eloquent Model class
find app/Models -type f -name '*.php' | xargs grep -L 'extends Model' | wc -l | grep -q '^0$'

# Verify proper namespace usage
grep -r 'namespace App\\Models' app/Models/*.php | wc -l

# Verify model class structure
php artisan tinker --execute="echo count(get_declared_classes())" 2>&1 | grep -q '[0-9]'
```

**Accept when:**
- All PHP files in app/Models directory extend Illuminate\Database\Eloquent\Model class
- Model classes are properly namespaced under App\Models and follow PSR-4 autoloading standards
- No direct database queries using DB facade exist in controller methods where Eloquent models are available
- Code review checklist includes verification of mass assignment protection and relationship eager loading
- Models define $fillable or $guarded arrays for mass assignment protection
- Relationships are defined in dedicated methods using Eloquent relationship types
- Business logic is extracted to service classes, not contained in models
- Model observers or events are used for cross-cutting concerns rather than duplicating logic in controllers

<enforcement>
Claude Code MUST verify all rules in this file. Violations of R-29-008 MUST be flagged during code review. CI pipeline MUST fail if models are detected outside app/Models namespace or not extending base Model class. Code review MUST block merge if models contain business logic beyond data access concerns.
</enforcement>
