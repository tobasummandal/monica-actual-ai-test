<rule_activation id="4e336b60-4c0a-46c1-b6a6-2ced1bceecb1" title="Organize Test Files by Domain and Feature Modules: Each Domain Subdirectory" applies_to="tests/Unit/Domains/**/*">
These rules are ALWAYS ACTIVE for all test files under tests/Unit/Domains/ to ensure consistent domain-driven test organization mirroring production code structure.
</rule_activation>

### Rules

- **R-ORG-001** MUST: Each domain subdirectory MUST contain feature module subdirectories that mirror the production code organization (e.g., ManageTemplates, ManageUserPreferences, ManageUsers).
- **R-ORG-002** MUST: Test files under tests/Unit/Domains/ MUST mirror the production code structure with tests/Unit/Domains/ prefix replacing src/ or app/ prefix.
- **R-ORG-003** MUST: Test file names MUST consistently append 'Test' suffix to production class names.
- **R-ORG-004** SHOULD: Domain and module directory names SHOULD be concise yet descriptive to minimize path length and avoid filesystem limits.
- **R-ORG-005** MAY: Shared test utilities or base test classes serving multiple domains MAY be organized separately (EXC-001).
- **R-ORG-006** MAY: Legacy test files being refactored into domain structure MAY be organized outside the standard structure during migration period (EXC-002).

### Verify

```bash
# Verify test files exist under tests/Unit/Domains/ with correct structure
find tests/Unit/Domains -type f -name '*Test.php' | head -20

# Verify namespace conventions match domain structure
grep -r 'namespace.*Tests\\Unit\\Domains' tests/Unit/Domains/ | head -10

# Verify domain feature modules are represented as subdirectories
ls -R tests/Unit/Domains/Settings/ | grep -E '(ManageTemplates|ManageUserPreferences|ManageUsers)'
```

**Accept when:**
- Test files exist under tests/Unit/Domains/ with subdirectories matching production domain structure
- Test file names consistently append 'Test' suffix to production class names
- Domain feature modules (ManageTemplates, ManageUserPreferences, ManageUsers) are represented as subdirectories within their respective domains
- Test file paths mirror production code paths with tests/Unit/Domains/ prefix replacing src/ or app/ prefix
- Namespace declarations in test files follow pattern Tests\Unit\Domains\{Domain}\{Module}

Code review MUST confirm new tests follow domain organization pattern. Violations MUST be flagged with suggested correct paths.
</enforcement>
