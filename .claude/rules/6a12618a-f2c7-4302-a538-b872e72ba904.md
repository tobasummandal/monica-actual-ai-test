<rule_activation id="6a12618a-f2c7-4302-a538-b872e72ba904" title="Adopt Domain-Driven Service Layer Architecture for Business Operations: Service Classes Encapsulate" applies_to="**/*.php">
These rules are ALWAYS ACTIVE for all PHP files in domain-driven service layer architecture.
</rule_activation>

### Rules

- **R-DDD-001** SHOULD: Service classes SHOULD encapsulate a single business operation or use case to maintain single responsibility principle.

### Verify

```bash
# Count service classes in domain structure
find app/Domains -type f -name '*.php' -path '*/Services/*' | wc -l

# Verify service namespace compliance
grep -r 'namespace.*Domains.*Services' app/Domains --include='*.php' | wc -l

# Count controllers in domain structure
find app/Domains -type f -name '*Controller.php' -path '*/Web/Controllers/*' | wc -l
```

**Accept when:**
- Service classes exist in `app/Domains/{Domain}/{Feature}/Services/` directories
- Controllers exist in `app/Domains/{Domain}/{Feature}/Web/Controllers/` directories
- At least 3 domain service classes follow the established pattern
- Service classes are named after the business operation they perform (e.g., CreateAccount, AcceptInvitation)
- Controllers remain thin, delegating business logic to service classes

<enforcement>
Claude Code MUST verify domain-driven service layer structure compliance. Violations include: business logic in controllers, service classes outside designated directories, or inconsistent naming patterns. CI pipeline checks MUST pass before acceptance.
</enforcement>
