<rule_activation id="78872876-55b6-471e-b406-516f04c87b92" title="Adopt Laravel Fortify for Authentication Action Standardization: Authentication Actions Stateless" applies_to="app/Actions/Fortify/**,app/Domains/Settings/**,tests/Feature/**">
These rules are ALWAYS ACTIVE for all authentication actions, domain services, and feature tests related to user lifecycle operations and password management.
</rule_activation>

### Rules

- **R-FORTIFY-001** SHOULD: Authentication actions SHOULD be stateless and idempotent where possible to support horizontal scaling and API-first deployment patterns.

### Verify

```bash
# Verify Fortify action classes exist and extend appropriate contracts
grep -r "extends.*Fortify" app/Actions/Fortify/ | wc -l

# Verify domain-specific user management services exist
find app/Domains -name "*Service.php" -path "*/Services/*" | wc -l

# Verify Hash facade is used consistently for password operations
grep -r "use Illuminate\\Support\\Facades\\Hash" app/Actions/Fortify app/Domains/Settings | wc -l

# Run authentication and password feature tests
php artisan test --filter=Auth --filter=Password --filter=Account
```

**Accept when:**
- All authentication actions in `app/Actions/Fortify` extend appropriate Fortify contracts and are registered in `FortifyServiceProvider`
- Domain-specific user management services exist in `app/Domains/*/Services` and delegate to Fortify actions for password operations
- Feature tests for authentication operations pass and cover both web and API scenarios without presentation layer dependencies
- Password validation uses Laravel Hash facade consistently across all authentication touchpoints
- No authentication logic is detected in controllers without corresponding Fortify action or domain service

<enforcement>
Claude Code MUST NOT skip or defer verification. All authentication changes require verification of Fortify pattern compliance before acceptance. Pull requests containing authentication logic must pass all verify commands and meet all accept-when criteria.
</enforcement>
