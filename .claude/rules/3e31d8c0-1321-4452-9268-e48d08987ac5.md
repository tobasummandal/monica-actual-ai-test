These rules are ALWAYS ACTIVE for all files matching `**/*`. New locales MUST maintain structural parity with existing language files to ensure feature completeness across all supported languages.
</rule_activation>

### Rules

- **R-I18N-001** SHOULD: New locales SHOULD maintain structural parity with existing language files to ensure feature completeness across all supported languages.

### Verify

```bash
# Verify language directory structure exists
find lang/ -type f -name '*.php' | wc -l | grep -E '[0-9]+'

# Check for hardcoded user-facing strings outside language files
grep -r "echo\|print" app/ | grep -v "trans(\|__('\|@lang" || echo 'No hardcoded strings found'

# Run translation checks
php artisan lang:check --missing || composer run check-translations
```

**Accept when:**
- Language directory structure exists with at least one locale containing all required translation categories (auth, validation, passwords, actions, pagination, http-statuses, format)
- No hardcoded user-facing strings are found in application code outside of language files
- Translation loading mechanism is implemented and functional with fallback to default locale for missing keys

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated CI pipeline checks for missing translation keys across supported locales are mandatory. Code review process must verify new user-facing strings are added to language files. Static analysis tools must scan for hardcoded strings in application code. Periodic translation completeness audits must compare key counts across locales.
</enforcement>
