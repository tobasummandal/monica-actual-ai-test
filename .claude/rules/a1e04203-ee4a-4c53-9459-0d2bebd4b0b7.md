<rule_activation id="a1e04203-ee4a-4c53-9459-0d2bebd4b0b7" title="Adopt Laravel Fortify for Authentication Action Standardization: Domain Specific User" applies_to="**/*">
These rules are ALWAYS ACTIVE for all Laravel authentication implementations, Fortify action classes, and domain-specific user management services.
</rule_activation>

### Rules

- **R-FORTIFY-001** MUST: Domain-specific user management services (CreateAccount, AcceptInvitation, CancelAccount) MUST be implemented as dedicated service classes within their respective domain boundaries.
- **R-FORTIFY-002** MUST: All password management operations (reset, update, validation) MUST use Laravel's Hash facade consistently across all authentication touchpoints.
- **R-FORTIFY-003** MUST: Authentication action classes MUST extend appropriate Fortify contracts and be registered in FortifyServiceProvider.
- **R-FORTIFY-004** MUST: Domain services MUST be placed in `app/Domains/{DomainName}/Services` and follow single-responsibility principle, handling one user lifecycle operation per service.
- **R-FORTIFY-005** MUST: Feature tests for authentication operations MUST cover both web and API scenarios without presentation layer dependencies.
- **R-FORTIFY-006** SHOULD: Password validation SHOULD use Laravel's validation rules consistently (min:8, confirmed, etc.) across all authentication actions.
- **R-FORTIFY-007** SHOULD: Feature tests SHOULD use Laravel's authentication testing helpers (actingAs, assertAuthenticated) and test both success and failure scenarios.

### Verify

```bash
# Count Fortify action class extensions
grep -r "extends.*Fortify" app/Actions/Fortify/ | wc -l

# Count domain-specific service classes
find app/Domains -name "*Service.php" -path "*/Services/*" | wc -l

# Verify Hash facade usage in authentication code
grep -r "use Illuminate\\Support\\Facades\\Hash" app/Actions/Fortify app/Domains/Settings | wc -l

# Run authentication and password feature tests
php artisan test --filter=Auth --filter=Password --filter=Account
```

**Accept when:**
- All authentication actions in `app/Actions/Fortify` extend appropriate Fortify contracts and are registered in FortifyServiceProvider
- Domain-specific user management services exist in `app/Domains/*/Services` and delegate to Fortify actions for password operations
- Feature tests for authentication operations pass and cover both web and API scenarios without presentation layer dependencies
- Password validation uses Laravel Hash facade consistently across all authentication touchpoints
- No authentication logic is detected in controllers without corresponding Fortify action or domain service
