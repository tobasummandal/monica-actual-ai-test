These rules are ALWAYS ACTIVE for all files in the Vault domain's ManageJournals subdomain and related journal management operations.
</rule_activation>

### Rules

- **R-DDSRV-001** SHOULD: Services SHOULD handle transaction boundaries and data persistence concerns internally, exposing clean interfaces to controllers.

### Verify

```bash
# Count service files in domain structure
find app/Domains/*/Services -type f -name '*.php' | wc -l

# Count controller files in ManageJournals
grep -r 'class.*Controller' app/Domains/Vault/ManageJournals/Web/Controllers | wc -l

# Verify service namespace pattern
grep -r 'namespace.*Services' app/Domains/Vault/ManageJournals/Services | head -5
```

**Accept when:**
- Service classes exist in dedicated Services directories within domain boundaries
- Controllers delegate to services rather than implementing business logic directly
- Service class names follow verb-noun convention (e.g., CreatePost, UpdateMetric, RemoveTag) and implement single-responsibility operations
- Services accept primitive types or DTOs as parameters rather than HTTP request objects
- Related services are grouped in subdirectories when domains grow large (e.g., ManageJournals/Services/Posts)

<enforcement>
Claude Code MUST verify that business logic is encapsulated in service layer classes and NOT scattered across controllers, models, or ad-hoc helpers. Verification is mandatory before accepting journal management code changes.
</enforcement>
