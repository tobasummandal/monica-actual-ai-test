<rule_activation id="5159ca99-f7c2-4121-a85b-ac1a26c32aeb" title="Standardize Primary Datastore Access Patterns in Domain Services and Helpers: Data Access Logic" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in scope:
- Domain service classes in `app/Domains/*/Services/`
- View helper classes in `app/Domains/*/Web/ViewHelpers/`
- Background jobs in `app/Domains/*/Jobs/`
- Global helper files in `app/Helpers/`

**Out of scope:** Third-party library code, database migrations/seeders, cache layer implementations, external API integrations, read-only analytics modules.

**Exceptions:**
- EXC-001: Performance-critical queries require raw SQL optimization
- EXC-002: Legacy code refactoring is planned but not yet completed
</rule_activation>

### Rules

- **R-DAL-001** SHOULD: Data access logic SHOULD be encapsulated in dedicated repository classes or service methods rather than scattered across view helpers.

- **R-DAL-002** MUST: Use Laravel Eloquent models as the primary ORM abstraction for all domain entities.

- **R-DAL-003** SHOULD: Inject model dependencies into service constructors rather than using static calls or facades for better testability.

- **R-DAL-004** SHOULD: For view helpers that need data, prefer calling service layer methods or creating dedicated query classes.

- **R-DAL-005** SHOULD: Background jobs SHOULD wrap datastore operations in database transactions where data consistency is critical.

- **R-DAL-006** MUST: Document any raw SQL queries with comments explaining why ORM was insufficient (include performance justification and exception ticket reference).

- **R-DAL-007** MUST: Create shared helper utilities in `app/Helpers/` for common query patterns (e.g., ScoutHelper for search functionality).

### Verify

```bash
# Check for undocumented direct SQL usage
grep -r 'DB::raw\|DB::select\|DB::statement' app/Domains --exclude-dir=vendor | grep -v '// Performance exception'

# Run data access tests
php artisan test --filter=DataAccessTest

# Run static analysis to detect pattern violations
phpstan analyse app/Domains --level=5 --error-format=table
```

**Accept when:**
- All domain services, view helpers, and jobs use ORM models or approved repository patterns for datastore access
- No direct SQL queries exist without documented performance justification comments
- Static analysis passes without violations of data access patterns
- Unit tests successfully mock data access layers without requiring database connections

Claude Code MUST NOT skip or defer verification. All changes to domain services, view helpers, jobs, or helper files MUST be verified against these rules before completion. CI pipeline runs static analysis (PHPStan) to detect direct SQL usage. Pull requests with violations are blocked until corrected or documented exceptions are approved by tech lead.
</enforcement>
