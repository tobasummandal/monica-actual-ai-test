<rule_activation id="203f1528-9e41-4d93-93b9-67f52f24737c" title="Adopt PHP as Primary Backend Language for Laravel-Based Web Applications: Deployment Targets Include" applies_to="**/*">
These rules are ALWAYS ACTIVE for all backend code and deployment configurations. PHP is the primary runtime for all backend business logic, authentication, domain services, and web controllers in this Laravel-based application.
</rule_activation>

### Rules

- **R-PHP-001** MUST: All backend business logic and domain services SHALL be implemented in PHP.
- **R-PHP-002** MUST: All authentication and authorization mechanisms (Fortify actions) SHALL be implemented in PHP.
- **R-PHP-003** MUST: All web controllers and HTTP request handling SHALL be implemented in PHP.
- **R-PHP-004** MUST: All database migrations and ORM operations SHALL be implemented in PHP.
- **R-PHP-005** MUST: All feature and unit tests for backend functionality SHALL be implemented in PHP.
- **R-PHP-006** MUST: All API endpoints and web routes SHALL be implemented in PHP.
- **R-PHP-007** MUST: Minimum PHP version 8.0+ SHALL be specified in composer.json platform requirements.
- **R-PHP-008** MUST: Deployment targets MAY include containerized environments (Docker) or traditional LAMP/LEMP stacks as long as PHP runtime requirements are satisfied.
- **R-PHP-009** SHOULD: Use Laravel Sail or Docker Compose for local development to ensure environment parity with production deployment targets.
- **R-PHP-010** SHOULD: Use PHP-FPM with nginx or Apache for production deployments to optimize process management and resource utilization.
- **R-PHP-011** SHOULD: Implement caching strategies (Redis/Memcached) and use queue workers for async operations to mitigate single-threaded execution model limitations.
- **R-PHP-012** MAY: Frontend JavaScript/TypeScript code executed in browser is out of scope for this rule.
- **R-PHP-013** MAY: Build tools and asset compilation (npm, webpack, vite) are out of scope for this rule.
- **R-PHP-014** MAY: Infrastructure-as-code scripts (Terraform, Ansible) are out of scope for this rule.
- **R-PHP-015** MAY: CI/CD pipeline scripts (bash, yaml configurations) are out of scope for this rule.
- **R-PHP-016** MAY: Database stored procedures or functions written in SQL dialects are out of scope for this rule.

### Verify

```bash
# Verify PHP version compatibility (8.0 or higher)
php --version | grep -E 'PHP [8-9]\.' && echo 'PHP version compatible' || echo 'PHP version incompatible'

# Verify required Laravel PHP extensions are present
php -m | grep -E '(openssl|pdo|mbstring|tokenizer|xml|ctype|json|bcmath)' | wc -l | grep -E '[8-9]|[1-9][0-9]' && echo 'Required extensions present' || echo 'Missing extensions'

# Verify PHP files detected in app directory
find app/ -name '*.php' -type f | wc -l | grep -E '[1-9][0-9]*' && echo 'PHP files detected in app directory' || echo 'No PHP files found'
```

**Accept when:**
- PHP version check returns 8.0 or higher in all deployment environments
- All required Laravel PHP extensions (OpenSSL, PDO, Mbstring, Tokenizer, XML, Ctype, JSON, BCMath) are installed and enabled
- Application backend code in app/ directory consists primarily of PHP files with .php extension
- Composer dependencies successfully install and application bootstraps without runtime errors
- composer.json specifies minimum PHP version 8.0+ in platform requirements
- CI/CD pipeline successfully validates PHP version compatibility and extension availability
- Deployment validation scripts confirm target environment meets PHP requirements before release

</enforcement>
