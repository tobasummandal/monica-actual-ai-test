These rules are ALWAYS ACTIVE for all files matching the application codebase to enforce domain-driven service layer architecture.
</rule_activation>

### Rules

- **R-DDD-001** MUST: Domain services MUST be organized by feature area (e.g., CreateAccount, CancelAccount, ManageUsers) to maintain clear boundaries

### Verify

```bash
# Count domain service files
find app/Domains -type f -name '*.php' -path '*/Services/*' | wc -l

# Verify service namespace compliance
grep -r 'namespace.*Domains.*Services' app/Domains --include='*.php' | wc -l

# Count domain controller files
find app/Domains -type f -name '*Controller.php' -path '*/Web/Controllers/*' | wc -l
```

**Accept when:**
- Service classes exist in `app/Domains/{Domain}/{Feature}/Services/` directories
- Controllers exist in `app/Domains/{Domain}/{Feature}/Web/Controllers/` directories
- At least 3 domain service classes follow the established pattern
- Service namespaces match `Domains\{Domain}\{Feature}\Services` structure
- Controllers are thin and delegate business logic to service classes

<enforcement>
Claude Code MUST NOT skip or defer verification of domain-driven service layer architecture compliance. Violations must be flagged and remediation required before acceptance.
</enforcement>
