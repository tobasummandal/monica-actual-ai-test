### Rules

- **R-DDS-001** MUST: Domain services MUST be organized by feature area (e.g., CreateAccount, CancelAccount, ManageUsers) to maintain clear boundaries.

### Verify

```bash
# Count service classes in domain Services directories
find app/Domains -type f -name '*.php' -path '*/Services/*' | wc -l

# Count namespace declarations for domain services
grep -r 'namespace.*Domains.*Services' app/Domains --include='*.php' | wc -l

# Count controllers in domain Web/Controllers directories
find app/Domains -type f -name '*Controller.php' -path '*/Web/Controllers/*' | wc -l
```

**Accept when:**
- Service classes exist in app/Domains/{Domain}/{Feature}/Services/ directories
- Controllers exist in app/Domains/{Domain}/{Feature}/Web/Controllers/ directories
- At least 3 domain service classes follow the established pattern (matching detected evidence)

<enforcement>
Claude Code MUST verify domain service organization follows feature-based boundaries. Verification includes checking directory structure compliance and namespace organization. CI pipeline checks and code review processes enforce this architectural pattern.
</enforcement>
