<rule_activation id="f89b7e46-319f-465e-a7c2-8782e47e3bdc" title="Adopt Eloquent ORM Models as Standard Data Access Layer: Database Backed Entities" applies_to="**/*">
These rules are ALWAYS ACTIVE for all database-backed entities in the application. All data access operations MUST use Eloquent ORM models as the primary abstraction layer.
</rule_activation>

### Rules

- **R-ELOQUENT-001** MUST: All database-backed entities MUST be represented as Eloquent Model classes extending Illuminate\Database\Eloquent\Model.
- **R-ELOQUENT-002** MUST: Define $fillable or $guarded properties immediately after model creation to prevent mass assignment vulnerabilities.
- **R-ELOQUENT-003** SHOULD: Document relationship methods with PHPDoc annotations specifying return types for better IDE support and static analysis.
- **R-ELOQUENT-004** SHOULD: Use model events (creating, created, updating, updated) for cross-cutting concerns like logging and auditing rather than duplicating logic in controllers.
- **R-ELOQUENT-005** SHOULD: Leverage Laravel's attribute casting ($casts property) to automatically convert database values to appropriate PHP types (dates, JSON, booleans).
- **R-ELOQUENT-006** SHOULD: Use model factories for testing to generate realistic test data without manual array construction.
- **R-ELOQUENT-007** MAY: Use raw SQL optimization for performance-critical queries that cannot be achieved through Eloquent query builder (EXC-001).
- **R-ELOQUENT-008** MAY: Use alternative approaches for legacy database schemas with complex naming conventions incompatible with Eloquent conventions (EXC-002).

### In Scope

- All persistent domain entities stored in relational database tables
- CRUD operations for File, Account, ContactInformationType, GiftOccasion, CallReasonType, PostTemplateSection, QuickFact, and similar entities
- Relationship definitions between domain entities
- Data validation rules at the model layer
- Entity-specific business logic and computed properties

### Out of Scope

- Complex analytical queries requiring raw SQL for performance optimization
- Data transfer objects (DTOs) used for API responses or inter-service communication
- Read-only views or materialized views without corresponding base tables
- Temporary or session-based data not persisted to the database
- Third-party API integrations where data is not stored locally

### Verify

```bash
# Count models extending Eloquent Model
grep -r 'extends Model' app/Models/ | wc -l

# Find models not in App\Models namespace
find app/Models -type f -name '*.php' | xargs grep -L 'namespace App\\Models'

# Display all models with table information
php artisan model:show --all | grep -E '(Table|Database)'

# Detect direct DB facade calls for CRUD operations (excluding approved exceptions)
grep -r 'DB::select\|DB::insert\|DB::update\|DB::delete' app/Http/Controllers/ app/Services/ | grep -v 'raw query approved'
```

**Accept when:**
- All model files exist in app/Models namespace and extend Illuminate\Database\Eloquent\Model
- No direct DB facade calls for CRUD operations found in controllers or services (excluding approved exceptions)
- Model count matches database table count for domain entities (excluding pivot tables and migrations table)
- All models define either $fillable or $guarded properties for mass assignment protection
- No N+1 query patterns detected in Laravel Telescope monitoring
