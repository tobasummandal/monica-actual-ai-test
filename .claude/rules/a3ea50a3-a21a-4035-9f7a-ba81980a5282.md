<rule_activation id="a3ea50a3-a21a-4035-9f7a-ba81980a5282" title="Adopt Eloquent ORM Models as Standard Data Modeling Pattern: Models Define Casts" applies_to="app/Models/**/*.php">
These rules are ALWAYS ACTIVE for all domain entities requiring database persistence in the application layer. All models MUST extend Eloquent ORM and follow established data modeling patterns.
</rule_activation>

### Rules

- **R-ELOQUENT-001** MUST: All domain entities requiring database persistence MUST be represented using Eloquent ORM models extending `Illuminate\Database\Eloquent\Model`.
- **R-ELOQUENT-002** MUST: All model classes MUST be placed in the `app/Models` directory with singular, PascalCase naming (e.g., `User`, `PostTemplateSection`, `ContactInformationType`).
- **R-ELOQUENT-003** MUST: Each model class MUST define either `$fillable` or `$guarded` properties to control mass assignment. Prefer `$fillable` for explicit whitelisting.
- **R-ELOQUENT-004** SHOULD: Models SHOULD define casts for attributes that require type conversion (dates, JSON, booleans, etc.) using the `$casts` property.
- **R-ELOQUENT-005** SHOULD: Relationships between entities SHOULD be defined using Eloquent relationship methods (hasMany, belongsTo, belongsToMany, morphMany, etc.) with proper return type hints.
- **R-ELOQUENT-006** SHOULD: Reusable query logic specific to a model SHOULD be implemented using query scopes (scopeActive, scopeRecent, etc.).
- **R-ELOQUENT-007** SHOULD: Model events (creating, created, updating, updated, deleting, deleted) SHOULD be leveraged for cross-cutting concerns like logging or cache invalidation.
- **R-ELOQUENT-008** SHOULD: Eager loading using the `with()` method SHOULD be used to prevent N+1 query problems when accessing relationships.
- **R-ELOQUENT-009** MAY: API resources or transformers MAY be used for serialization rather than exposing raw model attributes.

### Verify

```bash
# Count Eloquent models in app/Models directory
grep -r "extends Model" app/Models/ | wc -l

# Find model files not using Eloquent
find app/Models -type f -name '*.php' -exec grep -L 'use Illuminate\\Database\\Eloquent\\Model' {} \;

# Display model structure summary
php artisan model:show --all 2>&1 | grep -E '(class|table)' | head -20

# Verify fillable/guarded properties exist
grep -r "\$fillable\|\$guarded" app/Models/ | wc -l

# Verify casts are defined
grep -r "\$casts" app/Models/ | wc -l
```

**Accept when:**
- All model files in `app/Models` directory extend `Illuminate\Database\Eloquent\Model`
- Each model class corresponds to a database table and follows Laravel naming conventions (singular, PascalCase)
- Models define appropriate `$fillable` or `$guarded` properties for mass assignment protection
- Models define `$casts` property for attribute type conversion (dates, JSON, booleans, etc.)
- Relationships between entities are defined using Eloquent relationship methods with proper return type hints
- No raw SQL queries exist where Eloquent could reasonably be used instead
- Query scopes are used for reusable model-specific query logic
- Eager loading is implemented to prevent N+1 query problems
